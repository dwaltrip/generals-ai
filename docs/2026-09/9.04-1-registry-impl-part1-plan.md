# Goldens first cut: registry spike (first pass)

*Note: This was manually extracted from the Claude Code session chat and saved as a doc after the fact. The date in the filename is the historical date from when the plan was actually generated.*

## Context

The goldens first-cut build (branch `goldens-1st-cut-build`) has the shared emission code in place (walk core, tail, pack) and two golden test drafts, but the registry, loaders, and hash builders are stubs, so the tests collect zero entries. This session settled the registry design that was left open in 8.12-2 §6 and 8.25-1 §7.1:

- Supervision references are stored per (fixture, key, group), where a key's groups are defined by a declared dependency table: for each key, the config fields its bytes depend on. Points that agree on those fields share one stored array.
- Regen validates the table: within a group, every point must produce identical bytes, or regen refuses to bless.
- Groups are named after the first registered point that emits the key and matches the group's field values (the representative). This keeps existing files in place when a key gains a dependency.
- Registry data is two typed lists (`SupervisionPoint`, `SupervisionKey`) plus an obs point list and a fixture list. Config values are stored as plain dicts and converted at expansion; the config classes have no defaults, so `**d` construction is strict.

This plan is a spike: build the registry as designed, plus the smallest loaders, hash builders, fixture pick, and regen loop needed to run both golden tests end to end against throwaway fixtures, then exercise the three design checks by hand. Regen is prototype-grade in this pass. A short session note follows the spike.

## Step 1: registry

`registry.py` gets four parts.

Records (frozen, kw_only):

```python
class FixtureRecord: replay_id, slot, note; id -> f"{replay_id}-s{slot}"   # exists
class ObsPoint: name, cfg: dict[str, Any]
class SupervisionPoint: name, targets: dict[str, Any], emit_alive_mask: bool, keys: tuple[str, ...]
class SupervisionKey: name, deps: tuple[str, ...], hashed: bool = False
```

Data, plain values only:

- `OBS_POINTS`: `fp16_player_status_on` = `{dense_history_n: 5, obs_dtype: "fp16", player_status_channels: True}`, `fp32_pre_player_status` = same with `"fp32"` and `False` (matches `OBS_CONFIG_DEFAULTS` and `LEGACY_OBS_CFG`).
- `SUPERVISION_POINTS`, in this order: `core`, `alive_only`, `time_bin`, `next_death`. Targets dicts per 8.12-2 with the two `TargetsConfig` fields; edges `[10, 20, 40, 80, 160, 320, 640]` (the `ModelConfig` default, `model_config.py:226`) with a `TODO(sweep)` pointing at 8.12-2 §9. Keys written out in full per point: core keys are `legality_mask, action_target, is_pass, value_target`; `alive_only` adds `alive_mask`; `time_bin` adds `alive_mask, elim_bin_target`; `next_death` adds `alive_mask, next_elim_target, next_elim_dt, next_elim_removal_dt, present_mask` (from `aux_heads/next_death.py:49`).
- `SUPERVISION_KEYS`: `legality_mask` (deps `()`, hashed), the four other config-independent keys with `()`, `elim_bin_target` with `("elim_variant", "elim_bin_edges")`, the four next_death keys with `("elim_variant",)`.
- `FIXTURES`: empty until step 5 fills it with the throwaway picks.
- Constants: `REP_SEP = "@"`, `DATA_ROOT = Path(__file__).resolve().parents[2] / "tests" / "goldens"`, `FIXTURES_DIR`, `REFERENCES_DIR`.

Import-time checks, pure, in one `_validate()` called at module bottom:

- unique names across each list; no name contains `REP_SEP`
- every key in every point's `keys` has a `SupervisionKey`, and every `SupervisionKey` is in at least one keyset
- every `deps` field is a field of `TargetsConfig` or `PartialEmitSpec`
- `TargetsConfig`, `ObsConfig`, `PartialEmitSpec` have no field defaults (`dataclasses.fields`, `MISSING` on both `default` and `default_factory`)
- each point converts: `TargetsConfig(**p.targets)`, `ObsConfig(**p.cfg)` (this is the strict-keys assert)

Expansion:

- `_spec_for(point) -> PartialEmitSpec`: `TargetsConfig(**targets)`, `emit_alive_mask`, `attach_sim_frame=False`.
- `_group_id(key, spec) -> tuple`: values of `key.deps` read off the converted spec (look up on `spec.targets`, then `spec`).
- `_representative(key, group_id) -> str`: first point in list order with `key.name in point.keys` and matching group id.
- `ObsEntry(point, cfg, fixture, ref_path)` as today.
- `SupervisionEntry(point, spec, keys, hashed_keys: frozenset[str], fixture, paths: dict[str, Path])`. `paths[key] = REFERENCES_DIR / "supervision" / fixture.id / f"{rep}{REP_SEP}{key}.npy"`.
- `obs_entries()`, `supervision_entries()`: cross product, list order.

## Step 2: hash builders

`hashes.py`, promoted from `scripts/goldens_probe/layers.py:43-63`:

- `_hash64(buf) -> int` via `hashlib.blake2b(digest_size=8)`.
- `hash_frames(frames: list[WalkFrame]) -> [T] uint64`: stack `obs` to `[T, C, H, W]` (`np.ascontiguousarray`), hash `stack[t].tobytes()`.
- `hash_channels(frames) -> [C] uint64`: hash `stack[:, c]` (each channel's full history, per 7.15-2 §2), contiguous copy per channel.
- `hash_mask_frames(masks: [T, ...]) -> [T] uint64`: same per-t rule over the legality-mask stack.

One module comment recording the algorithm and the canonical-bytes rule (C-order, emitted dtype). Drop the `TODO(sketch)`.

## Step 3: loaders

`loaders.py`:

- `load_fixture(fixture) -> (sim, meta)`: `np.load` of `FIXTURES_DIR / f"{replay_id}.npz"` and `.meta.npz`, dict-of-arrays like `dataset.py:301-304`.
- `perspective_for(game_meta: GameMeta, slot: int) -> PerspectiveMeta`: the unique `k` whose `perspectives[k].slot == slot`; assert exactly one. (Signature changes from the stub, which took the raw meta dict.)
- `load_array(path) -> np.ndarray | None`: `np.load` if the file exists, else None.
- `load_obs_reference(path) -> ObsReference | None`: npz with `frame_hashes`, `channel_hashes`.
- `load_supervision_reference(paths: dict[str, Path]) -> dict[str, np.ndarray] | None`: None if any file is missing (partial counts as unblessed).

## Step 6: prototype regen

`regen.py` with a `main()`; run as `uv run python -m training.goldens.regen` from `packages/training`. Prototype-grade, prints only, no flags. Per fixture:

1. Load fixture, `GameMeta`, perspective.
2. Obs: for each obs entry, `walk`, hash, compare to the existing npz if any, write, print `unchanged | changed (n ticks, first t) | new`.
3. Supervision: compute every point's dict via `compute_supervision`. Assert each equals its keyset (stop with a message otherwise).
4. For each `SupervisionKey`, group the emitting points by `_group_id`. Within a group, assert byte equality across points; on failure print the contradiction (key, agreeing points, differing points, first differing t) and exit 1 without writing. Then take the group's array (hashes for hashed keys), compare to the file at the representative's path if present, write, print one status line per file (`unchanged | changed | new`).
5. After all keys, warn once per key whose groups are pairwise byte-identical (over-declared or unexercised).
6. Orphans: files under the fixture's directory not in the expected set. Print `moved` if the bytes match a file written as `new` this run, else `removed`. Delete them.

Registry helpers `_group_id` and `_representative` are reused, not duplicated. Expected paths come from `supervision_entries()`.

## Step 7: tests and exercise

Update the two tests to the new shapes (`perspective_for(game_meta, slot)`, `load_supervision_reference(entry.paths)`, `compare_supervision(..., entry.hashed_keys)`). Then:

1. Run the pick script, paste the two `FixtureRecord`s, run regen, run `uv run pytest packages/training/tests/goldens -q`. Expect both tests to collect and pass (2 obs points × 2 fixtures, 4 supervision points × 2 fixtures).
2. Case 2 check (contradiction): temporarily change one of the two player-status paths in `precompute_for` (`bc/datapipe/precompute.py:28-32`) so `alive_mask` differs under elim points. Expect the supervision test to fire for `time_bin` and `next_death` only, and regen to refuse with the contradiction report. Revert.
3. Representative naming and case 1 check: temporarily append a point `time_bin_alt` to `SUPERVISION_POINTS`, same as `time_bin` but with a different edge tuple and the same keys. Run regen and expect one `new` file, `time_bin_alt@elim_bin_target.npy`, with every shared key unchanged and nothing relocated. Then simulate a stale table by removing `elim_bin_edges` from `elim_bin_target`'s deps, and expect regen to refuse with a contradiction between `time_bin` and `time_bin_alt`. Revert both.
4. Fire check: perturb `policy_pass_target`'s output in `emit_tail` (for example flip `is_pass`), expect all four supervision points to fire on `is_pass`, expect regen to print `changed` for `core@is_pass.npy` once. Revert.
5. Full suite: `uv run pytest packages/training/tests -q` green.
