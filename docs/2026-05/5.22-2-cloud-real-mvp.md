## Findings worth carrying forward

- **`add_local_python_source` beats `add_local_dir + uv_pip_install("/pkg")` for pure-Python packages.** Modal resolves the modules via the local-env import path and drops files at `/root/` (on PYTHONPATH). No synthetic install paths, no pyproject re-resolution, no hatchling build. Use the pip-install path only if a package needs entry points / console scripts / build hooks (none of ours do).
- **`uv export` needs `--no-emit-workspace`.** Without it, workspace cross-deps appear as `-e ./packages/<name>` in the requirements file. Modal's `uv_pip_install(requirements=...)` runs before any `add_local_*` layer, so the path doesn't exist in the container → image build fails. Documented in [`working-with-modal-cloud-gpu.md`](../working-with-modal-cloud-gpu.md).
- **The dep audit was right about what `training` pulls in:** torch + numpy + matplotlib + utils. The earlier `replay-collector` transitive bloat (from `utils.player_name_lists` → `replay_collector.usernames`) is gone since the `usernames` module moved into `utils/`.
- **`pick_device("auto")` now prefers CUDA → MPS → CPU** and `pick_device("cuda")` raises if CUDA isn't available — silent CPU fallback would have been a footgun on a paid GPU box. `--device auto` from the cloud wrapper does the right thing.

## Next: step 2 — corpus Volume + smoke slice

Goal: same image as step 1, but with a Modal Volume mounted RO. CPU function opens a manifest from the Volume and reads a single `.npz` sample — no training, just confirms path translation works.

Sub-tasks:

1. **Assemble a smoke slice.** `training/data/splits/probe_500.json` (used for the local smoke) is the natural choice. Its referenced `.npz` files live in `replay-parser/data/intermediate/` — extract just those into a flat slice dir (call it `tmp/cloud-smoke-slice/` or similar). The full ~10 GB corpus is overkill for step 2 and slow to upload while iterating on Volume plumbing.
2. **Create the Volume + upload.** `modal volume create generals-corpus` (or similar name); `modal volume put generals-corpus tmp/cloud-smoke-slice/ /intermediate/`. Also upload `probe_500.json` to the Volume (or mount the manifest path separately).
3. **Wire the Volume in `run_bc_modal.py`.** `modal.Volume.from_name("generals-corpus")`, mount at `/data/` in the function. Add a new `smoke_volume()` function (or extend `smoke()`) that opens the manifest, calls `load_manifest`, picks the first sample, loads its `.npz`, and reports tensor shapes.
4. **Re-run.** Confirm path translation works. If yes, step 2 done.

The plain text we'll feed the Modal function: `--manifest /data/probe_500.json --intermediate /data/intermediate/`.

### Open questions for step 2

- **Manifest path translation.** `probe_500.json` has paths inside it that point at the parser output. When we put the file on the Volume, those internal paths need to match the Volume mount layout (`/data/intermediate/...`). Either rewrite the manifest before upload, or have the Modal function rewrite paths on the fly. Cheaper: regenerate the smoke manifest with cloud-relative paths at build time.
- **Read-only vs RW mount.** Step 2 just reads, so RO. Step 3 (outputs Volume) is when we deal with RW.
- **Volume naming.** `generals-corpus` is a placeholder; could also be `generals-intermediate` or split into separate Volumes for corpus vs runs.
