# Working style

- Agile chunk-per-commit. Update the status doc's chunks-table status column (`[ ]` → `[X]`) as items land.
- Status doc decisions log: only **durable** choices, ~3-5 short bullets per entry + a `*Where:*` pointer to the implementing files. Implementation mechanism (open flags, try/finally, idiom specifics) belongs in code, not the ledger.
- Inline TODO comments for in-code follow-ups + deferred work as we move toward the POC corpus run.
- Verify `pytest training/tests/` is green at start and at major commits.
- `uv sync` only from the workspace root — running it from `training/` strips root-level dev deps (pytest, ruff, pyright) from the shared venv.
- **Lean toward proposing simplifications.** Existing code is not automatically worth preserving — surface candidates for removal rather than defaulting to leaving as-is.
