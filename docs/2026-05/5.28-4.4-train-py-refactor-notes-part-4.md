# PR 4 sketch — resume mechanics

**Date:** 2026.05.28
**Design contract:** [`5.28-2-train-refactor-and-resume-design.md`](./5.28-2-train-refactor-and-resume-design.md) (§Run-dir lifecycle on resume, §CLI surface, §Failure modes, §Sub-PR breakdown #4)

End-to-end resume for **combined-format** checkpoints. (Legacy-checkpoint resume + `--legacy-lr-warmup-batches` is PR 5; the 2026-05-27 operational resume is PR 6.) This is the bundle that cashes in the PR 1–3 cleanup.

## The keystone: `run_loop` → `train_loop(state, …, artifacts)`

Today `run_loop` builds the state, measures FLOPs, builds artifacts, *then* loops. To let fresh and resume share the loop, the **setup moves out to the callers** and `train_loop` becomes just the epoch loop:

```python
def train_loop(state, config, loader, dataset, val_samples, device, artifacts) -> None:
    amp_dtype = ...resolve from config/device...      # for autocast threading
    run_start = time.perf_counter()
    with artifacts, gpu_util_sidecar(artifacts.gpu_util_path, device):
        for epoch in range(state.epoch + 1, config.epochs + 1):   # <-- the resume hinge
            ...train_one_epoch / run_val / mfu / log_epoch / print_epoch_summary...
            state.epoch = epoch
            state.save(artifacts.ckpt_dir)
```

`range(state.epoch + 1, config.epochs + 1)` is the whole trick: fresh (`epoch=0`) → 1..N; resume (`epoch=5`) → 6..N. Monotonic numbering falls out for free.

FLOPs measurement + the param/precision/FLOPs prints move into a small `_build_run_setup`-style step the callers run before `train_loop` (they produce the `flops_per_sample`/`peak_tflops` that go into `RunArtifacts`).

## Two entry paths, one loop

- **Fresh** — `bc_run(config)` (today's path): `initialize_run_dir` (caller), then load manifest, `build_dataloader`, `TrainingState.fresh`, build `RunArtifacts(suffix="")`, tee `run.log`, `train_loop`.
- **Resume** — new `bc_resume(config, force_config_mismatch)` in `train.py` (env-agnostic, so it isn't duplicated across the two wrappers):
  1. `info = prepare_resume(config.run_dir)` — pure inspection.
  2. Drift gate vs `info.parent_args_path` (abort unless `--force-config-mismatch`; lr/weight_decay abort regardless).
  3. Write `args_resume_NN.json` (+ `args_cloud_resume_NN.json` on Modal).
  4. `TrainingState.from_checkpoint(info.latest_checkpoint, config, device)`.
  5. `RunArtifacts(suffix=info.next_suffix, …)`, tee `run_resume_NN.log`, `train_loop`.

Both paths build state + artifacts and call the same `train_loop`. `bc_run`/`bc_resume` share helpers for the manifest/dataloader/tee/setup portion.

## `prepare_resume(run_dir) → ResumeInfo` (`run_dir.py`)

Pure inspection — no writes:

```python
@dataclass
class ResumeInfo:
    next_suffix: str        # "_resume_NN", zero-padded, from max existing +1
    latest_checkpoint: Path # max(epoch_NNN.pt) by filename
    parent_epoch: int       # NNN parsed from that filename
    parent_args_path: Path  # args_resume_{NN-1}.json, or args.json for the first resume
```

- `next_suffix`: glob `*_resume_[0-9][0-9].*`, take max NN, `+1`, `f"_resume_{n:02d}"`.
- `latest_checkpoint` / `parent_epoch`: `max` over `checkpoints/epoch_*.pt` by filename; parse NNN.
- `is_legacy_checkpoint` is **deferred to PR 5** — PR 4 targets combined-format checkpoints, where `from_checkpoint` reads `epoch` straight from the dict. (Legacy detection + the warmup abort arrive with the warmup flag.)

## CLI surface (shared parser — `train_cli.py`)

`--resume` and `--force-config-mismatch` go on `build_arg_parser`, so **both** wrappers inherit them. Run-id → run-dir needs no per-environment branch: `out_dir` is already environment-set (`/runs` on Modal, `training/data/runs` locally), so:

```python
# config_from_args
run_dir = args.out_dir / (args.resume or make_run_id())
```

`config_from_args` returns the config; the wrapper reads `args.resume`/`args.force_config_mismatch` to dispatch `bc_resume` vs `initialize_run_dir`+`bc_run`. `TrainConfig` is frozen, so the run-dir is set at construction (no post-hoc mutation).

## Drift gate (`run_dir.py` helper)

Compare resume-side `TrainConfig` to the parent `args.json` dict. Three buckets (per design §`--force-config-mismatch`):

- **Excluded** (always free): `epochs`, `run_dir`, `manifest`, `intermediate`.
- **Checkpoint-owned, never overridable**: `lr`, `weight_decay` — abort if changed *even with* `--force-config-mismatch` (optim.load_state_dict overwrites them anyway).
- **Trajectory-critical** (everything else): abort listing deltas; `--force-config-mismatch` bypasses.

Compares raw stored values (the known footgun: `--pin-memory true` vs stored `None` trips the gate; documented, accepted).

## Suffix + exclusive-create rollout

The suffix string is the source of truth; `RunArtifacts` carries it and derives paths:

| artifact | path |
|---|---|
| run log | `run{suffix}.log` (tee) |
| batches/epochs | `RunLogger(run_dir, suffix)` (already supported) |
| gpu util | `gpu_util{suffix}.jsonl` |
| args | `args{suffix}.json` (suffix `""` → `args.json`) |

- **`RunArtifacts`** gains `suffix: str` + `resume_segment: int` + exposes `log_path` / `gpu_util_path`. (The PR-1-deferred fields land here.)
- **`tee_stdio(log_path, mode="x")`** — new `mode` param, default exclusive-create (`"x"`). Verify `run_adhoc.py` (eval-tools) still works; pass `"w"` there if it re-runs into an existing dir.
- **`gpu_util_sidecar(path, device)`** — takes the full jsonl path instead of `run_dir` (signature change per design). Sampling-logic fix stays deferred.
- All new-file opens use `"x"` so a bad suffix → `FileExistsError` at startup, not silent truncation. Handles open once at startup → can't trip mid-training.

## `args_resume_NN.json`

Full `TrainConfig` as JSON + a top `_resume_meta` block:

```json
{"_resume_meta": {"resumed_from_epoch": 5, "parent_args": "args.json",
                  "resumed_at": "<ISO8601 from caller>"}, "...": "config fields"}
```

`parent_args` = the immediate predecessor (chains for resume-of-resume; terminates at `args.json`, which has no `_resume_meta`). `resumed_at` timestamp is passed in by the caller (scripts can't call `datetime.now` inside the workflow-pure layer, but `run_dir.py` is fine — it's not workflow code; still, keep the timestamp at the wrapper boundary for testability).

## Modal-side plumbing (`run_bc_modal.py`)

`train_remote` currently does `initialize_run_dir → _write_args_cloud → bc_run`. It needs to dispatch: on resume, skip `initialize_run_dir`, write `args_cloud_resume_NN.json`, call `bc_resume`. The resume flag + `force_config_mismatch` are passed into `train_remote` (Modal serializes them alongside `config`).

## Failure modes (all abort before training)

`--resume` nonexistent dir; empty `checkpoints/`; latest epoch `>= config.epochs` (already finished); drift without `--force-config-mismatch`; lr/weight_decay change. Clear messages, fail within seconds Modal-side (V1; local pre-pull is deferred V2).

## Tests

- `prepare_resume` suffix discovery: N existing resume artifacts → `_resume_{N+1:02d}`; parent_epoch/parent_args correct.
- Drift gate: non-excluded field change aborts; `--force-config-mismatch` bypasses; lr change aborts regardless.
- Integration smoke: `--epochs 2` to completion, then resume `--epochs 4` → `epochs.jsonl` rows 1–2, `epochs_resume_01.jsonl` rows 3–4, monotonic, chained `_resume_meta`.

## Open decisions to confirm before implementing

Each has a recommended default + the reasoning behind it, so the next session can react rather than re-derive.

### 1. `bc_resume()` in `train.py` vs. duplicated in each wrapper — **recommend: `train.py`**
The design's prose puts the resume sequence "in the wrapper," but that duplicates 5 steps across `run_bc_local` *and* `run_bc_modal`. `bc_run` and `bc_resume` share almost everything — manifest load, `build_dataloader`, suffixed tee, `train_loop`; the only env-specific bit is run-id→run_dir, already handled by `out_dir / resume_id` in `config_from_args`. So `bc_resume(config, force_config_mismatch)` lives in `train.py`; wrappers just dispatch.
- **Modal wrinkle:** the fresh path already splits the cloud-only `args_cloud.json` write out of `bc_run` — `train_remote` does `initialize_run_dir` → `_write_args_cloud` → `bc_run` as three steps. Mirror that for resume: the Modal wrapper writes `args_cloud_resume_NN.json` around `bc_resume`, so the one env-specific write stays in the wrapper and `bc_resume` owns the bc-side `args_resume_NN.json` + the rest.

### 2. `--resume` / `--force-config-mismatch` on the shared parser — **recommend: shared**
`out_dir` is already environment-set via `set_defaults` (local `training/data/runs`, Modal `/runs`), so no per-env run-id resolution is needed: `config_from_args` does `run_dir = out_dir / (args.resume or make_run_id())`.
- **Dispatch in `main()`:** `if args.resume: bc_resume(config, args.force_config_mismatch)` else `initialize_run_dir(config); bc_run(config)`. Crucially `initialize_run_dir` must **not** run on resume — its `mkdir(exist_ok=False)` would (correctly) refuse the existing dir.
- `--force-config-mismatch` is only meaningful with `--resume`; consider warning/erroring if passed alone (minor).

### 3. `tee_stdio(log_path, mode="x")` default exclusive-create — **RESOLVED: safe, just do it**
Checked the only other caller, `run_adhoc.py`: it writes into a fresh per-run timestamped dir (`data/eval-runs/<ts>`, `mkdir(parents=True, exist_ok=True)`), so `run.log` never pre-exists. Default `"x"` is safe there — no explicit `"w"` needed — and even adds a same-wall-clock-second collision guard consistent with how bc's run-id already collides. So default `"x"` everywhere, no special-casing.

### 4. Defer `is_legacy_checkpoint` to PR 5 — **recommend: defer (PR 4 = combined-format only)**
Matches the design's "resume works for new-format checkpoints" framing for PR 4.
- **Important cross-PR note for PR 5:** for *combined* resume, `from_checkpoint` reads `epoch` straight from the dict (authoritative). A *legacy* bare-state_dict has no `epoch` field → `from_checkpoint` falls back to `0`, which is **wrong** for resume. So PR 5 must (a) add `is_legacy_checkpoint` to `ResumeInfo`, (b) add the legacy-without-`--legacy-lr-warmup-batches` abort, **and** (c) set `state.epoch` from `prepare_resume`'s `parent_epoch` (parsed from the filename `epoch_005.pt` → 5) when the checkpoint is legacy. Don't let PR 5 be surprised that legacy resume needs the filename epoch, not the dict epoch — that's why `prepare_resume` computes `parent_epoch` even though PR 4's combined path doesn't strictly need it.

### 5. Split PR 4 into 4a + 4b — **recommend: split**
- **4a (pure refactor, zero behavior change):** reshape `run_loop` → `train_loop(state, config, loader, dataset, val_samples, device, artifacts)`, moving FLOPs measurement + the param/precision/FLOPs prints + state/artifacts construction out to the callers; loop becomes `range(state.epoch + 1, config.epochs + 1)` (a no-op for fresh: `0 + 1 = 1`). `RunArtifacts` gains `suffix`/`resume_segment`/`log_path` with fresh defaults (`""` / `0` / `run.log`). Keep `gpu_util_sidecar`'s **current** signature in 4a (the path-arg change is resume-motivated → 4b; with `suffix=""` the path is unchanged anyway). Verify by the same byte-identical fresh-run smoke (loss fingerprint) + full suite.
  - **Watch:** the moved prints must keep the same content **and order** or the fresh-run-output check will flag a false diff.
- **4b (the new capability):** `prepare_resume` + `ResumeInfo`, the CLI flags + dispatch, drift gate, `bc_resume`, `args_resume_NN.json` + `_resume_meta`, the exclusive-create (`"x"`) rollout, `gpu_util_sidecar` path-arg signature change, `tee_stdio` mode param.
- Rationale: 4a lands the risky keystone reshape as a provable no-op; 4b is then purely additive.
