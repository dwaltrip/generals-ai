# PR 4 plan — resume mechanics (4a · C1 · 4b)

**Date:** 2026.05.28
**Design contract:** [`5.28-2-train-refactor-and-resume-design.md`](./5.28-2-train-refactor-and-resume-design.md) (§Run-dir lifecycle on resume, §CLI surface, §Failure modes, §Sub-PR breakdown #4).

This plan refines the contract on two points, settled in discussion:

- **Resume orchestration lives in a new `bc/resume.py`** — not in the wrappers (the contract's prose, which duplicates the sequence across local + Modal) and not in `train.py`. `train.py` stays resume-ignorant; the wrappers just dispatch. See [Module split](#module-split).
- **A config defaults-dedup step (C1) lands between the reshape and the resume capability.** It makes `TrainConfig` the single source of default values and yields "what did the operator explicitly pass" for free — which lets resume build its config by overlaying the parent `args.json`, so the drift gate fires only on intentional changes. See [C1](#c1--defaults-on-trainconfig-thin-parser) and [Resume config overlay](#resume-config--parent-argsjson-overlaid-with-explicit-cli).

PR 4 is the bundle that cashes in the PR 1–3 cleanup. Legacy-checkpoint resume + `--legacy-lr-warmup-batches` remains PR 5; the 2026-05-27 operational resume is PR 6.

## Sequence

| Step | What | Behavior change |
|---|---|---|
| **4a** | `run_loop` → `train_loop(state, …, artifacts)` reshape; setup moves to the caller | none — pure refactor, byte-identical fresh run |
| **C1** | parser defaults → `TrainConfig` field defaults; thin parser via `argparse.SUPPRESS`; overlay in `config_from_args` | none for existing CLI calls |
| **4b** | the resume capability: `resume.py`, `prepare_resume`, flags, suffix discipline, drift gate | additive (new code paths) |
| C2 | `--config <file>` JSON input | deferred — TODO in `train_cli.py` |

Keep C1 a separate small PR rather than folding it into 4b: 4b stays a focused "additive resume capability"; C1 stays a clean reviewable dedup.

## 4a — the keystone reshape (pure no-op)

Today `run_loop` builds the state, measures FLOPs, builds artifacts, *then* loops. To let fresh and resume share the loop, the setup moves out to the caller and `train_loop` becomes just the epoch loop:

```python
def train_loop(state, config, loader, dataset, val_samples, device, artifacts) -> None:
    run_start = time.perf_counter()
    with artifacts, gpu_util_sidecar(artifacts.run_dir, device):   # current sidecar sig in 4a
        for epoch in range(state.epoch + 1, config.epochs + 1):    # <-- the resume hinge
            ... train_one_epoch / run_val / mfu / log_epoch / print_epoch_summary ...
            state.epoch = epoch
            state.save(artifacts.ckpt_dir)
```

`range(state.epoch + 1, config.epochs + 1)` is the whole trick: fresh (`epoch=0`) → `1..N` (`0 + 1 = 1`, a no-op); resume (`epoch=5`) → `6..N`. Monotonic numbering falls out for free.

`bc_run` absorbs what `run_loop` did before the loop: build `TrainingState.fresh`, measure FLOPs, print the param/precision/FLOPs block, build `RunArtifacts`, then call `train_loop`. `gpu_util_sidecar` keeps its **current** `(run_dir, device)` signature in 4a — the path-arg change is resume-motivated (4b), and with `suffix=""` the path is unchanged anyway.

- **Watch:** the moved FLOPs/param/precision prints must keep the same content **and order**, or the byte-identical fresh-run check flags a false diff.
- **Verify:** byte-identical fresh-run loss fingerprint (`run_bc_local.py --skip-val`, short) + full `training/tests` green.

## C1 — defaults on `TrainConfig`, thin parser

`TrainConfig` already declares every hyperparameter default as a field default (`lr: float = 3e-4`, `batch_size: int = 64`, …). `build_arg_parser` then re-declares the same values — **two homes for the defaults that happen to agree**, and the parser is the wrong owner. This step deletes the parser's copies.

- **Parser:** training-knob flags switch to `default=argparse.SUPPRESS`, so a flag that isn't passed never lands on the namespace. Env-wiring flags (`--manifest`/`--intermediate`/`--out-dir`/`--device`) keep `set_defaults` as today.
- **`config_from_args`:** overlay only what was passed onto the dataclass defaults:
  ```python
  overrides = {FIELD[k]: adapt(k, v) for k, v in vars(args).items() if k in TRAINING_FLAGS}
  return TrainConfig(manifest=..., intermediate=..., run_dir=..., **overrides)
  ```
  `adapt` keeps the small `--pin-memory` string→`bool|None` map and the `--value-head`→`value_head_variant` rename, applied only to present keys.
- **Payoff:** `vars(args)` is now exactly the explicitly-passed set — which 4b's resume overlay needs (below). `SUPPRESS` also disambiguates "not passed" from a meaningful `None` (`max_batches`, `pin_memory=auto`), which a `None` sentinel can't.
- **Tradeoff:** `--help` no longer auto-shows defaults. Mitigate with a `--show-config` that prints the resolved `TrainConfig`, or point at `args.json`.

A named `DEFAULT_CONFIG` instance is intentionally *not* added — the dataclass field defaults are the single source, with no placeholder path values and no second copy to drift. Revisit only if we want named presets (smoke vs full), which is a distinct construct.

## 4b — the resume capability

### Module split

The contract's prose puts the resume sequence "in the wrapper," which duplicates ~5 steps across `run_bc_local` and `run_bc_modal`. Putting it in `train.py` removes the duplication but teaches `train.py` about resumes. The split that does neither:

- **`train.py`** exposes one resume-agnostic core, parameterized only by a `suffix` string and a `make_state` factory — never by "am I resuming":
  ```python
  def bc_run(config):                       # fresh entry, caller-facing
      run_training(config, suffix="", make_state=lambda dev: TrainingState.fresh(config, dev))

  def run_training(config, suffix, make_state):
      # disable_mps_fallback, validate, device, seed, ckpt_dir(exist_ok=True → resume reuses it)
      with tee_stdio(config.run_dir / f"run{suffix}.log"):
          # manifest load + build_dataloader      (printed inside the tee)
          state = make_state(device)              # fresh OR from_checkpoint — train.py can't tell
          # FLOPs measure + param/precision/FLOPs prints
          artifacts = RunArtifacts(suffix=suffix, ...)
          with artifacts, gpu_util_sidecar(artifacts.gpu_util_path, device):
              train_loop(state, config, loader, dataset, val_samples, device, artifacts)
  ```
  `run_training` is the 4b extraction of `bc_run`'s 4a body, generalized by `suffix`/`make_state`. The factory — rather than a pre-built `state` — keeps the `building model`/`params` prints inside the tee.
- **`bc/resume.py`** owns all resume bookkeeping and calls the shared core:
  ```python
  def bc_resume(config, force_config_mismatch):
      info = prepare_resume(config.run_dir)                # run_dir.py, pure inspection
      check_drift(config, info.parent_args_path, force_config_mismatch)
      write_args_resume(config, info)                      # run_dir.py helper
      run_training(config, suffix=info.next_suffix,
                   make_state=lambda dev: TrainingState.from_checkpoint(info.latest_checkpoint, config, dev))
  ```
- **`run_dir.py`** gains the run-dir-shaped helpers — `prepare_resume`/`ResumeInfo`, the drift gate, the `args_resume` write — the same neighborhood as `initialize_run_dir`/`RunArtifacts`.
- **Wrappers** just dispatch: `if args.resume: bc_resume(config, args.force_config_mismatch)` else `initialize_run_dir(config); bc_run(config)`. `train.py` imports nothing resume-specific.

### `prepare_resume(run_dir) → ResumeInfo` (`run_dir.py`)

Pure inspection — no writes:
```python
@dataclass
class ResumeInfo:
    next_suffix: str        # "_resume_NN", zero-padded, from max existing +1
    latest_checkpoint: Path # max(epoch_NNN.pt) by filename
    parent_epoch: int       # NNN parsed from that filename
    parent_args_path: Path  # args_resume_{NN-1}.json, or args.json for the first resume
```
- `next_suffix`: glob `*_resume_[0-9][0-9].*`, take max NN, `+1`, `f"_resume_{n:02d}"`.
- `latest_checkpoint` / `parent_epoch`: `max` over `checkpoints/epoch_*.pt` by filename; parse NNN.
- `is_legacy_checkpoint` is **deferred to PR 5** — PR 4 targets combined-format checkpoints, where `from_checkpoint` reads `epoch` straight from the dict. Cross-PR note for PR 5: a legacy bare-state_dict has no `epoch` field, so `from_checkpoint` falls back to `0` — wrong for resume. PR 5 must set `state.epoch` from `parent_epoch`, which is why `prepare_resume` computes it even though the combined path doesn't strictly need it.

### Resume config = parent `args.json` overlaid with explicit CLI

Built on C1's explicitly-passed set: resume config = parent `args.json` (base) → overlay the explicitly-passed CLI flags → overlay env paths/run_dir. So `--resume <id> --epochs 8` reproduces the parent's `batch_size`/`lr`/etc. automatically — no re-typing every non-default knob to dodge the gate.

Consequence for the drift gate: it fires only on fields the operator **explicitly changed** — the only time it should.

### Drift gate (`run_dir.py` helper)

Three buckets (design §`--force-config-mismatch`):
- **Excluded** (always free): `epochs`, `run_dir`, `manifest`, `intermediate`.
- **Checkpoint-owned, never overridable:** `lr`, `weight_decay` — abort if changed *even with* `--force-config-mismatch` (`optim.load_state_dict` overwrites them anyway).
- **Trajectory-critical** (everything else): abort listing deltas; `--force-config-mismatch` bypasses.

### CLI surface (shared parser — `train_cli.py`)

`--resume` and `--force-config-mismatch` go on `build_arg_parser`, so both wrappers inherit them. `out_dir` is already environment-set, so run-id → run-dir needs no per-env branch:
```python
run_dir = args.out_dir / (args.resume or make_run_id())
```
- **Validator:** `--force-config-mismatch` is only meaningful with `--resume`; a shared post-parse check in `train_cli.py` errors if it's passed alone (argparse can't natively express "A requires B").
- `TrainConfig` is frozen, so `run_dir` is set at construction — no post-hoc mutation.

### Suffix + exclusive-create rollout

The suffix string is the source of truth; `RunArtifacts` carries it and derives paths:

| artifact | path |
|---|---|
| run log | `run{suffix}.log` (tee) |
| batches/epochs | `RunLogger(run_dir, suffix)` (already supported) |
| gpu util | `gpu_util{suffix}.jsonl` |
| args | `args{suffix}.json` (suffix `""` → `args.json`) |

- **`RunArtifacts`** gains `suffix: str` + `resume_segment: int` and exposes `log_path` / `gpu_util_path` — the PR-1-deferred fields land here.
- **`tee_stdio(log_path, mode="x")`** — new `mode` param, default exclusive-create. The only other caller (`run_adhoc.py`) writes into a fresh per-run timestamped dir, so `run.log` never pre-exists — default `"x"` is safe there, no special-casing.
- **`gpu_util_sidecar(path, device)`** — takes the full jsonl path instead of `run_dir`. Sampling-logic fix stays deferred.
- All new-file opens use `"x"`, so a bad suffix surfaces as `FileExistsError` at startup, not silent truncation. Handles open once at startup, so this can't trip mid-training.

### `args_resume_NN.json`

Full `TrainConfig` as JSON + a top `_resume_meta` block:
```json
{"_resume_meta": {"resumed_from_epoch": 5, "parent_args": "args.json",
                  "resumed_at": "<ISO8601 from caller>"}, "...": "config fields"}
```
`parent_args` = the immediate predecessor (chains for resume-of-resume; terminates at `args.json`, which has no `_resume_meta`). `resumed_at` is passed in by the caller — keep the timestamp at the wrapper boundary for testability.

### Modal-side plumbing (`run_bc_modal.py`)

`train_remote` currently does `initialize_run_dir → _write_args_cloud → bc_run`. On resume it dispatches: skip `initialize_run_dir`, write `args_cloud_resume_NN.json`, call `bc_resume`. The one env-specific write (`args_cloud_resume`) stays in the wrapper, mirroring how the fresh path keeps `_write_args_cloud` out of `bc_run`; `bc_resume` owns the bc-side `args_resume_NN.json`. The resume flag + `force_config_mismatch` serialize alongside `config`.

### Failure modes (all abort before training)

`--resume` nonexistent dir; empty `checkpoints/`; latest epoch `>= config.epochs` (already finished); drift without `--force-config-mismatch`; lr/weight_decay change; `--force-config-mismatch` without `--resume`. Clear messages, fail within seconds Modal-side (V1; local pre-pull deferred to V2).
