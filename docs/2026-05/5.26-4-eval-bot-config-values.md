## 1. Threat Detection

### `THREAT_WINDOW_LEN = 8`

**Consumer:** `world_model.py:268` — `deque(maxlen=self.cfg.THREAT_WINDOW_LEN)`

The deque holds one `ThreatEntry` per tick per contacted player (when their largest stack is visible). The closing check at `world_model.py:294-298` computes `mean(deltas)` over consecutive pairs, so N entries → N-1 deltas. Needs at least 2 entries to evaluate at all.

| Direction           | Effect                                                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 15)    | More deltas in the average → smoother signal, resistant to noise, but slower to detect new threats. A quick 3-tick lunge gets diluted by 12 ticks of neutral history.                 |
| **Down** (e.g. 3)   | 2 deltas. Single-tick movement dominates the average. Twitchy, fast reaction, many false positives.                                                                                   |
| **Extreme low**     | 2 — one delta per evaluation. Any single close step gives mean=-1, always fires.                                                                                                      |
| **Extreme high**    | 50+ — in practice windows break often (identity check at `world_model.py:262`), so rarely fills. Main effect: dilutes the average since evaluation uses whatever entries are present. |
| **Effective range** | 3–15                                                                                                                                                                                  |

---

### `CLOSING_THRESHOLD = -0.3`

**Consumer:** `world_model.py:298` — `closing = (sum(deltas) / len(deltas)) < self.cfg.CLOSING_THRESHOLD`

Each delta is typically -1 (closer), 0 (holding), or +1 (retreating). The mean must be **more negative** than this value to trigger.

| Direction                           | Effect                                                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (less negative, e.g. -0.1)   | Triggers on slow drift. Even 1 closing step in 10 ticks gives mean ≈ -0.1, fires. Many false positives from random movement near the general. |
| **Down** (more negative, e.g. -0.8) | Only triggers on determined charges (enemy closing almost every tick). Misses careful or meandering approaches.                               |
| **Extreme low**                     | -1.0 — enemy must close every single tick (max possible mean when all deltas are -1). Practically unreachable given pauses.                   |
| **Extreme high**                    | -0.01 — any net closing triggers.                                                                                                             |
| **Effective range**                 | -0.1 to -0.8                                                                                                                                  |

---

### `EATING_RADIUS = 3`

**Consumer:** `world_model.py:309-316` — Manhattan radius for tile-flip search around the threat stack.

Cell counts in a Manhattan diamond: radius 1→5, 2→13, 3→25, 5→61, 10→221. On a 30×30 map, radius 15 encompasses most of the board.

| Direction           | Effect                                                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| **Up** (e.g. 6)     | Catches wider incursions but false positives from unrelated border scraps far from the threat. |
| **Down** (e.g. 1)   | Only detects eating right at the stack's position. Misses broader-front attacks.               |
| **Effective range** | 1–8                                                                                            |

---

### `EATING_MIN = 3`

**Consumer:** `world_model.py:321` — `eating = eaten >= self.cfg.EATING_MIN`

Minimum tiles flipped to enemy within the radius to qualify. Max possible eaten ≈ area of Manhattan diamond within the map.

| Direction           | Effect                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 6)     | Requires a substantial incursion. Ignores small border scraps. May miss real but narrow attacks.   |
| **Down** (e.g. 1)   | Single tile flip triggers eating. Very noisy — any border tile changing hands fires the condition. |
| **Effective range** | 1–8 (tied to EATING_RADIUS — can't exceed the diamond's cell count)                                |

## 2. Defend Response

### `INTERCEPT_LOOKAHEAD = 3`

**Consumers:**
- `defend.py:43` — `idx = min(cfg.INTERCEPT_LOOKAHEAD, len(path) - 1)` — selects intercept tile along invader→general path
- `defend.py:47` — `max_moves = tw.dist_to_general - cfg.INTERCEPT_LOOKAHEAD` — time budget for defend gather

The path runs from invader (index 0) to our general (last index). `idx=3` means the intercept point is 3 cells ahead of the invader on their path to our general. If `max_moves <= 0`, defend returns None (general handles it alone).

| Direction           | Effect                                                                                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 6)     | Intercept placed further along invader's path (closer to our general). Tighter time budget (`dist - 6`). If invader is within 6 cells, defend disables entirely. More aggressive "let them come to us" posture, and the general self-defends against close threats. |
| **Down** (e.g. 1)   | Intercept near the invader's current position. Generous time budget (`dist - 1`). Tries to meet them far from the general. Risk: invader moves past the intercept point before gather completes.                                                                    |
| **Extreme low**     | 0 — gather to invader's current position. max_moves = full distance. The invader is moving, so we're chasing rather than intercepting.                                                                                                                              |
| **Extreme high**    | 15 — for any invader further than 15 cells, we intercept near the general. For closer invaders, defend returns None.                                                                                                                                                |
| **Effective range** | 1–8                                                                                                                                                                                                                                                                 |

## 3. Economy / Reserve

### `RESERVE_FRACTION = 0.25`

**Consumers:**
- `gather.py:24` — `return int(cfg.RESERVE_FRACTION * total_army)` — called by `gather_path` and `try_attack`
- Affects general's effective army in `_select_source` (`gather.py:86-88`): if `ceil(gen_army/2) >= reserve`, general uses split move; otherwise general is unavailable
- Affects attack commit budget in `attack.py:174-175`: `mobile = total - reserve; commit = ATTACK_COMMIT_FRACTION * mobile`

| Direction           | Effect                                                                                                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 0.5)   | Half of total army locked on general. Less mobile army for attacks/explores. General harder to deplete, safer against surprise kills. But attacks are weaker and happen less (commit budget shrinks). |
| **Down** (e.g. 0.1) | Almost all army mobile. Aggressive posture, big attacks possible. General vulnerable — a surprise killshot or defend bypass could end the game.                                                       |
| **Extreme low**     | 0.0 — no reserve. General sends full army every gather.                                                                                                                                               |
| **Extreme high**    | 1.0 — all army reserved. General never participates. Only distributed tile army available for gathers.                                                                                                |
| **Effective range** | 0.05–0.5                                                                                                                                                                                              |

---

### `ATTACK_COMMIT_FRACTION = 0.4`

**Consumer:** `attack.py:175` — `commit = int(cfg.ATTACK_COMMIT_FRACTION * mobile)`, then passed as `min_army` to `gather_path` at `attack.py:179`

This is a **minimum viable attack size**, not the actual amount sent. The gather must produce at least `commit` army to proceed; it might assemble more.

`mobile = total_army - reserve_amount`. With RESERVE_FRACTION=0.25, mobile = 75% of total. At 0.4, the attack must assemble at least 30% of total army.

| Direction           | Effect                                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 0.8)   | High floor. Attack only fires when the bot can assemble 60% of total army (0.8 × 0.75). Infrequent but heavy attacks. May never fire early game when army is scattered. |
| **Down** (e.g. 0.2) | Low floor. Small raids qualify. Frequent but individually weak pushes — more probing, less decisive.                                                                    |
| **Extreme low**     | 0.0 — min_army=0. Any gather path qualifies regardless of army. Sends trivially small forces.                                                                           |
| **Extreme high**    | 1.0 — must assemble entire mobile army. Only fires when everything is reachable from a single gather. Rarely possible.                                                  |
| **Effective range** | 0.15–0.8                                                                                                                                                                |

---

### `EXPAND_EXPLORE_THRESHOLD = 0.4`

**Consumer:** `expand.py:195` — `if expandable_count > 0 and expandable_count / frontier_count >= cfg.EXPAND_EXPLORE_THRESHOLD`

Expandable = owned tiles (army ≥ 2) adjacent to 0-garrison neutrals (free moves). Frontier = owned tiles adjacent to any neutral. When ratio is at or above threshold → expand mode; below → explore mode.

| Direction           | Effect                                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 0.7)   | Explore mode most of the time — needs 70% of frontier to be free-expand eligible before switching to expand. More gather pushes into fog.   |
| **Down** (e.g. 0.1) | Expand mode dominates — as long as 10% of frontier has cheap moves, expand fills those. Explore only when almost no free expansions remain. |
| **Extreme low**     | 0.0 — always expand if any expandable tiles exist.                                                                                          |
| **Extreme high**    | 1.0 — only expand when every frontier tile is expandable (never happens in practice).                                                       |
| **Effective range** | 0.1–0.7                                                                                                                                     |

## 4. gather_path Internals

### `SOURCE_DIST_WEIGHT = 1.0`

**Consumer:** `gather.py:96` — `score = eff - cfg.SOURCE_DIST_WEIGHT * d`

Selects the gather source tile. `eff` = effective army (1–200+ range), `d` = BFS distance to target (1–30 range on a 30×30 map).

| Direction           | Effect                                                                                                                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 5.0)   | Each cell of distance costs 5 army units in the scoring. Strongly prefers nearby tiles. A tile with 20 army at distance 10 scores 20 - 50 = -30 (rejected). Only very close or very fat tiles win. |
| **Down** (e.g. 0.1) | Distance barely matters. Always picks the fattest tile. General almost always wins (highest army) regardless of how far it is from the target.                                                     |
| **Extreme low**     | 0.0 — pure army selection.                                                                                                                                                                         |
| **Extreme high**    | 10+ — only immediately adjacent tiles are viable.                                                                                                                                                  |
| **Effective range** | 0.1–5.0                                                                                                                                                                                            |

### `SIDE_GATHER_FRACTION = 0.5`

**Consumer:** `gather.py:200` — `max_side = min(remaining, int(cfg.SIDE_GATHER_FRACTION * len(path)))`

Caps side-gather count as a fraction of path length. Each side-gather is one move (tributary tile pushes onto path). Also capped by `remaining` (moves left after sweep cost).

| Direction           | Effect                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 1.5)   | Up to 1.5× path length in side-gathers. Fatter stack arrives but many ticks consumed pre-sweep. In practice, limited by `remaining` and available candidates. |
| **Down** (e.g. 0.1) | Almost no side-gathers. Leaner, faster sweeps but arrive with less army.                                                                                      |
| **Extreme low**     | 0.0 — no side-gathers ever. Only path-tile army contributes.                                                                                                  |
| **Extreme high**    | 3.0+ — limited by actual candidate count and remaining budget, not the fraction.                                                                              |
| **Effective range** | 0.1–1.5                                                                                                                                                       |

## 5. Kill-shot

### `KILLSHOT_MARGIN_BASE = 10`

**Consumer:** `killshot.py:41-42` — `margin = cfg.KILLSHOT_MARGIN_BASE + math.ceil(cfg.KILLSHOT_MARGIN_PER_STEP * travel_time)`, then `killshot.py:48` — `candidate.arriving_army >= gen_army + margin`

Flat buffer on top of the enemy general's army. Absorbs estimation error independent of distance — enemy army on nearby path tiles, small reinforcements.

| Direction           | Effect                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 8)     | Needs 8+ extra army beyond general's garrison. Conservative — only commits when overwhelming. Fewer killshot attempts. |
| **Down** (e.g. 1)   | Razor-thin margin. Commits to killshots with barely enough army. Fails often if any enemy army exists on the path.     |
| **Extreme low**     | 0 — no flat buffer. `arriving >= gen_army` is sufficient.                                                              |
| **Extreme high**    | 30 — needs massive surplus. Only attempts against undefended generals with huge bot army.                              |
| **Effective range** | 0–10                                                                                                                   |

---

### `KILLSHOT_MARGIN_PER_STEP = 2`

**Consumer:** `killshot.py:42` — `math.ceil(cfg.KILLSHOT_MARGIN_PER_STEP * travel_time)`

Per-step margin accounting for: (1) enemy army on path tiles consuming our arriving force, (2) defender reinforcing their general during travel. `travel_time = len(candidate.moves)` includes side-gathers + sweep.

At 0.5/step, a 20-step killshot needs ceil(10) = 10 extra army. A 5-step killshot needs ceil(2.5) = 3 extra.

| Direction           | Effect                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 1.5)   | Each step costs 1.5 army margin. A 15-step killshot needs ceil(22.5)=23 extra. Only very close or very weak generals are feasible.    |
| **Down** (e.g. 0.1) | Distance barely affects margin. Willing to attempt long-range killshots optimistically.                                               |
| **Extreme low**     | 0.0 — distance has no effect on feasibility. Only the base margin matters.                                                            |
| **Extreme high**    | 3.0 — even a 5-step killshot needs 15 extra army. Effectively disables killshots except at point-blank range with overwhelming force. |
| **Effective range** | 0.1–2.0                                                                                                                               |

---

### `RACE_MARGIN = 4`

**Consumer:** `bot.py:162` — `if my_travel + self.cfg.RACE_MARGIN < their_travel: return killshot_plan`

When both defend and killshot fire against the same player: killshot wins the race only if `our_travel + RACE_MARGIN < invader's_dist_to_general`. Higher margin = more conservative (we need a bigger head start to justify racing).

| Direction           | Effect                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 8)     | Very conservative — need an 8-tick cushion. Only races when the killshot is dramatically faster than the invader's approach. |
| **Down** (e.g. 1)   | Permissive — races with a slim margin. Risky if BFS distance underestimates invader's actual speed.                         |
| **At 0**            | Races whenever our plan finishes strictly before invader arrives.                                                            |
| **Effective range** | 0–8                                                                                                                          |

## 6. Attack — Target Scoring

### `TARGET_SCORE_W_WEAKNESS = 1.0`

**Consumer:** `attack.py:107` — `cfg.TARGET_SCORE_W_WEAKNESS * weakness`

`weakness = 1.0 / max(0.1, rs.army)`. Hard-gated: score=0 if `rs.army > 1.0`. So `rs.army ∈ (0, 1.0]` → `weakness ∈ [1.0, 10.0]`.

Typical values: enemy at 50% of field average → weakness=2.0; at 80% → 1.25; at 10% → 10.0.

| Direction           | Effect                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Up** (e.g. 3.0)   | Score gap between weak (2.0 × 3 = 6.0) and average-strength (1.0 × 3 = 3.0) targets is amplified. Bot strongly prioritizes weakest player. |
| **Down** (e.g. 0.3) | Weakness contributes little. Proximity and urgency dominate target choice.                                                                 |
| **Effective range** | 0.1–5.0                                                                                                                                    |

---

### `TARGET_SCORE_W_PROXIMITY = 0.8`

**Consumer:** `attack.py:108` — `cfg.TARGET_SCORE_W_PROXIMITY * proximity`

`proximity = exp(-avg_dist / PROXIMITY_HALF_DIST)` where `avg_dist` is the mean BFS distance of the K nearest visible tiles (K=`PROXIMITY_K`). Exponential decay strongly prefers nearby contacts; the averaging over K tiles prevents single straggler tiles from inflating the score.

Weighted proximity values at current settings (half_dist=12):
```
avg_dist:   5     8     10    12    15    20    25
× 0.8:     0.53  0.41  0.35  0.29  0.23  0.15  0.10
```

| Direction           | Effect                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 2.0)   | Proximity dominates target selection. Nearest contacts strongly preferred regardless of weakness.           |
| **Down** (e.g. 0.1) | Distance barely factors in. Willing to attack distant weak players over nearby stronger ones.               |
| **Effective range** | 0.1–3.0                                                                                                    |

---

### `PROXIMITY_HALF_DIST = 12`

**Consumer:** `attack.py:95` — `proximity = math.exp(-avg_dist / cfg.PROXIMITY_HALF_DIST)`

Controls exponential decay steepness. At `avg_dist == PROXIMITY_HALF_DIST`, proximity ≈ 0.37.

| Direction           | Effect                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 20)    | Gentler decay. Moderate-distance contacts (avg_dist=15) still score well. Less preference for nearby targets.   |
| **Down** (e.g. 7)   | Steep decay. Only very close contacts matter. avg_dist=15 is nearly zero.                                       |
| **Effective range** | 5–25                                                                                                            |

---

### `PROXIMITY_K = 10`

**Consumer:** `attack.py:93` — `nearest_k = np.sort(reachable)[:cfg.PROXIMITY_K]`

How many nearest visible tiles to average for the proximity distance. If the player has fewer than K visible reachable tiles, all are used.

| Direction           | Effect                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 20)    | Requires a broad front for high proximity. A player with 5 close tiles and 15 far tiles gets diluted.                            |
| **Down** (e.g. 3)   | Small cluster of nearby tiles is enough. More susceptible to straggler tiles inflating the score (though less than K=1 / nearest-only). |
| **Effective range** | 3–20                                                                                                                             |

---

### `TARGET_SCORE_W_GROWING = 0` (disabled)

**Consumer:** `attack.py:109` — `cfg.TARGET_SCORE_W_GROWING * growing`

Binary signal: `growing = float(land_delta > 0)` over CONFLICT_WINDOW. Contribution is 0 or `w_growing`. Currently disabled — target selection uses weakness and proximity only.

| Direction            | Effect                                                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 1.0)    | Big urgency bonus (+1.0) for growing targets. Could dominate over proximity differences. Bot prioritizes "closing window" aggressively. |
| **Down** (e.g. 0.05) | Growth signal is nearly irrelevant. Bot attacks based on weakness and proximity alone.                                                  |
| **Note**             | Since this is binary (0 or w_growing), its effective scale is "how big a bonus does growth add relative to the other terms."            |
| **Effective range**  | 0.0–1.5                                                                                                                                 |

### `TARGET_SCORE_W_CONFLICT = 0` (disabled)

**Consumer:** `attack.py:110` — `- cfg.TARGET_SCORE_W_CONFLICT * in_conflict` (subtracted)

Binary: `in_conflict = float(conflict_flag(p))`. Triggers when the target player is **losing** land in a mirrored fight. Contribution is 0 or `-w_conflict`. Currently disabled — the bot doesn't penalize fighting targets.

| Direction           | Effect                                                                                                                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 2.0)   | Large penalty (-2.0) for attacking players already in a fight. Very conservative about three-way conflicts.                                                                                   |
| **Down** (e.g. 0.1) | Minor penalty. Willing to dogpile on fighting players.                                                                                                                                        |
| **Note**            | Since it's subtracted and binary, compare against the typical total of other terms (~1.5–3.0) to judge impact. At 0.5, it's a moderate dip. At 2.0, it can flip sign and zero out the target. |
| **Effective range** | 0.0–3.0                                                                                                                                                                                       |

### `ATTACK_SWITCH_THRESHOLD = 0.5`

**Consumer:** `attack.py:209` — `return new_score > current_score + cfg.ATTACK_SWITCH_THRESHOLD`

Hysteresis for the current attack target. New target must outscore current by this amount. With the current weights (weakness=1.0, proximity=0.8, growing/conflict disabled), typical TargetScore range is ~1.0–3.0.

| Direction            | Effect                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 2.0)    | Almost never switches. Locked into current target unless a dramatically better opportunity appears. |
| **Down** (e.g. 0.05) | Switches on tiny score differences. Maximum opportunism, frequent churn, wasted gather progress.    |
| **Extreme low**      | 0.0 — no hysteresis. Any marginal improvement switches.                                             |
| **Extreme high**     | 5.0 — never switches (typical score spread doesn't reach 5).                                        |
| **Effective range**  | 0.05–1.5 (should be calibrated to typical score spread once weights are set)                        |

## 7. Conflict Detection

### `CONFLICT_WINDOW = 20`

**Consumers:** `attack.py:45,49,96,98` — lookback period for land delta comparisons.

In generals.io sim ticks, 20 ticks ≈ 10 real-time seconds. Land ticks (all tiles generate +1 army) happen every 25 ticks.

| Direction           | Effect                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Up** (e.g. 50)    | Captures longer engagements, smoother signal. But slow to detect new fights, and old fights that ended still show in the window. |
| **Down** (e.g. 5)   | Fast detection. But land deltas over 5 ticks are small (maybe 1–3 tiles), so CONFLICT_THRESHOLD must also be lowered.            |
| **Effective range** | 5–50 (must be tuned with CONFLICT_THRESHOLD)                                                                                     |

---

### `CONFLICT_THRESHOLD = 3`

**Consumers:** `attack.py:52` — `delta_p >= -CONFLICT_THRESHOLD` (loser must lose ≥ threshold), `attack.py:59` — `delta_q <= CONFLICT_THRESHOLD` (winner must gain ≥ threshold)

Over 20 ticks, a strong attack can flip 10+ tiles. Normal expansion adds ~2–5.

| Direction           | Effect                                                   |
| ------------------- | -------------------------------------------------------- |
| **Up** (e.g. 8)     | Only big fights count. Misses moderate engagements.      |
| **Down** (e.g. 1)   | Very sensitive. Normal expansion can look like fighting. |
| **Effective range** | 1–10 (tied to CONFLICT_WINDOW)                           |

### `CONFLICT_MATCH_TOL = 5`

**Consumer:** `attack.py:61` — `abs(delta_p + delta_q) < cfg.CONFLICT_MATCH_TOL`

If p loses 8 and q gains 6, sum = -2, abs = 2 < 5 → match. Allows imperfect mirroring (tile flips to/from third parties, neutrals, etc.).

| Direction           | Effect                                                                        |
| ------------------- | ----------------------------------------------------------------------------- |
| **Up** (e.g. 12)    | Very permissive. Unrelated land changes can match.                            |
| **Down** (e.g. 1)   | Strict mirror. Only detects clean 1v1 fights with no third-party involvement. |
| **Effective range** | 1–10                                                                          |

## Summary: Tuning posture

The initial values lean conservative on kill-shots (high base margin + steep per-step cost + large race margin) and moderate on attack commitment. Target scoring uses weakness and proximity only — the growth-urgency and conflict-avoidance signals are disabled until the bot's base behavior is validated.

**Constants most likely to need early adjustment based on observed play:**
- `KILLSHOT_MARGIN_BASE` / `KILLSHOT_MARGIN_PER_STEP` — if the bot never attempts killshots, these are too high; if it attempts and fails, too low
- `ATTACK_COMMIT_FRACTION` — if attack never fires early-mid game, the floor is too high for the available army
- `ATTACK_SWITCH_THRESHOLD` — calibrate once typical TargetScore spreads are observed (currently 0.5 against scores in the ~1–3 range)
