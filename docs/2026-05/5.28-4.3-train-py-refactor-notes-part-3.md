# PR 3 sketch — TrainingState + combined checkpoint format

**Date:** 2026.05.28
**Design contract:** [`5.28-2-train-refactor-and-resume-design.md`](./5.28-2-train-refactor-and-resume-design.md) (§TrainingState, §Checkpoint format, §Sub-PR breakdown #3)

Introduce the persistent-state object and switch the on-disk checkpoint to the combined dict. **Fresh-run behavior unchanged; only the bytes on disk change.** Resume *wiring* (`--resume`, suffixes, drift gate) is PR 4 — this PR adds the state-serialization primitives resume will build on.

## End state

```
training/bc/
  state.py       — TrainingState (new file)
  checkpoint.py  — load_bc_model (+ combined-format branch), ckpt_name (moved from train.py), save_state
  train.py       — run_loop builds TrainingState.fresh(...); loop saves via state.save(...)
```

## `TrainingState` (`state.py`)

```python
@dataclass
class TrainingState:
    model: BCModel
    optim: torch.optim.Optimizer
    scaler: torch.amp.GradScaler
    epoch: int  # last COMPLETED epoch; resume starts at epoch + 1

    @classmethod
    def fresh(cls, config, device) -> "TrainingState": ...
    @classmethod
    def from_checkpoint(cls, path, config, device) -> "TrainingState": ...
    def save(self, ckpt_dir) -> Path: ...
```

- Unfrozen dataclass (models are inherently mutable; pretending otherwise is friction).
- `fresh`: builds `BCModel(value_head_variant=...).to(device)`, the AdamW optim (lr/weight_decay/betas as today), the GradScaler, `epoch=0`. Mirrors the construction currently inline in `run_loop`.
- `from_checkpoint`: `model = load_bc_model(path, device, variant)`; then load `optim`/`scaler` state from the dict **when present** (combined format), and read `epoch`. Added now so the round-trip test has a load path; the resume *flow* that calls it is PR 4.
- `save`: writes the combined dict via one `torch.save` (see below), returns the path. Uses `ckpt_name(self.epoch)`.

## Combined checkpoint format

`<ckpt_dir>/epoch_NNN.pt` becomes:

```python
{"model": model.state_dict(), "optim": optim.state_dict(),
 "scaler": scaler.state_dict(), "epoch": N}
```

Single `torch.save` — load returns the whole dict or raises. No partial-write handling (operator cleans up; per design).

- `load_bc_model` gains the format-detection branch **now** (PR 3 is where the combined producer arrives, so the branch finally has something to read): `obj = torch.load(...); sd = obj["model"] if isinstance(obj, dict) and "model" in obj else obj`. Legacy bare-state_dict checkpoints (incl. the pinned `epoch_005.pt`) still load — distinguished by the absence of a top-level `"model"` key.
- `ckpt_name` moves train.py → checkpoint.py so both `train.py` (epochs.jsonl "ckpt" field, written pre-save) and `state.save` can import it without a train↔state import cycle.

## `train.py` / `run_loop` changes

- Replace the inline `model`/`optim`/`scaler` construction with `state = TrainingState.fresh(config, device)`. Keep the param-count + precision + FLOPs prints (now reading `state.model`).
- Loop body: `train_one_epoch(... model=state.model, optim=state.optim, scaler=state.scaler ...)` (signature still takes the loose pieces this PR — collapsing those params into a `state` arg is PR 4/later, not now). After a completed epoch + val + epoch-row write: `state.epoch = epoch` then `state.save(artifacts.ckpt_dir)`.
- **Invariant:** bump `state.epoch` only AFTER the epoch fully completes and just before/at save — a mid-epoch crash leaves `state.epoch` one behind, which is exactly what resume wants.
- Delete `_save_checkpoint` (→ `state.save`) and its stale "resume isn't on the spike's path" docstring; the format change makes that comment obsolete.
- Update the module docstring line: `checkpoints/epoch_NNN.pt` is now the combined dict, not a bare state_dict.

## `amp_dtype` / precision — the one design-signature wrinkle

`run_loop` needs `amp_dtype` for autocast (threaded into `train_one_epoch`), and the scaler (now owned by `TrainingState`) needs the same fp16-enabled decision. Two ways:

- **(A, default)** `TrainingState.fresh(config, device)` resolves precision internally to build the scaler; `run_loop` independently derives `amp_dtype`. `resolve_precision` is pure + cheap, so the double-call is harmless and keeps the design's exact `fresh(config, device)` signature.
- **(B)** `run_loop` resolves once and passes `amp_dtype` into `fresh(config, device, amp_dtype)` — single source of truth, but extends the signature past the design.

Leaning **(A)** for the clean signature; flag if (B) is preferred.

- Existing `test_checkpoint.py` legacy-format test stays green (combined branch must not break bare-state_dict loading).
