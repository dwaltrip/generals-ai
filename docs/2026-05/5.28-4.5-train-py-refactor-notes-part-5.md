# Part 5 plan — legacy resume + LR warmup

**Date:** 2026.05.28
**Design contract:** [`5.28-2-train-refactor-and-resume-design.md`](./5.28-2-train-refactor-and-resume-design.md) (§`--legacy-lr-warmup-batches`, §Resume-side loader, §Failure modes, §Sub-PR breakdown #5).
**Cross-PR note from Part 4:** [`5.28-4.4`](./5.28-4.4-train-py-refactor-notes-part-4.md) §`prepare_resume` — the legacy epoch fallback.

Part 4 landed resume for combined-format checkpoints. Part 5 makes resume work for the **legacy bare-`state_dict`** checkpoints (the pre-refactor format), where the optimizer's adaptive-step EMAs start from zero. The cold restart is gated behind an explicit `--legacy-lr-warmup-batches N` opt-in that ramps the LR over the first `N` batches so the first few hundred steps don't do damage at full LR while AdamW's `v_t` re-warms.

## Refinements settled in discussion

These extend or deviate from the contract; settled before writing this sketch.

- **`--legacy-lr-warmup-batches` is a CLI directive, not a `TrainConfig` field** (Part-4 deviation #3, confirmed). It's a transient per-segment knob — it shouldn't enter the trajectory config, `args.json`'s config body, or the drift gate. It is instead logged in the `_resume_meta` block (below).
- **`_resume_meta` becomes the home for resume-time directives.** It gains `legacy_lr_warmup_batches`, `force_config_mismatch`, and `legacy_checkpoint` (the detected fact). The first two close a pre-existing provenance gap — `--force-config-mismatch` is logged nowhere today. `_resume_meta` lives in the bc-side `args_resume_NN.json` written by `write_args_resume`, which runs on both local and Modal, so one write covers both environments.
- **`ResumeInfo.is_legacy_checkpoint` is set by a content peek in `prepare_resume`** — it reads the latest checkpoint's structure (dict with a `"model"` key ⇒ combined; bare `state_dict` ⇒ legacy), not just filenames. This makes `ResumeInfo` a complete picture of the resume target. The format-detection logic lives in `checkpoint.py` (the format-knowledge home) and is shared with `load_bc_model` / `from_checkpoint`.
- **Combined-format checkpoint + `--legacy-lr-warmup-batches` ⇒ abort.** The flag is meaningless on a healthy optimizer state, and silently throttling LR on a normal resume is a footgun. Strict-by-design, matching the rest of the resume gating.
- **`bc_resume(..., info)` is required** (drop the Part-4 `info=None` branch). Both wrappers now compute `info` via `prepare_resume` and pass it; `bc_resume` consumes it. One call shape instead of two — the `None` branch only existed because the local path didn't pre-compute the suffix the way Modal must.
- **Per-batch `lr` logged in `batches.jsonl`.** Makes the warmup ramp observable in a real run (the Part 6 cloud resume); constant column (`= config.lr`) on fresh runs. Fingerprint-safe — `smoke_train.sh` reads a fixed key set that excludes `lr`.
- **`WarmupSchedule` lives on `TrainingState`, not threaded as a param.** Conceptually it's training mechanics (it drives `optim`), so it belongs with the domain training state rather than the outputs/IO bucket (`RunArtifacts`). Practically, this is also the cleaner wiring: `bc_resume` attaches it inside its `make_state` closure — the existing injection point for fresh-vs-resume divergence — so `run_training` and `train_loop` signatures are **untouched**. The field is transient (not checkpointed); `save()` hand-picks its keys and deliberately omits it.
- **Legacy-resume e2e test deferred** — discuss + document after implementation (per the focused-testing default; Part 4's fresh+resume e2e was likewise manual).

## `WarmupSchedule` (`bc/resume_warmup.py`, new)

A deliberately narrow module — the legacy-checkpoint LR workaround, not a general LR-schedule framework.

```python
class WarmupSchedule:
    def __init__(self, target_lr: float, n_batches: int):
        self.target_lr = target_lr
        self.n_batches = n_batches
        self.t = 0  # batches stepped in the resumed segment

    def step(self, optim) -> None:
        frac = min(1.0, (self.t + 1) / self.n_batches)
        lr = self.target_lr * frac
        for group in optim.param_groups:
            group["lr"] = lr
        self.t += 1
```

- Linear ramp `target_lr·(t+1)/N` for `t < N`, holds at `target_lr` for `t ≥ N` (the `min(1.0, …)` cap). `target_lr = effective.lr`.
- The counter is **transient** (on the object, not on `TrainingState`) and spans the resumed **segment's** batches — not per-epoch. One instance is built in `bc_resume` and threaded through every `train_one_epoch` call of the segment, so `t` accumulates across the segment's epochs.
- `N` counts batches from resume, not from the checkpoint's prior history — the AdamW `v_t` EMA we're re-warming only accumulates during fresh optimizer steps.

## `bc/checkpoint.py`

Add the shared format-detection helper; both existing loaders route through it instead of re-inlining the `"model" in obj` check.

```python
def _is_combined(obj) -> bool:
    return isinstance(obj, dict) and "model" in obj

def is_legacy_checkpoint(path, device="cpu") -> bool:
    """True if `path` is a legacy bare-state_dict checkpoint (no combined wrapper)."""
    return not _is_combined(torch.load(path, map_location=device, weights_only=True))
```

Plain `torch.load` — the extra read is a sub-second one-time cost at resume startup. (`mmap=True` would make the peek near-free by not materializing tensors; one-line upgrade if we ever care.)

## `bc/state.py`

Two changes: a transient `warmup` field, and a `fallback_epoch` param on `from_checkpoint`.

**`warmup` field** — `warmup: WarmupSchedule | None = None`. Defaulted, so `fresh()` and `from_checkpoint()` leave it `None`; the resume path attaches it (see `bc/resume.py`). Carries a comment: *transient — not written by `save()`; the resume path rebuilds it per-process*. The class docstring's "the bits that survive a resume" framing is broadened so it doesn't over-claim with a non-persistent field present. `save()` already hand-picks its 4 keys (not `asdict`-based), so omitting `warmup` is automatic; the comment makes the intent loud.

**`fallback_epoch`** on `from_checkpoint`, fixing the legacy epoch bug (the Part-4 cross-PR note):

```python
@classmethod
def from_checkpoint(cls, path, config, device, fallback_epoch: int = 0) -> TrainingState:
    ...
    epoch = fallback_epoch                       # was: epoch = 0
    obj = torch.load(...)
    if _is_combined(obj):
        ...
        epoch = int(obj.get("epoch", fallback_epoch))
    return cls(..., epoch=epoch)
```

Combined format reads its own `epoch` from the dict (unchanged). Legacy has none ⇒ `epoch` stays at `fallback_epoch`, which `bc_resume` passes as `info.parent_epoch` (parsed from the filename). Fresh runs use `.fresh`, never this path, so the default `0` is inert.

## `bc/run_dir.py`

- **`ResumeInfo` gains `is_legacy_checkpoint: bool`.**
- **`prepare_resume`** calls `is_legacy_checkpoint(latest)` and sets the field. Still a pure read (no writes); now reads content as well as filenames. Docstring updated.
- **`write_args_resume`** signature grows to carry the directives into `_resume_meta`:
  ```python
  def write_args_resume(config, info, *, legacy_lr_warmup_batches, force_config_mismatch) -> None:

          "resumed_from_epoch": info.parent_epoch,

      }
  ```

## `bc/resume.py`

`bc_resume` grows the warmup directive and requires `info`:

```python
def bc_resume(config, force_config_mismatch, overrides, info, legacy_lr_warmup_batches=None) -> None:
    parent = load_parent_config(info.parent_args_path)
    effective = _resume_config(config, parent, overrides)
    check_drift(effective, parent, force_config_mismatch)
    if info.parent_epoch >= effective.epochs: abort(...)            # unchanged

    # Legacy gating (new)
    if info.is_legacy_checkpoint and legacy_lr_warmup_batches is None:
        raise SystemExit("legacy bare-state_dict checkpoint — cold optimizer restart "
                         "needs explicit opt-in; pass --legacy-lr-warmup-batches N (e.g. 500).")
    if not info.is_legacy_checkpoint and legacy_lr_warmup_batches is not None:
        raise SystemExit("--legacy-lr-warmup-batches applies only to legacy checkpoints; "
                         "this is a combined-format checkpoint with healthy optimizer state.")

    write_args_resume(effective, info,
                      legacy_lr_warmup_batches=legacy_lr_warmup_batches,
                      force_config_mismatch=force_config_mismatch)

    def make_state(dev):
        state = TrainingState.from_checkpoint(
            info.latest_checkpoint, effective, dev, fallback_epoch=info.parent_epoch)
        if legacy_lr_warmup_batches:
            state.warmup = WarmupSchedule(effective.lr, legacy_lr_warmup_batches)
        return state

    run_training(effective, suffix=info.next_suffix, make_state=make_state)
```

The warmup is attached inside `make_state`, so `run_training` takes no warmup param. The `if info is None: info = prepare_resume(...)` branch and the `prepare_resume` import are removed.

## `bc/train.py`

The warmup rides on `state`, so `run_training` and `train_loop` signatures are **unchanged**. Only `train_one_epoch` and the batch record change.

- `train_loop` passes `warmup=state.warmup` into `train_one_epoch` (alongside the existing `state.optim` etc.).
- `train_one_epoch(..., warmup=None)`: at the top of the batch loop (before the forward, so the LR is set for this batch's step):
  ```python
  if warmup is not None:
      warmup.step(optim)
  ```
- Batch record gains `"lr": optim.param_groups[0]["lr"]`.

Fresh runs carry `state.warmup is None` ⇒ the guard is skipped ⇒ no-op. `bc_run`'s path is untouched.

  parser.add_argument("--legacy-lr-warmup-batches", type=int, default=None,

## Tests (committed)

- **`WarmupSchedule.step` formula** — `t < N` ⇒ `lr == target·(t+1)/N`; `t ≥ N` ⇒ `lr == target`; counter increments every call. Direct on a dummy optimizer; no training.
- **`is_legacy_checkpoint` detection** — combined ⇒ `False`, bare state_dict ⇒ `True`. Tiny synthetic checkpoints.
- **Abort paths** — legacy + no flag ⇒ `SystemExit`; combined + flag ⇒ `SystemExit`.
- **`from_checkpoint` fallback** — `from_checkpoint(legacy, fallback_epoch=5).epoch == 5`; combined still reads its own epoch.
