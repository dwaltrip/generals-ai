# train.py refactor + resume design

**Date:** 2026.05.28

`training/bc/train.py` has grown to ~470 lines with several distinct concerns tangled in the same function bodies — model + optimizer construction, file-handle lifecycle, JSONL writing, console formatting, FLOPs/MFU measurement, checkpoint save, val orchestration. This doc designs a refactor that splits those concerns into small abstractions (`TrainingState`, `RunArtifacts`, `RunLogger`), and then uses the cleaned structure to add proper resume support for BC training runs on Modal.

The refactor is the primary goal. Resume is the new functionality the cleaned structure enables.

---

## Goals

**Primary — decouple the mixed concerns in `train.py`:**

- Persistent training state (model + optim + scaler + epoch) becomes a named object that owns its own serialization.
- Per-run runtime resources (file handles, ckpt_dir, FLOPs constant) move into a `RunArtifacts` struct.
- JSONL writing moves into a `RunLogger` aware of resume-segment suffixing.
- Console output, dataloader construction, and warmup logic become named functions in `train.py` rather than inline blocks inside `run_loop` / `train_one_epoch`.

**Secondary (enabled by primary) — proper resume:**

Save model + optim + scaler + epoch at each checkpoint; on resume, restore all four and continue with epoch numbering monotonic across segments. Mitigates Modal's 24h function timeout and recovers from the 5/8-epoch incident from 2026-05-27 (a planned 8-epoch run cut short by a 6h timeout we'd forgotten to raise on the training function).

## Non-goals

- **Mid-epoch resume.** Epoch boundary only. Mid-epoch would require dataloader-state rehydration and a partial-row reconciliation in `batches.jsonl`; not worth the complexity.
- **RNG-state preservation.** Train data order is deterministic from `(seed, epoch)` via `set_epoch`; dropout-style randomness in the forward pass is not byte-restored on resume.
- **Checkpoint pruning.** Modal Volume disk grows linearly with epochs across resumes; deferred.
- **Lightning-style trainer framework / hooks.** Over-structure for our scale — one trainer, no distributed, no plugins.

## Current state

`train.py` is 469 lines, 9 functions. The two largest:

- `run_loop` (148 lines): model + optimizer + GradScaler construction, FLOPs measurement, epoch loop, per-epoch JSONL writes, console formatting, checkpoint save.
- `train_one_epoch` (109 lines): per-batch training step, rolling samples/sec tracking, per-batch JSONL writes, per-N-batch console log.

Checkpoint format today is `model.state_dict()` only (no optim, no scaler, no epoch — explicit comment at `train.py:83`: *"Resume-from-checkpoint isn't on the spike's path"*). Run-dir lifecycle is split between `initialize_run_dir` and `bc_run`. Two parallel checkpoint loaders exist in the inference path (`self_play.agent.load_checkpoint`, `value_head_probe.load_frozen_trunk`), each doing `torch.load + load_state_dict` directly with no shared helper.

## Architecture

Two new dataclasses and one new logger class encapsulate the concerns:

### `TrainingState` — the persistent state

The bits that survive a resume:

```python
@dataclass
class TrainingState:
    model: BCModel
    optim: torch.optim.Optimizer
    scaler: torch.amp.GradScaler
    epoch: int  # last completed; resume starts at epoch + 1
```

Constructed via classmethods:

- `TrainingState.fresh(config, device)` — builds new model/optim/scaler, epoch=0.
- `TrainingState.from_checkpoint(path, config, device)` — builds the shells, populates from disk via `load_bc_model` + checkpoint dict.

Saves itself via `state.save(ckpt_dir) -> Path`. Lives in `training/bc/state.py`.

The state is mutated in place by `train_one_epoch` (`state.epoch += 1` after each completed epoch) and saved at the end of each epoch. The dataclass is unfrozen — PyTorch models are inherently mutable, and pretending otherwise creates friction.

### `RunArtifacts` — per-run runtime

Born at run start, released at end. Wraps file handles, paths, and run-start measurements that aren't part of the serialized state:

```python
@dataclass
class RunArtifacts:
    run_dir: Path
    ckpt_dir: Path
    logger: RunLogger
    flops_per_sample: int
    peak_tflops: float | None
    resume_segment: int  # 0 for original, 1+ for resumes
    log_path: Path       # suffixed run.log path for tee_stdio
```

Acts as a context manager. `__enter__` opens the `RunLogger`'s JSONL writers; `__exit__` closes them. Lives in `training/bc/run_dir.py`.

### `RunLogger` — suffix-aware JSONL writers

Owns `batches.jsonl` and `epochs.jsonl` writers. Constructor takes a suffix string (`""` for original, `"_resume_01"` for the first resume, etc.) and chooses file paths accordingly.

```python
class RunLogger:
    def __init__(self, run_dir: Path, suffix: str): ...
    def log_batch(self, record: dict) -> None: ...
    def log_epoch(self, record: dict) -> None: ...
    def close(self) -> None: ...
```

Lives in `training/bc/run_logger.py`. Single source of truth for the JSONL format.

### `train_loop` and `train_one_epoch` — the imperative driver

Stay as free functions in `train.py`. Both take `TrainingState` and `RunArtifacts` as arguments; data flow is visible at every call site:

```python
def train_loop(
    state: TrainingState,
    config: TrainConfig,
    loader: DataLoader,
    dataset: IterableDataset,
    val_samples: list[tuple[Path, int]],
    device: torch.device,
    artifacts: RunArtifacts,
) -> None: ...
```

The loop increments `state.epoch`, runs `train_one_epoch`, optionally runs `run_val`, logs the epoch row via `artifacts.logger`, and saves the checkpoint via `state.save(artifacts.ckpt_dir)`.

## Checkpoint format

### New format (combined dict)

`<run_dir>/checkpoints/epoch_NNN.pt` is a dict, written via a single `torch.save`:

```python
{
    "model": model.state_dict(),
    "optim": optim.state_dict(),
    "scaler": scaler.state_dict(),
    "epoch": N,
}
```

Single-file write is structurally atomic — either `torch.load` returns the complete dict or the file is missing / unreadable and the load fails loudly.

### Legacy format (bare state_dict)

Existing `epoch_NNN.pt` files (pre-refactor) are raw `state_dict` objects — a flat dict of parameter tensors. The pinned smoke-test checkpoint at `training/data/runs-cloud/2026-05-23T23-40-14Z/checkpoints/epoch_005.pt` is the load-bearing reason to keep loading these.

### `load_bc_model` helper

Single function in `training/bc/checkpoint.py`:

```python
def load_bc_model(
    path: Path,
    device: torch.device,
    value_head_variant: str = "direct",
) -> BCModel:
    """Load a BC model from a checkpoint. Handles both combined and legacy formats."""
```

The format-detection branch lives only in this helper. All inference and probe callers go through it:

- `self_play.agent.load_checkpoint` becomes a one-line delegating wrapper (5+ existing consumers in `packages/`, `scripts/`, and tests; the wrapper allows migration without touching every call site at once). Deletion of the wrapper is a follow-up PR.
- `value_head_probe.load_frozen_trunk` uses the helper, then extracts the trunk.

### Resume-side loader

`TrainingState.from_checkpoint` reads the dict. If the legacy format is detected and the operator has not passed `--legacy-lr-warmup-batches`, the run aborts with a clear message naming the flag (see [Failure modes](#failure-modes)). Optim/scaler are populated only when present in the wrapped format.

### Modal Volume bandwidth note

The combined format means `modal volume get` of a checkpoint pulls the full bundle (~3x the weights-only size) even when the consumer needs weights only. For current model sizes (~5M params → ~60MB combined vs. ~20MB weights-only), the cost is modest. Revisit if the model grows substantially.

## Run-dir lifecycle on resume

### Suffix rule

On resume, the system writes new files alongside the originals using the suffix `_resume_NN` — zero-padded, starting at `01`. Original files are never touched.

| Original | First resume | Second resume |
|---|---|---|
| `args.json` | `args_resume_01.json` | `args_resume_02.json` |
| `args_cloud.json` | `args_cloud_resume_01.json` | `args_cloud_resume_02.json` |
| `batches.jsonl` | `batches_resume_01.jsonl` | `batches_resume_02.jsonl` |
| `epochs.jsonl` | `epochs_resume_01.jsonl` | `epochs_resume_02.jsonl` |
| `run.log` | `run_resume_01.log` | `run_resume_02.log` |
| `gpu_util.jsonl` | `gpu_util_resume_01.jsonl` | `gpu_util_resume_02.jsonl` |

Checkpoints continue monotonic numbering (`epoch_006.pt`, `epoch_007.pt`, ...) — no suffix on the `.pt` files themselves.

### `prepare_resume(run_dir)`

In `training/bc/run_dir.py`. Globs existing `*_resume_NN.*` artifacts and returns a small struct:

```python
@dataclass
class ResumeInfo:
    next_suffix: str       # e.g., "_resume_02"
    latest_checkpoint: Path
    parent_epoch: int      # last completed epoch
    parent_args_path: Path # the immediate predecessor args file
    is_legacy_checkpoint: bool
```

Callers (the resume entry point) use this to wire the suffix into `RunLogger`, `RunArtifacts`, `args_resume_NN.json` writes, and `tee_stdio`'s target path.

### `args_resume_NN.json` schema

Same shape as `args.json` (full `TrainConfig` as JSON), plus a `_resume_meta` block at the top:

```json
{
  "_resume_meta": {
    "resumed_from_epoch": 5,
    "parent_args": "args.json",
    "resumed_at": "2026-05-28T22:14:00Z"
  },
  "manifest": "...",
  "epochs": 8,
  "lr": 3e-4,
  ...
}
```

`parent_args` points at the immediate predecessor. For the first resume that's `args.json`; for the second resume it's `args_resume_01.json`. Chains naturally for resume-of-resume.

### One-time rename: `console.log` → `run.log`

The training log file is renamed to `run.log` — semantically matches `batches.jsonl` / `epochs.jsonl` (run artifacts), avoids the generic "console" name (also a JS API), and slots cleanly into the suffix rule. Applies to new runs only; existing run dirs keep their `console.log`.

## CLI surface

### `--resume <run_id>`

New flag on both `run_bc_modal.py` and `run_bc_local.py`. Resolves the run ID to a run dir based on the environment:

- Modal: `/runs/<run_id>` (the Volume mount).
- Local: `<runs_dir>/<run_id>` (depends on the wrapper's default).

`<run_id>` is the timestamp directory name (e.g., `2026-05-27T22-04-15Z`).

### `--force-config-mismatch`

Drift-safety gate. On resume, the resume-side `TrainConfig` is compared to the parent's `args.json`. Every field is compared except: `epochs` (the new target), `run_dir`, `manifest`, `intermediate`. If any other field differs, the run aborts with a message listing the deltas. `--force-config-mismatch` overrides this gate.

Strict by design: performance knobs (`num_workers`, `pin_memory`, `prefetch_factor`) are included. If this proves too aggressive in practice, perf knobs can be carved out later. Predictability beats subtlety here.

### `--legacy-lr-warmup-batches <int>`

Enables linear LR warmup over the first `N` batches of the resumed segment. The LR ramps linearly from `target_lr * (1/N)` up to `target_lr`, then holds. Default: off.

Used only when resuming from a legacy bare-state_dict checkpoint, where the optimizer's adaptive-step EMAs (especially `v_t`, β₂=0.999, half-life ~700 batches) start from zero. Warmup gates the cold-restart loss bump while `v_t` re-warms — it does not fix the missing variance estimates directly, but it prevents the first few hundred steps from doing damage at full LR.

If the operator attempts to resume a legacy checkpoint *without* this flag, the run aborts. Cold-restart is the operator's explicit opt-in.

## Failure modes

All failures abort before any training work begins, with clear messages.

- `--resume <id>` for nonexistent run dir.
- Run dir exists but `checkpoints/` is empty.
- Latest checkpoint's epoch is `>= config.epochs` (the run already finished — nothing to resume).
- Config drift detected without `--force-config-mismatch`.
- Legacy bare-state_dict checkpoint detected without `--legacy-lr-warmup-batches`.
- `value_head_variant` mismatch (caught by `load_state_dict(strict=True)`).

V1: most checks happen Modal-side, failing within seconds of container startup (~5-30s).

V2 (deferred): pre-pull `args.json` and `epochs.jsonl` via the Modal Volume SDK to fail entirely on the local side before any container spawns.

## Sub-PR breakdown

Brief sketch — ordering may shift as we implement.

1. **Decoupling refactor.** Extract `RunArtifacts`, `RunLogger`, `print_epoch_summary`, `build_dataloader`. Rename `console.log` → `run.log`. Zero behavior change for training runs.
2. **Centralize checkpoint loading.** Add `load_bc_model` helper in `training/bc/checkpoint.py`. Migrate `self_play.agent.load_checkpoint` and `value_head_probe.load_frozen_trunk` to delegate. No checkpoint format change yet.
3. **`TrainingState` + new checkpoint format.** Add `state.py`, switch the save path to the combined dict. Fresh-run behavior unchanged; format on disk is new.
4. **Resume mechanics.** `run_dir.py:prepare_resume`, `--resume` flag, suffix discipline, `--force-config-mismatch`. End-to-end resume works for new-format checkpoints.
5. **Warmup.** `_apply_warmup_lr` named function, `--legacy-lr-warmup-batches` flag. Legacy-checkpoint resume works.
6. **(Operational)** Resume the 2026-05-27 run with `--legacy-lr-warmup-batches 500`.

## Tests

- **`TrainingState` save/load round-trip.** Save state, load into fresh shells, run one batch — assert resulting parameters match a continuous training comparison. Deterministic equivalence.
- **`prepare_resume` suffix discovery.** Given a run dir with N resume artifacts, returns `_resume_{N+1:02d}`.
- **`load_bc_model` legacy format.** Bare-state_dict checkpoint loads into a fresh `BCModel` without errors.
- **`_apply_warmup_lr` formula.** At step `t < N`, LR is `target * (t+1)/N`; at step `t >= N`, LR is `target` (untouched).
- **Integration smoke.** 2 epochs → kill → resume 2 more. Assert `epochs.jsonl` has rows 1-2, `epochs_resume_01.jsonl` has rows 3-4, both with monotonic epoch numbers.

## Deferred concerns

- **Checkpoint pruning.** Modal Volume disk grows linearly with epochs across resumes. At ~60MB per checkpoint and ~10-20 epochs per run, a few resumed runs fill several GB. Worth a "keep last K" policy eventually.
- **Local pre-validation via Modal Volume SDK.** V1 fails fast Modal-side (~5-30s container startup). V2 could pre-pull `args.json` and `epochs.jsonl` locally to fail before any container spawns.
- **`gpu_util_sidecar` reliability.** Currently broken. Only the file-naming change (`_resume_NN` suffix) is in scope here; the sampling logic is a separate fix.
