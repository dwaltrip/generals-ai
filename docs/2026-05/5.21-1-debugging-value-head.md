# Value head is a constant predictor (dead-ReLU collapse)

**Date:** 2026-05-21
**Branch:** `spike-phase-3`
**Context:** Post-PoC analysis of `training/data/runs/20260521-005930/` (2k games × 5 epochs, M1 MPS).

## Finding

The value head in `epoch_005.pt` is **mechanically a constant predictor**: it produces bit-for-bit identical 8-class softmax output across every input. Root cause is a **dead-ReLU collapse** inside the head.

The pipeline `Conv2d(160→1, k=3) → ReLU → flatten → Linear(1024 → 8)` has settled into a state where:

- The conv layer outputs uniformly negative values across all 32×32 cells, regardless of input. Measured on a batch of 64 val frames: `min=-26.42, max=-1.24, mean=-7.17` — the *maximum* pre-ReLU activation is still negative.
- ReLU annihilates everything to zero. Post-ReLU features are strictly zero on every cell, every sample.
- The linear layer therefore sees an all-zero input vector on every forward pass. The output is entirely the bias.
- The 8-dim bias has trained to `[1.235, 0.572, -0.030, -0.580, -1.068, -1.497, -1.830, -3.438]`, which softmaxes to `[0.4585, 0.2362, 0.1294, 0.0746, 0.0458, 0.0298, 0.0214, 0.0043]` — matches the train placement marginal to ~3 decimals.

Because gradient through ReLU is zero everywhere the pre-activation is negative, the conv weights and the linear's non-bias weights are stuck. The 64-parameter bias vector is effectively the entire trained "head."

## Supporting evidence

Two independent lines of evidence converge:

1. **Loss matches marginal entropy.** Frame-weighted marginal entropy of placement on val = **1.5195 nats**; val value loss at epoch 5 = **1.52**. Within noise. A model that has converged on the marginal as a constant prediction would land exactly here. Train and val marginals match (1.5164 vs 1.5195), so it's not a distribution-shift artifact. Reproduce: `uv run python training/scripts/marginal_entropy.py training/data/splits/poc_2kish_perspecs.json --include-train`
2. **Per-batch view shows a sharp early plateau.** Value loss drops from ~2.3 to ~1.5 in the first ~30% of epoch 1, then is flat for 4.7 epochs (`training/data/runs/20260521-005930/plots/per_batch_loss.png`). Other heads keep descending across all 5 epochs. Consistent with the head reaching its dead-ReLU state quickly and getting stuck.

Frame-weighted val placement distribution:
```
1st 47.6%  2nd 19.3%  3rd 15.5%  4th  3.9%
5th  5.0%  6th  5.9%  7th  2.3%  8th  0.7%
```
Frame-weighting (each frame counts once) ~doubles the 1st-place share vs. perspective-weighting (32.7% → 47.6%) because survivors play much longer than eliminated players. ~Half the supervision the value head sees is "1st place," which makes the marginal an especially flat local optimum.

## Why the head ended up here

The `Conv(C→1) → ReLU → Linear` shape is a fragile design:

- **Severe bottleneck.** 160 channels collapsed to 1 in a single conv. One dead channel is catastrophic — there's no redundancy.
- **ReLU on the wrong side of the classifier.** Most classifier heads do `pool/flatten → Linear → logits` with no activation before the final linear. The ReLU here restricts the linear's input to `[0, ∞)`, narrowing the function class the head can express.
- **Constant prediction is a deep attractor.** Frame-weighted "1st-place 48%, 8th 0.7%" matches the train marginal very accurately, so the loss gradient near the marginal is small. Easier for the conv to drift into "always negative" (collapsing to bias-only output) than to find a board-conditional function.

The other heads (policy, pass) don't have this structure and don't show the same pathology — they keep learning across all 5 epochs.

## Implications

- **For BC PoC:** the head contributes only trunk regularization in BC. With the head dead and the linear-bias acting as a 64-parameter "constant," the regularization signal it provides to the trunk is also dead. Policy/pass curves are unaffected by this finding directly. PoC critical path is not blocked.
- **For PPO:** load-bearing. Advantages = reward − value; a board-blind baseline gives near-zero learning signal. Must be fixed before Phase 4.
- **For our triage:** the structural diagnosis re-orders the menu of fixes (next section). Cheap signal-shaping tweaks (turn-gate, frame-weight, lambda bump) won't help while the head is structurally dead — `ReLU' = 0` means they multiply nothing.

## Candidate moves

Two tiers: structural fixes that restore gradient flow, then signal/target tweaks that become live once gradient flow is restored.

**Tier 1 — structural (address the dead-ReLU root cause):**

1. **Re-initialize just the value head, warm-start everything else from `epoch_005.pt`, keep training.** Probe: is the trunk's representation usable for placement prediction at all? Or will the head re-collapse from a fresh start? Cheapest experiment — single retraining run on a small slice.
2. **Remove the ReLU between conv and linear.** One-line model change. Lets the linear layer see the full range of conv outputs. (Note: DeepNash has a ReLU here, but their setup is scalar output + RL supervision with v-trace — different gradient dynamics.)
3. **Widen the conv: `Conv2d(C→K)` with K ∈ {8, 16, 32}.** Multi-channel projection means a single dead channel is no longer catastrophic. Closer to a typical classifier head.
4. **Swap ReLU for LeakyReLU or GELU** in the head. Allows gradient flow even with negative pre-activation. Cheap.
5. **Option C extension** — insert PyramidModule before projection (stubs at `model.py:473-482` already encode this). Adds capacity and skip connections that prevent total signal loss. Bigger change but the most "architecturally correct" fix.

**Tier 2 — signal/target tweaks (live again once Tier 1 unsticks the head):**

These were our first instinct before the dead-ReLU diagnosis. They don't help while gradient is zero, but they remain real questions about *what target signal* makes sense for placement prediction in BC. Worth revisiting once the head is responsive:

- **Turn-gate the value loss** — only contribute `value_ce` for frames past some turn threshold. Tests "early-game frames are too noisy to predict placement from" as an isolated hypothesis. Currently untested — dead ReLU short-circuited it.
- **Frame-weighted value CE** — softer version of the gate, weight per-frame contribution by `t/T` or similar.
- **Bump `LAMBDA_VALUE`** from 0.5 → 1.0 or 2.0 — give the value gradient more pull in the total loss. Currently moot (×0 = 0), live after Tier 1.
- **Bootstrapped categorical targets** — target at time t = mixture of `softmax(v_θ(s_{t+1}))` and final-outcome one-hot. Closest BC-compatible analogue to DeepNash's v-trace. Harder implementation, evaluate after simpler fixes.
- **Re-weighted CE** — weight loss by inverse class frequency, since 1st is ~48% of frames and 8th is ~0.7%.
- **Switch to scalar value** — predict expected placement (continuous), enables direct TD(0). Bigger architecture change.

## Open

- Whether Tier-1 fixes restore the head end-to-end, or whether the trunk's representation also lacks board-conditional placement signal (the reinit experiment settles this).
- Which Tier-2 hypothesis dominates once the head is unstuck.
- Whether to do Tier-1 in spike or punt to early Phase 4. (Tier 1 #2 is one line; Tier 1 #5 is half-day. Spread.)
