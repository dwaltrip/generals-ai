## 1. WorldModel + PlayerView refactor, Plan dataclass

Refactor before new logic. Zero behavior change — smoke test validates.

### WorldModel (new class, `world_model.py`)

Owns raw sim state and the per-tick update pipeline. Internal state that decision logic never touches:
- Ownership/armies snapshot buffers (`[T, HW]`)
- Sim dict (mountains, cities, generals, capture events)
- MemoryState (fog tracking from `bc.obs`)

`init_for_game(state, static)` — allocate buffers, init MemoryState. Existing code extracted from `EvalBot.init_for_game`.

`update(state, static) -> PlayerView` — per-tick pipeline:
1. Append latest ownership/armies snapshots
2. Refresh dynamic sim fields (cities, capture_events)
3. Compute visibility (`bc.visibility.compute_visibility`)
4. Advance fog tracking (`bc.obs.step_memory`)
5. Compute scoreboard (land/army per player)
6. Build fog-filtered ownership/armies: `np.where(vis, god_state, sentinel)`
7. Compute passable mask (`known_passable_mask`)
8. Package into PlayerView and return

Steps 1–5 are existing code moved from `EvalBot.act`. Steps 6–7 are new (fog-filtered arrays, passable was previously computed in `act`).

### PlayerView (new dataclass)

Everything the bot can legally see this tick. Decision functions receive this, nothing else.

```
own: [H, W] int8        — fog-filtered ownership. -2 = no info (fogged).
arm: [H, W] int16       — fog-filtered armies. 0 behind fog.
vis: [H, W] bool         — current visibility mask.
passable: [H*W] bool     — BFS passability.

my_slot: int
gen_flat: int
H, W: int
timestep: int

land: [P] int            — scoreboard: tile count per player.
army: [P] int            — scoreboard: total army per player.
alive: [P] bool          — per-player alive status.

mem: MemoryState          — fog-tracking memory. TODO: cherry-pick fields
                            instead of passing the full object, so decision
                            logic can't accidentally reach raw state through it.
```

M2 additions (wired up in later sections): `contact_set`, `threat_windows`, `incursion_threats`.

### EvalBot changes

Slimmed down. Holds:
- `self.world: WorldModel` — created in `__init__`, initialized in `init_for_game`
- `self._active_plan: Plan | None` — multi-tick plan state (None until a gate creates one)
- Counters (`n_moved`, `n_expand`, etc.)

`init_for_game(state, static)` — delegates to `self.world.init_for_game(...)`, resets plan + counters.

`act(view: PlayerView) -> (src, dst, is50)` — pure decision logic. No raw state access, no update calls. Signature change: takes `PlayerView` instead of `(state, static)`.

### Driver changes (`driver.py`)

Tick loop becomes:
```python
view = bot.world.update(state, static)
src, dst, is50 = bot.act(view)
```

Update and decide are visibly separate at the call site. Raw sim state flows into WorldModel; only PlayerView reaches decision logic.

### Plan dataclass

Defined in this step, not yet used by any gate (explore still emits single moves).

```
gate: str                 — which gate created this plan ("explore", "defend", etc.)
moves: list[(src, dst, is50)]  — pre-computed move sequence.
cursor: int               — index of next move to emit. Starts at 0.
```

`next_move() -> (src, dst, is50) | None` — returns move at cursor and advances, or None if exhausted.

### Decision function signature changes

`pick_expand_or_explore(view: PlayerView)` — replaces the current multi-arg signature. Internal helpers (`_expandable_tiles`, `_pick_expand_move`, etc.) can unpack what they need from `view`.

## 2. ThreatWindow + IncursionThreat

Threat detection machinery. All state lives on WorldModel, results surfaced through PlayerView.

### Data structures (world_model.py)

```
ThreatEntry:
    pos: int              — flat cell index of the tracked stack
    army: int             — army count at that position
    dist_to_general: int  — BFS distance from pos to bot's general
```

### Persistent state on WorldModel

```
_threat_windows: dict[int, deque[ThreatEntry]]   — per contact player, maxlen THREAT_WINDOW_LEN
_eating_baselines: dict[int, ndarray[H, W] bool]  — snapshot of "was mine" at window-open
```

Initialized empty in `init_for_game`. Persists across ticks — windows accumulate history until identity breaks or player leaves contact.

### WorldModel.update() additions

After passable mask (step 7), before building PlayerView. Each step is a private method on WorldModel — `update()` calls them in sequence and passes results forward. Existing steps 1–7 stay inline for now; new code adopts the extracted-method pattern.

```
 8. _compute_contact_set() -> set[int]
    contact_set = { p : mem.opp_contacted[p] and mem.opp_captured_by[p] == -1 }

 9. _update_threat_windows(fog_own, fog_arm, passable, contact_set)
    for each p in contact_set:
      a. find largest visible stack: argmax(fog_arm where fog_own == p)
         - if no visible tiles for p → clear window + baseline, continue
      b. identity check: if window not empty and manhattan(best_pos, prev_pos) > 1
         → clear window + baseline
      c. if window is empty → snapshot eating baseline: (fog_own == my_slot)
      d. append ThreatEntry(pos, army, bfs_dist(pos, gen_flat, passable))

    for each p NOT in contact_set (or dead): clear window + baseline

10. _evaluate_incursion_threats(fog_own) -> dict[int, bool]
    for each p with len(window) >= 2:
      Closing:
        deltas = [entry[i].dist - entry[i-1].dist for consecutive pairs]
        closing = mean(deltas) < CLOSING_THRESHOLD

      Eating:
        threat_pos = window[-1].pos
        eaten = count cells where:
          manhattan(cell, threat_pos) <= EATING_RADIUS
          and eating_baseline[cell] == True (was mine at window-open)
          and fog_own[cell] == p (now theirs)
        eating = eaten >= EATING_MIN

      incursion_threat[p] = closing AND eating
```

### PlayerView additions

```
contact_set: set[int]
threat_windows: dict[int, deque[ThreatEntry]]  — Defend reads for severity, position, time budget
incursion_threats: dict[int, bool]              — Defend gate trigger
```

### How downstream code reads these

- **Defend gate (§3):** `view.incursion_threats` → does the gate fire? `view.threat_windows[p][-1]` → threat pos, army, dist_to_general for severity check and intercept targeting.
- **Tick loop preemption:** check `any(view.incursion_threats.values())` to decide if defend should preempt an active explore/attack plan.

## Decision flow architecture

How `act()` works once the plan lifecycle is in place. Sections 3–6 all plug into this structure.

### Gate result types (plan.py)

```
SingleMove: src, dst, is50, gate        — fire-and-forget, no lifecycle

Plan (base):                             — multi-tick, managed by _tick_active_plan
    moves: list[(src, dst, is50)]
    cursor: int (init=False, starts 0)
    next_move(), is_complete              — shared behavior via inheritance

DefendPlan(Plan):   target_player: int
ExplorePlan(Plan):  (no extra fields)
AttackPlan(Plan):   target_player: int   (future)
KillshotPlan(Plan): target_general: int  (future)

GateResult = Plan | SingleMove | None
```

The type IS the gate identity — dispatch via isinstance, no string matching. Variant-specific fields carry the metadata each gate's re-evaluation needs. Keep an eye on inheritance complexity; switch to flat dataclasses if it becomes unwieldy.

Expand returns SingleMove. Defend, explore (upgraded), attack, killshot return Plan variants.

### EvalBot.act(view) flow

```
move = _tick_active_plan(view)     — manage existing plan
if move: return move

result = _pick_new_plan(view)      — walk decision ladder
if Plan:       store as active, emit first move
if SingleMove: emit directly
if None:       pass
```

### _tick_active_plan(view) → move tuple | None

Manages the active plan. Only clears or emits — never creates new plans.

```
if no active plan → return None

check spent → clear, return None
gate-specific re-evaluation:
    defend:   re-check incursion threat → clear if resolved or target changed
    attack:   re-check target scores → clear if better target by threshold
    killshot: fully sticky, no re-eval
    explore:  static, run to completion
preemption: if gate not in (defend, killshot) and incursion threat active → clear
if still active → emit next move
```

When re-evaluation clears a plan (defend target changed, attack target switched), `_pick_new_plan` runs immediately after and recreates the right plan via the decision ladder. Same result as inline replacement, cleaner separation.

### _pick_new_plan(view) → GateResult

The decision ladder from spec §2. First gate to fire wins.

```
defend        → try_defend(view)         returns Plan | None
killshot      → try_killshot(view)       returns Plan | None (future)
expand/explore → pick_expand_or_explore  returns SingleMove | Plan | None
attack        → try_attack(view)         returns Plan | None (future)
```

Each gate is a standalone function that reads PlayerView and returns its result type. Gates don't know about each other or the lifecycle — priority is handled by the ladder ordering.

## 3. Defend gate

First real gate beyond expand/explore. Plugs into the decision flow architecture above. Calls gather_path (section 5) — wired but not functional until then.

### Gate function: `try_defend(view) -> DefendPlan | None` (defend.py)

```
1. threats = { p for p, active in view.incursion_threats if active }
   if empty → return None

2. most_severe = pick from threats by:
     closest to general (min dist_to_general), then largest army
     read from view.threat_windows[p][-1]

3. severity → target:
   gen_r, gen_c = divmod(gen_flat, W)
   if threat.army > view.arm[gen_r, gen_c]:
       target = gen_flat                              # rally to general
   else:
       path = bfs_path(threat.pos, gen_flat, ...)
       idx = min(INTERCEPT_LOOKAHEAD, len(path) - 1)
       target = path[idx]                             # intercept ahead

4. time budget:
   max_moves = threat.dist_to_general - INTERCEPT_LOOKAHEAD
   if max_moves <= 0 → return None                    # general absorbs locally

5. plan = gather_path(target, max_moves, min_army=None, gate="defend")
   return DefendPlan(moves=plan.moves, target_player=most_severe)
```

### Re-evaluation: `should_clear_defend(view, plan) -> bool` (defend.py)

Called by `_tick_active_plan` when the active plan is a DefendPlan.

```
if no incursion threats active → return True (threat resolved)
new_most_severe = pick_most_severe(view)
if new_most_severe != plan.target_player → return True (target changed, re-plan)
return False (keep going)
```

When cleared due to target change, `_pick_new_plan` runs immediately — defend is the first gate in the ladder, so it fires again targeting the new most-severe player.

### Tick loop integration

`_tick_active_plan`: adds `isinstance(plan, DefendPlan)` branch that calls `should_clear_defend`.

`_pick_new_plan`: adds `try_defend(view)` as the first gate in the ladder, above expand/explore.

### Constants

`INTERCEPT_LOOKAHEAD = 3` — steps ahead of invader to place intercept point.

## 4. Upgrade explore to use gather_path

Explore switches from single-step moves (SingleMove) to multi-tick plans (ExplorePlan) via gather_path.

### Target selection (replaces old `_pick_explore_move`)

```
1. sector scoring — same as before (passable non-owned tiles per quadrant)
2. frontier tiles in winning sector — _unoccupied_frontier filtered to best quadrant
3. multi-source BFS from those frontier tiles (bfs_distances_multi)
4. target = random non-owned tile at EXPLORE_FOG_DEPTH from frontier
   if none at that depth, random among deepest available (≤ EXPLORE_FOG_DEPTH)
5. gather_path(view, target, EXPLORE_MAX_PLAN_TICKS, EXPLORE_MIN_ARMY, "explore")
6. wrap in ExplorePlan, or fall back to expand
```

### BFS addition

`bfs_distances_multi(sources, passable, H, W)` — seeds the BFS queue with all sources at distance 0. Same loop as single-source, trivial variant.

### Return type change

`pick_expand_or_explore` returns `SingleMove | ExplorePlan | None` (was `SingleMove | None`). Expand stays SingleMove. Bot's plan lifecycle handles both — SingleMove emits directly, ExplorePlan stored as active plan.

### Constants

```
EXPLORE_FOG_DEPTH = 3
EXPLORE_MAX_PLAN_TICKS = 15
EXPLORE_MIN_ARMY = 5
```

## 5. gather_path implementation

### Call sites

**Defend** — `gather_path(view, intercept_point, max_moves=invader_eta, min_army=None, gate="defend")`. Respond to an incoming threat with whatever army we can muster. Tight move budget derived from invader distance. Best-effort (no min_army). Bypasses reserve.

**Explore** — `gather_path(view, fog_tile, max_moves=EXPLORE_MAX_PLAN_TICKS, min_army=EXPLORE_MIN_ARMY, gate="explore")`. Push into unexplored territory. Moderate budget, low min_army floor as a sanity check. Respects reserve.

**Kill-shot** (future) — `gather_path(view, enemy_general, max_moves=None, min_army=None, gate="killshot")`. All-in on capturing a revealed general. No move cap, no min_army — feasibility checked by margin after. Respects reserve (except same-player as attacker, §6b.2).

**Attack** (future) — `gather_path(view, enemy_frontier, max_moves=ATTACK_MAX_PLAN_TICKS, min_army=commit_amount, gate="attack")`. Project force into enemy territory. Bounded budget, min_army = fraction of mobile army. Respects reserve.

### Signature

```
gather_path(view, target, max_moves, min_army, gate) -> GatherResult | None

GatherResult: moves (list of (src, dst, is50)), arriving_army (int)
```

Caller wraps the result in the appropriate Plan variant (DefendPlan, ExplorePlan, etc.).

### Implementation steps

```
1. Reserve calculation
   reserve_amount = int(RESERVE_FRACTION * view.army[my_slot])
   bypass_reserve = (gate == "defend")

2. Source selection
   dist_from_target = bfs_distances(target, passable, H, W)

   for each owned tile with army >= 2:
       if max_moves is not None and dist_from_target[tile] > max_moves → skip
       eff = effective_army(tile)
       score = eff - SOURCE_DIST_WEIGHT * dist_from_target[tile]
   source = argmax score

   effective_army:
     non-general: army - 1
     general + bypass reserve: army - 1
     general + ceil(army/2) >= reserve_amount: floor(army/2) (split)
     general + otherwise: 0 (unavailable)

3. BFS path
   path = bfs_path(source, target, passable, H, W)
   if empty or source == target → return None

4. Side-gathers
   sweep_cost = len(path) - 1
   remaining = max_moves - sweep_cost  (unlimited when max_moves is None)
   candidates = _find_side_gather_candidates(path, ...)
   max_side = min(remaining, floor(SIDE_GATHER_FRACTION * len(path)))
   side_gathers = candidates[:max_side]

5. Army estimate
   movers = path[:-1] + side_gather_sources (general excluded if split)
   arriving = mobile_army(movers, ...) + general_split_contribution
   if min_army is not None and arriving < min_army → return None

6. Build moves
   moves = _build_move_sequence(path, side_gathers, gen_flat, use_split)
   return GatherResult(moves, arriving)
```

### Helpers (gather.py)

**`mobile_army(tiles, arm_flat, own_flat, my_slot) -> int`** — sum of `army - 1` for each owned tile. Warns if any tile is not owned. Reusable for kill-shot margins, attack commit estimates.

**`_find_side_gather_candidates(path, own, arm, my_slot, H, W)`** — owned tiles with army >= 2, cardinal-adjacent to a path tile, not on the path. Returns list of `(tile, army, path_index)` sorted by army descending.

**`_build_move_sequence(path, side_gathers, gen_flat, use_split)`** — side-gathers ordered by injection point (ascending path index), then sweep steps. Sets `is50=1` on general's sweep step when `use_split` is true.

### Constants

```
RESERVE_FRACTION = 0.25
RISK_FRACTION = 0.5
SOURCE_DIST_WEIGHT = 1.0
SIDE_GATHER_FRACTION = 0.5
```

### Notes

Source selection doesn't account for side-gather opportunity — a close source with many nearby stacks might deliver more than a distant fat source, but the scoring doesn't model this. Acceptable for v1; the greedy fill after source selection works well enough at map scale.

## 6. Spent detection

Checked each tick in `_tick_active_plan` before re-evaluation or emitting.

### `_is_spent(view, plan) -> bool`

```
if plan exhausted (cursor >= len(moves)) → spent
if source tile not owned by us → spent (captured mid-plan)
if source army <= 1 → spent (can't move)

sent = army // 2 if is50 else army - 1
if destination is enemy-owned and dst_army >= sent → spent (blocked, defender wins ties)
```

### M3 extension point

Kill-shot adds a plan-type-specific check: `attacking_army < target_general_army`. Requires isinstance dispatch on KillshotPlan with access to the target general's current army.
