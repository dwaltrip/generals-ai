# PR 2 sketch — centralize checkpoint loading

**Date:** 2026.05.28
**Design contract:** [`5.28-2-train-refactor-and-resume-design.md`](./5.28-2-train-refactor-and-resume-design.md) (§Checkpoint format → `load_bc_model` helper, §Sub-PR breakdown #2)

One inference-side checkpoint loader instead of two parallel ad-hoc ones. Pure consolidation — behavior-identical, no checkpoint format change.

## End state

```
training/bc/
  checkpoint.py   — load_bc_model (new file)
```

`self_play.agent.load_checkpoint` is **deleted**; `value_head_probe.load_frozen_trunk` delegates to the helper then extracts the trunk. All inference/probe paths load through `bc.checkpoint.load_bc_model`.

## The helper

```python
# training/bc/checkpoint.py
def load_bc_model(path, device, value_head_variant="direct") -> BCModel:
    model = BCModel(value_head_variant=value_head_variant)
    state_dict = torch.load(path, map_location=device, weights_only=True)
    model.load_state_dict(state_dict)   # strict — catches arch/variant drift
    model.to(device)
    model.eval()
    return model
```

- Byte-for-byte the body of the current `self_play.agent.load_checkpoint`. Signature matches, so call-site migration is find-and-replace.
- **Only the current (legacy bare-state_dict) format** this PR — no format-detection branch. The combined-format branch lands in PR 3 when the combined format gets a producer (save path) and consumer (resume). No consumer exists yet → don't add the branch yet.
- Module docstring describes the abstraction (checkpoint I/O for BC models), not today's single function — `latest_checkpoint` + combined-format handling arrive in later PRs.

`load_frozen_trunk` (`value_head_probe.py`): body becomes `model = load_bc_model(ckpt_path, device, value_head_variant)` then `trunk = model.trunk; freeze; trunk.eval()`. Returned trunk is identical (`load_bc_model` already `.eval()`s the whole model; the per-trunk freeze is what matters).
