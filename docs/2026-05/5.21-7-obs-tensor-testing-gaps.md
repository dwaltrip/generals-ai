# Obs tensor testing gaps

**Date:** 2026-05-21
**Scope:** `training/bc/obs.py` (`MemoryState`, `init_memory`, `step_memory`, `build_obs`, `compute_known_passable`) and the fog-parity fixture at `training/tests/test_fog_parity.py`.

A review of `test_fog_parity.py` found no bugs in the fixture or assertions — every asserted value matches what `init_memory` + `step_memory` actually compute given the fixture data, including the documented stale-`known_general` behavior at t=7. But the fixture is narrow: it walks one 2-player 5x6 game with perspective=slot-0 and asserts a handful of state transitions. A lot of `obs.py` is not exercised. This note enumerates the gaps so future test work can prioritize.

## What the fog-parity fixture already covers

- Cumulative vision growth (`historically_seen`).
- First-sight resolution of mountain / neutral-city / opp-general structures.
- `opp_has_seen` activation + Moore-dilation on first opp tile sighting.
- Capture-event timing: event at action-t processed during `step_memory(t)`, ownership effects in snapshot[t+1].
- Capture-with-vision: `new_city` fires at t=7, `known_general` stays stale (matches obs.py:316-327 TODO).
- Never-seen sentinels: `last_seen_owner=-2`, `last_seen_armies=-1`, `turns_since_seen=-1`.

The fixture's docstring (test_fog_parity.py:32-38) already calls out two limitations: no visible→fogged transition, and perspective=slot-0 only. Everything below is on top of those.

## Gaps

### Memory dynamics

- **TSS=0 (visible-reset) and TSS>0 (fogged-increment) paths.** Only the TSS=-1 sentinel is asserted (test_fog_parity.py:213, 378). The `state.turns_since_seen[vis] = 0` write at obs.py:335 and the `+= 1` increment at obs.py:337 have no direct check.
- **`last_seen_armies` values.** Only the -1 sentinel is asserted. Specific army-write values from obs.py:331 (fixture writes 10 for self, 1 for opp) are never read back.
- **Persistence after vision loss.** No cell is owned-then-un-owned in the fixture, so `last_seen_owner` / `last_seen_armies` aren't tested for "remembered after fog returns."

### Capture-event variants

- **Cross-opp capture (captor != perspective).** The canonical-channel translation at obs.py:633-644 (map raw captor slot → canonical channel index 1..7) is dead code at P=2.
- **Multiple capture events at the same tick.** The `events_now` loop (obs.py:357-361) is only exercised with a single event.

### Canonicalization (multi-opponent)

- **Non-zero perspective slot.** `canonical_slot_order` (obs.py:84-98) with perspective=0 is identity; off-by-one or slot-mapping bugs would not surface.
- **`opp_has_seen[p]` for p > 1.** The fixture is P=2; rows for other slots aren't checked for being all-False.
- **Per-opp channel ordering in `build_obs`.** The per-opp contract (obs.py:16-26) — channel `i ∈ 1..7` corresponds to `opp_slots[i-1]` — is untested.

### Code paths outside `step_memory`

- **`compute_known_passable` (obs.py:376-424).** Entire BFS passability policy untested: own/enemy general handling, own-city always-passable, neutral/enemy city army-ratio gate, `effective_owner` / `effective_army` fog fallback.
- **`build_obs` end-to-end.** Fog-parity stops at `MemoryState`. No obs tensor is built, so channel ordering, padding (H_PADDED × W_PADDED), log-scaling, and sentinel-to-channel encodings (e.g., `last_seen_armies_ch` post-log -1 sentinel) are not exercised. The dataloader smoke test catches shape/NaN; it doesn't catch semantic bugs in channel content.
- **`_cat_dense_history` (obs.py).** The two encoder helpers `_encode_ownership_transition` and `_encode_army_delta` have direct unit tests in `test_obs.py`. What's still untested: the buffer-indexing / `t_newer` derivation inside `_cat_dense_history`, and end-to-end channel content from `build_obs` — both of which would fall out of a build_obs smoke test on the existing fixture.
- **Scoreboard.** `land_count_history` / `army_count_history` are computed in `init_memory` (obs.py:218-223) but never asserted; same for `_cat_self_broadcast` and `_cat_opp_broadcast` outputs.

### Minor

- **t=6 lacks negative checks.** test_t6 only asserts the 4 quantities that change at the capture tick. Unintended mutations to `historically_seen`, `opp_has_seen`, etc. at t=6 wouldn't be caught.
- **Ownership-transition path for cities.** Both initial cities in the fixture stay neutral for the whole walk; no "neutral city → captured city" transition.

## Suggested next fixtures

Rough priority by what most reduces risk in current code paths:

1. **`build_obs` smoke + a couple of semantic spot-checks.** Cheapest win — verifies channel ordering, padding, and that the cat-by-cat helpers stitch together correctly. Could reuse the existing `sim` fixture.
2. **A visible→fogged fixture.** Small board where perspective gains then loses a tile; assert TSS=0 → TSS=1,2,... and `last_seen_*` persistence.
3. **A non-zero-perspective fixture.** Same game data, perspective=slot-1 (or higher in a P≥3 game), assert canonical channel layout in `build_obs`.
5. **`compute_known_passable` unit tests.** Direct inputs to the function — doesn't need a full game walk.
