## Operational notes worth knowing

- **`IterableDataset` requires `set_epoch(epoch)` before each iteration.** Wired into `train_one_epoch`; any new training-loop variant must call it. Without it, every iteration reproduces the epoch-0 shuffle.
- **`dataloader_kwargs` lives in `shared/device.py`.** Both train and val unpack it; a tweak to either resolution rule (`pin_memory` auto-detect, `prefetch_factor` conditional inclusion) lands in one place.
- **`move_batch` uses `non_blocking=True` unconditionally.** Safe for current call sites — the model forward consumes on the same CUDA stream, which CUDA orders correctly. A future call site doing `.cpu()` / `.numpy()` / `.item()` on a moved tensor will race against the in-flight copy; needs `torch.cuda.synchronize()` first.
- **Sharding tests call `_iter_groups` directly — no real DataLoader workers.** macOS Py3.14 `fork()` deprecation warning + slow subprocess spawn don't pay back for testing logic we control. Integration coverage is `test_dataloader_smoke` (real DataLoader, `num_workers=0`).
- **`pin_memory` provenance is split.** `args.json` records the operator's input (which may be `None` for "auto"); the resolved bool used by the DataLoader is in `console.log` at run start. Re-running the same config on a different device intentionally re-resolves.
