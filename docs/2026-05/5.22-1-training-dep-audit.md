# `training/` dependency audit — Modal cloud-GPU image scoping

Snapshot date: 2026-05-22. Branch: `cloud-train-poc`. Tip: `2e6b2df`.

## TL;DR

The prior claim "`training` imports only from `bc.*`, `utils.*`, and `torch.*`" is **outdated**. Current imports also include `shared.*` (a sibling pkg inside `training/`), `numpy`, `matplotlib` (one plotting script + the value-head-probe analysis), and — under tests/investigations — `pytest`. There is one undeclared workspace cross-dep: `bc/splits.py` imports `utils.*`, but `training/pyproject.toml` doesn't list `utils` as a dependency. And `utils` itself transitively pulls `replay-collector` (which drags `curl-cffi`, `httpx`, `lzstring`, `python-dotenv`) — heavyweight and avoidable for a training-only image.

For a minimal Modal image that runs `scripts/train_bc.py`: install `torch` + `numpy` + workspace members `training` and `utils` (+ `replay-collector` transitively, unless we surgically break that). **No matplotlib needed at runtime** — it's only used by `plot_run.py` and `value_head_probe.py`, neither of which is on the train_bc.py code path.

## 2. Runtime-minimal set for `scripts/train_bc.py`

### External Python deps

- `torch` (with CUDA for Modal H100)
- `numpy`

That's it. No matplotlib, no pytest.

### Workspace cross-deps that must be installed

- `training` itself (provides `bc` + `shared`)
- `utils` — required because `bc/splits.py` imports `utils.{json_io, player_name_lists}` at module load
- `replay-collector` — transitively required because `utils/player_name_lists.py` imports `replay_collector.usernames` at module load. **Functionally unused** by `train_bc.py` (never calls `load_union`/`load_curated_names`/`filter_valid`), but the import resolves at startup, so the package must be installable. Its own deps (`curl-cffi`, `httpx`, `lzstring`, `python-dotenv`) will land in the image. ~unfortunate.

### Subdirectories of `training/` that need to be present

- `bc/` — yes (all of it; `train_bc.py` reaches `dataset`, `eval`, `loss`, `model`, `splits`; transitively `actions`, `bfs`, `constants`, `filters`, `mask`, `obs`, `utils`, `visibility`)
- `shared/` — yes (`device.py` and `log.py` both imported from `train_bc.py`)
- `scripts/` — only `train_bc.py` itself needs to be present (no cross-script imports)
- `tests/`, `investigations/` — no
- `curated-player-lists.txt` at the **repo root** — touched lazily; `bc/splits.py` only resolves it if `build_manifest` is called. `train_bc.py` calls `load_manifest`, not `build_manifest`, so the file isn't read at training time. But it *is* referenced by a module-level `Path(...)` (`splits.py:60`), which is just a path object, not I/O — safe to omit.

## 3. Surprises and concerns

### Undeclared workspace cross-deps (bug-ish)

`training/pyproject.toml` doesn't list any workspace siblings under `dependencies`, but `bc/splits.py` imports `utils.*` unconditionally at module load. Today this works only because the **root workspace** install pulls `utils` in alongside `training` (root `pyproject.toml` lists both). A Modal image that does `pip install training` without also pulling `utils` would `ImportError`. See section 4 for the fix.

### `replay-collector` transitive bloat

The `utils` → `replay-collector` edge (see `utils/utils/player_name_lists.py:25` and its TODO at line 17) drags `curl-cffi`, `httpx`, `lzstring`, `python-dotenv` into the training image even though the training entry point never executes the code path that needs them. That TODO already exists in-repo (deliberate compromise pending a `usernames.py` move into `utils`). Worth flagging again now that we're sizing a cloud image.

### `__file__`/`os.getcwd` use in `train_bc.py` and friends

`train_bc.py:45-47`:

```python
REPO_ROOT = Path(__file__).resolve().parent.parent.parent
DEFAULT_INTERMEDIATE = REPO_ROOT / "replay-parser" / "data" / "intermediate"
DEFAULT_RUNS_DIR = REPO_ROOT / "training" / "data" / "runs"
```

These are only used as `argparse` *defaults*. Modal runs will override both via CLI flags (mount-paths for intermediate data, volume-paths for run outputs), so the bad defaults are harmless. No `os.getcwd` use anywhere.

Other `__file__` sites:
- `bc/splits.py:59,79,279` — same pattern (CLI defaults + git-sha cwd). The `cwd=Path(__file__).resolve().parent` in `_git_sha` will resolve to something inside the installed wheel inside the Modal container; `git rev-parse` will fail there, which is fine — the function catches `CalledProcessError`/`FileNotFoundError` and returns `"unknown"`. Acceptable.
- `scripts/value_head_probe.py:59-61` — same `REPO_ROOT` pattern; not on the `train_bc.py` path.

No surprises. The container will work as long as `--manifest`, `--intermediate`, and `--out-dir` are passed explicitly (which we'll do via the Modal entrypoint).

### Other

- `bc/splits.py:74-85` shells out to `git rev-parse` for run provenance — gracefully degrades if git isn't installed in the image. No action needed unless we want a real SHA in cloud-run records, in which case bake the SHA in as an env var at image build time.
- `shared/device.py` is the right abstraction for cloud — it picks `cuda`/`mps`/`cpu` from a `--device` arg, and the existing `pick_device("auto")` already prefers CUDA when available.
- `matplotlib.use("Agg")` is set in both plotting scripts before `pyplot` import — already headless-clean if we ever do want to run them in cloud.

## 4. Recommended changes to `training/pyproject.toml`

Add `utils` as a workspace dep. The honest declaration is:

```toml
[project]
name = "training"
version = "0.1.0"
requires-python = ">=3.14"
dependencies = [
    "numpy>=2.0",
    "torch>=2.12",
    "utils",
    # matplotlib is only used by post-hoc analysis scripts (plot_run.py,
    # value_head_probe.py) — not by the train_bc.py runtime path. Keep it
    # here for local-dev convenience, or move to an optional extra if we
    # want lean cloud images.
    "matplotlib>=3.10.9",
]
```

And the root `[tool.uv.sources]` already wires `utils = { workspace = true }`, so the workspace install picks it up automatically.

Two follow-on choices worth a short discussion:

1. **Matplotlib placement.** Either leave it as a hard `training` dep (current state — fine, ~30 MB) or move it to an optional extra (`[project.optional-dependencies] analysis = ["matplotlib>=3.10.9"]`) and install with `training[analysis]` locally. For a *training-only* Modal image, leaving it out gets us a faster cold-start.
2. **The `utils` → `replay-collector` edge.** Pre-existing TODO in `utils/player_name_lists.py`. If we want a small Modal image, address that TODO now: move `filter_valid` into `utils` (it's pure-stdlib — `unicodedata` + `logging`), drop `replay-collector` from `utils`'s deps, and the cloud image gets rid of curl-cffi/httpx/lzstring/python-dotenv.

### Minimal Modal image (assuming the two changes above are NOT done)

```
pip install: torch, numpy
uv workspace install: training, utils, replay-collector
transitive: curl-cffi, httpx, lzstring, python-dotenv (from replay-collector)
```

### Minimal Modal image (assuming `filter_valid` moves into `utils`, and matplotlib goes to an optional extra)

```
pip install: torch, numpy
uv workspace install: training, utils
transitive: (none significant)
```
