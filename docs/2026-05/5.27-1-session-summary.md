## Session Summary

### Goal

Adapt the self-play package into generic game-running infrastructure for evaluating model checkpoints — against each other, against the hand-coded EvalBot, or in any N-player combination.

### What we built

**`packages/game-runner/` — new package** (4 commits)
- `Policy` protocol + `GameResult`/`PlayerStats` dataclasses
- `run_game()` — generic N-player game loop with `on_tick` callback
- `write_eval_game()` — save games as compressed `.npz` (modeled on replay-parser's `write_sim_output`)
- `render_viewer_html()` — lower-level viewer entry point for duck-typed state/static
- `git mv`'d `driver.py`, `sim_adapter.py`, `seed_map.py`, `viewer.py` from self-play (clean renames in git history)

**`packages/eval-bot/eval_bot/eval_bot_agent.py`**
- `EvalBotAgent` — wraps `WorldModel` + `EvalBot` to satisfy `Policy` protocol

**`scripts/eval_run.py` — full eval runner**
- `--policy` CLI with flexible spec format: `checkpoint:path:force_move,sample,temperature=0.5` or `evalbot`
- `--maps random:N` / `--maps replay_id:...` with `--map-seed` for reproducibility
- `--swap-slots` doubles games with reversed slot assignments (2-player)
- Output: `data/eval-runs/<timestamp>/` with `config.json`, `results.jsonl`, and per-game `.npz` + `.meta.json` + `.metrics.json`

**`scripts/eval/` — eval tooling modules**
- `policy_spec.py` — parse/validate policy CLI specs, `build_policy_names`
- `metrics_collector.py` — `on_tick` callback collecting land/army curves + move analysis
- `move_analyzer.py` — action stream stats (1s-traversals, attack chains, attack army sizing)
- `view_game.py` — render saved `.npz` → timestep-viewer HTML (no sim_core needed)

**Self-play slimmed down**
- `driver.py` is now a thin wrapper that builds two ModelAgents and calls `run_game`

### Design decisions made
- `game-runner` as its own package (clean dep boundary — depends only on `sim_core` + `numpy`)
- `Policy` protocol stays minimal (just `init_for_game` + `act`); diagnostics are duck-typed via `get_diagnostics`
- MetricsCollector/MoveAnalyzer live in eval tooling, not in game-runner — the runner is agnostic via `on_tick` callback
- Saved games use `.npz` with full snapshots (no sim_core replay needed for viewing)
- Policy names ("bc-model", "evalbot") numbered only when duplicates exist
