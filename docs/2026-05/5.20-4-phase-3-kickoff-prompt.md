# Working style

- Agile; brief discussion on key design points before code; commit
  and move forward.
- **Light-touch documentation.** Default to inline TODO/comments in
  code; brief session note at the end only if something was
  non-obvious. **Don't proactively create a Phase 3 status doc** —
  the user will decide later in the session whether one is warranted.
  Heavier write-up energy is better saved for when there's actual
  loss-curve signal to interpret (Phase 4 territory).
- Prefer inline TODOs over over-engineering up front.
- If something tricky surfaces, stub it and ask.
- Verify `pytest tests/` is green at the start and at major commits.
- **Investigation depth on carry-forward items:** stay at general
  orientation by default; dive deep only when commitment to a path is
  made. Several items (fog parity, pass-head retuning) may defer
  entirely — pre-investing context on them is waste. Shuffle-buffer
  is the exception (see required reading).
