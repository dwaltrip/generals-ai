# Eval Bot Session Notes — Milestone 3 Implementation

**Date:** 2026.05.26

**Branch:** `eval-bot-m3`

**Outcome:** Kill-shot and Attack gates implemented end-to-end, including scoring machinery, decision flow wiring, and review fixes. TBD tuning constants use a sentinel value (`BOT_CFG_PLEASE_CHANGE_ME = 999`) — grep to find all values needing real tuning.

## What was built

**BotConfig refactor.** Centralized all tunable constants from module-level globals into a single `BotConfig` dataclass (`bot_config.py`). Threaded as `cfg` through EvalBot → WorldModel and EvalBot → gate functions. Enables running multiple bots with different configs in the same process for A/B comparison.

**Kill-shot gate** (`killshot.py`). Iterates revealed enemy generals (`mem.general_locations`), builds a gather_path candidate with no time cap, checks margin-based feasibility (`arriving_army >= last_seen_armies + margin`, margin scales with travel time). Same-player killshots (target is the player attacking us) bypass the reserve — the capture resolves the threat via inheritance.

**Attack gate** (`attack.py`). Scoring functions: `relative_strength` (army/land ratios vs field average), `conflict_flag` (mirrored land deltas over a rolling window), `_target_score` (composite: weakness + proximity + growth urgency - conflict, hard gate against stronger players). `try_attack` picks the best target via TargetScore, gathers toward their nearest visible tile (or revealed general if known), with a commit budget of `RISK_FRACTION * (total_army - reserve_amount)`. `should_clear_attack` implements hysteresis — only switches targets when the new best outscores current by `ATTACK_SWITCH_THRESHOLD`.

**Decision flow wiring** (`bot.py`). Defend/killshot race condition: both gates are called, killshot wins when targeting the same player and our gather arrives before the invader. Killshot exempt from preemption. Attack re-evaluation via `should_clear_attack`.

**World model additions.** `has_recent_attack` computed per contact player (any of our tiles flipped to them since their threat window opened). Surfaced on PlayerView but not yet consumed — it's a ThreatScore input for future de-escalation.

## Decisions and deviations

**Decision ladder reordered: attack above expand/explore.** The spec puts expand/explore above attack, but `UnoccupiedFrontier > 0` is true nearly the entire game, so expand/explore would almost always fire first and attack would rarely trigger. Flipped so the bot presses weaker contacts instead of passively expanding.

**`gate: str` replaced with `bypass_reserve: bool`.** The `gate` string param on `gather_path` was only used for `gate == "defend"` to bypass reserve. Replaced with an explicit bool — clearer, and killshot's conditional bypass (same-player only) fits naturally.

**Killshot spent check removed.** The initial implementation compared the per-move `sent` army against the target general's army. This falsely triggered during side-gathers (small tributary tiles, not the accumulated stack). The generic spent checks (army == 1, blocked by garrison) cover real "stuck" cases. Killshot feasibility re-evaluation is a separate concern for a future pass.

**`reserve_amount` extracted as a helper.** Was computed inline in both `gather_path` and `try_attack`. The attack commit budget now uses the spec's formula (`RISK_FRACTION * (total_army - reserve_amount)`) instead of the incorrect `RISK_FRACTION * mobile_army(all_tiles)` from the initial implementation. Big TODO on the helper — the single global fraction is a very crude budgeting model.

## Review fixes

Opus sub-agent review found and we fixed:

- **Killshot spent check bug** — per-tile `sent` vs general army during side-gathers (described above).
- **Dead `reserve_amount` in `try_attack`** — commit budget used wrong formula; fixed to spec.
- **`dist_to_general = -1` poisoning closing deltas** — BFS returning -1 (unreachable) in the threat window created huge negative deltas that falsely triggered the closing condition. Added a guard to skip appending when unreachable.
- **`should_clear_defend` None edge case** — `_pick_most_severe` could theoretically return None; the existing `!= plan.target_player` check handles it correctly. Added a comment for clarity.
