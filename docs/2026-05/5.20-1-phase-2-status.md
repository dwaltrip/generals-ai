## High-priority items (impact training quality)

### 1. Fog memory: oracle in place, but needs independent verification

`test_fog_parity.py` is the correctness oracle for `init_memory` +
`step_memory` on a 5×6 / 2-player fixture. Covers init state, monotonic
accumulators, structure resolution (mountains / cities / generals),
general source pinning, opp contact, and the capture event →
general→city transition (including the documented stale-flag behavior).

**Important caveat: the same agent wrote both the implementation and
the hand-computed expected values within the same session. A passing
test could mean both correctly track the design — or that the same
agent encoded the same bug in both. The test result alone doesn't
distinguish those cases.** The risk is a fog-logic bug encoded
identically in implementation *and* expected state — the test passes
while the training data is still wrong.

**Mitigation (do before serious training):** a fresh-perspective
re-derivation of the expected state at one or more checkpoints, then
compare to the test file. Either the user reading the test cold and
verifying against the design docs + game mechanics, or a fresh agent
prompted to re-derive from first principles (design docs only, no
access to `test_fog_parity.py`). A single independently-re-derived
checkpoint would substantially reduce the risk.

Three coverage gaps also remain — narrower follow-ups, can land any time:

- **Visible → fogged transition not exercised.** Every cell in the
  current fixture either stays visible or never becomes visible, so
  the `turns_since_seen` increment path (0 → 1 → 2 → ...) is not
  tested. A second small fixture (or an extended trajectory where the
  perspective loses ownership of a cell) covers it.
- **Non-zero perspective slot canonical-channel mapping not tested.**
  Fixture uses `perspective=slot-0` only. Bugs in per-opp channel
  ordering for non-zero perspective wouldn't be caught.
- **BFS cache hit/miss + distance correctness untested.** Independent
  of fog memory; small focused test file when convenient.

### 2. Dense-history encoding is degraded

Current implementation emits a binary "cell-changed" mask plus signed-
log army delta. Design (5.05-1 §G) calls for a signed encoding that
distinguishes self-lost / neutral-lost / opp-k-lost transitions, and
production-subtracted army deltas. See TODO in `obs.py` cat 10.

The model will still learn from the degraded form, just less
efficiently — those 10 channels carry a fraction of the intended
tactical-history signal. Worth upgrading before serious training so
the eval results actually reflect the design.

### 3. BFS-policy knobs are at spike defaults

The "knobs" header comment in `bc/bfs.py` documents three decisions
that live in the caller's `known_passable` mask construction
(`obs.py` cat 5):

  - Enemy generals walkable (currently: yes)
  - City traversal cost (currently: uniform = 1)
  - Structures-in-fog impassable (currently: yes)

Wrong defaults here produce behavioral pathologies the model bakes in
(e.g., routing "through" enemy territory in BFS-derived distance
features that don't reflect attack semantics). At least the
"treat opp generals as impassable" knob is worth picking now rather
than discovering post-train.

## Lower-priority items (broad health, less spike-critical)

Each of these is documented in code where it lands:

- **`opp_N_city_inference` zero-stub** (`obs.py` cat 8 TODO) — model
  learns blind on these 7 channels; one missing signal vs catastrophic.
- **Broadcast-scalar normalization divisors** (`obs.py` top constants) —
  hand-picked typical values; wrong scale slows learning but doesn't
  break it.
- **General→city stale flag without vision** (`obs.py::step_memory`
  TODO) — cosmetic; BFS sees both general + city as passable.
- **`opp_N_captured_by` edge-case fallback** — silent default to "alive"
  if captor isn't in `opp_slots`. Defensive; can't trigger at P=8.
- **Broadcast channels' padded region is 0** — a "broadcast" value isn't
  actually constant across padding; action mask zeros that region anyway.
- **`canonical_slot_order(P=8)` hardcoded** — Phase 1 review S2; latent
  until we pick up P=4–7 games (post-spike).
- **BFS is a Python deque loop** — fine at 90%+ cache hit regime; swap
  to vectorized BFS only if profiling shows it bottlenecks.

## What's left for Phase 3

Plan §3 Phase 3 steps 1–7:

- Game-id-level train/val split (`bc/splits.py`); seeded shuffle,
  95/5, saved to `training/data/splits/v1.json`.
- Subset-of-corpus training loop (path (a): ~2–4k games proof-of-concept).
- Board-symmetry augmentation (`bc/augment.py`); direction-channel
  unit test.
- JSONL logging + per-epoch checkpointing at
  `training/data/runs/<timestamp>/`.
- Held-out val eval per epoch (top-1 + top-3 action accuracy,
  action-distribution histogram, pass fraction).

**One thing the overfit run surfaced for Phase 3 dataloader work:**
the current `IterableDataset` walks `(game, perspective, timestep)`
sequentially within each game. The first batches of the overfit run
were 100% pass frames (early-game army-build turns). Phase 3 SGD wants
per-batch frame diversity — shuffle-buffer mixing across game
boundaries is worth lifting up front in Phase 3 work, not after a bad
loss curve forces it.
