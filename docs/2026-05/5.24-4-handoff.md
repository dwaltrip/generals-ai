The next step before implementation is a **pseudo-code grounding pass**: for each heuristic, metric, and gate, write concrete pseudo-code that traces every input back to a field on game_state (or a derived value computed from previous game_state). This surfaces any remaining ambiguities before we commit to code structure.

Work through these items from easy-to-hard:

1. `ExpandableTiles` / `UnoccupiedFrontier` — pure game_state reads
2. `ContactSet` — vision-based set update
3. Scoreboard reads (`RelativeStrength`, `CityCountEst`, `ConflictFlag`)
4. Source selection (`argmax(army - k·dist)`) + reserve floor
5. Sector scoring / explore target selection
6. `ThreatWindow` update + identity tracking
7. `ThreatScore` / `TargetScore`
8. `IncursionThreat` (Closing + Eating)

The bot will live in `packages/eval-bot`, reusing game state from `packages/self-play`. You'll probably need to look at the self-play package to understand what fields are available on the game state object.
