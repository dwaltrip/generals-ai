# Model-config refactor — design sketch

**Date:** 2026-05-31
**Branch:** `quick-model-arch-sweep`
**Status:** Design sketch, pre-implementation. Seeds the width-sweep work — the sweep is blocked on this.

## Why

Trunk width is hard-coded as module constants in `bc/model.py` (`OUTER_WIDTH=128`, …), and the checkpoint records only `{"model", "optim", "scaler", "epoch"}` — **no architecture metadata**. Width is implicit in the constants; `value_head_variant` is implicit in a load-time arg the operator has to remember.

This blocks a width sweep for a non-obvious reason: the eval design that makes our tooling worthwhile is **head-to-head in one process** — the batched runner groups rows by `model_key` and runs each distinct model through one forward. Two checkpoints at different widths must coexist in a single Python process. With width as a global constant, you cannot instantiate a 0.5× and a 2× model at the same time.

The fix is to make architecture **self-describing**: a `ModelConfig` that flows config-file → model → checkpoint → inference, so any checkpoint carries everything needed to reconstruct its model. This is a clean improvement independent of the sweep (it also retires the "remember which value-head variant this checkpoint used" foot-gun).

## Goals / non-goals

**In scope:**
- Trunk arch (widths + block counts) and `value_head_variant` become configurable, not hard-coded.
- Checkpoints self-describe their architecture (new `arch` key); inference reconstructs from it.
- All quality/recipe knobs (arch, `lr`, `weight_decay`, `batch_size`, `epochs`, `seed`, `precision`, `shuffle_buffer_size`) move off CLI flags into a `--config <json>` file; the CLI keeps only invocation-local operational knobs.
- Run dir captures both the raw input config and the fully-resolved config.
- Backward-compatible loading of the checkpoints already on disk.

**Out of scope (deferred):**
- CLI overrides of config-file values (disjoint domains for v1 — see partition below). Includes a `--data-root` mount override that would make one config portable across environments.
- Obs-encoder knobs (`DENSE_HISTORY_N`, channel set, `CITY_TRAVERSABILITY_FACTOR`). Recorded as pinned facts, not made configurable.
- The sweep launcher itself (how N config files get fanned out to Modal).
- **Diligently migrating every call site.** First pass covers the main entry points (`run_bc_local.py`, `run_bc_modal.py`, the shared config plumbing, `checkpoint`/`inference`/`state`/`resume`, and `smoke_train.sh` — the no-op harness). Probe/bench scripts (`flops_probe`, `overfit_one_batch`, `value_head_probe`, `bench_decode_sync`) get a TODO and are accepted temporarily broken. Completed-experiment launchers (`phase_a_sweep.sh`) are archived to `scripts/_archive/` rather than migrated.

## The three buckets

Every run input falls into one of three buckets. The bucket decides *how it's supplied* and *where it's recorded*.

| Bucket | What | Input via | In checkpoint? | In run-dir artifact? |
|---|---|---|---|---|
| **1. Model design** | widths, block counts, `value_head_variant`; `in_ch`/H/W (pinned) | config file | ✅ `arch` key | ✅ |
| **2. Run identity / recipe** | `lr`, `weight_decay`, `batch_size`, `epochs`, `seed`, `precision`, `shuffle_buffer_size`, `gpu`, `manifest`, `intermediate` | config file | ❌ | ✅ |
| **3. Invocation-local** | `run_dir`, resume-from path, `num_workers`, `pin_memory`, `prefetch_factor`, `log_every`, `skip_val`, `max_batches`, `device` | CLI flags | ❌ | ✅ (resolved) |

The dividing line for **file vs CLI** is not "does it affect quality" — it's **"is it part of this run's reproducible identity, or about where/how this particular invocation runs?"**

- `gpu` lands in the file (bucket 2): it doesn't affect the weights, but each sweep cell must declare the card it needs (0.5× on a T4, 2× wants an A100). The Modal launcher reads `config.gpu` locally and applies it via `train_remote.with_options(gpu=...)`, retiring the required `--modal-gpu` flag; the field rides into the remote inertly (recorded provenance) and goes in `_DRIFT_EXCLUDED` (the card may change freely on resume).
- `manifest` / `intermediate` are full-path fields in the config file. A given file is environment-specific (Modal `/data/...` vs a local path) — accepted for v1; splitting out a `--data-root` mount override so one config is portable across environments is deferred (see CLI-override work). They keep their existing field names, so they stay in `_DRIFT_EXCLUDED` (free to change on resume) with no change to the drift sets.
- `max_batches` sits in bucket 3 (CLI) despite affecting the trained result: real runs leave it `None` (no effect on identity); it's set only for smoke/perf runs or occasionally as a quick stand-in for a smaller data slice — invocation-local in practice, grouped with `skip_val`.

**Input vs resolved.** The `--config` file is the operator's *input* (may be partial — set what you want, defaults fill the rest). The run-dir artifact is the *fully-resolved* merge (every field, defaults filled, `auto`s like `precision`/`device` resolved). These are two different objects; today's `args.json` is the resolved one.

**Loading.** `TrainConfig.from_file(path)` merges the file over defaults for buckets 1–2 (`arch` as a nested `ModelConfig`), validating via `__post_init__` (recipe on `TrainConfig`, arch on `ModelConfig`); the CLI supplies bucket 3. Because the domains are **disjoint** (no field in both), the merge is a plain union — no precedence rules to reason about. The resolved `TrainConfig` is what `bc_run` consumes and what's written to the run dir. The flat `--lr` / `--batch-size` / `--value-head` / … training flags are removed — `config_from_args`'s `_TRAINING_FIELDS` surface in `train_cli.py` is replaced by `--config`. This is a substantive rewrite of `train_cli.py` (and `test_train_cli.py`, whose override-mapping assertions go away).

## `ModelConfig`

A frozen dataclass in a new **torch-free** module `bc/model_config.py`.

Why its own module, not `model.py`: `train_config.py` is deliberately torch-free at module load — it imports `VALUE_HEAD_VARIANTS` *inside* `__post_init__` to avoid dragging the torch-heavy `model.py` into its import graph. If `ModelConfig` lived in `model.py`, composing `arch: ModelConfig` on `TrainConfig` would force that heavy import back to module level. A light `model_config.py` (pure dataclass + `constants.py` imports) lets `train_config`, `model`, `checkpoint`, and `inference` all depend on it cheaply. `VALUE_HEAD_VARIANTS` moves here too, which removes the deferred-import hack.

```python
# bc/model_config.py  (torch-free)
from dataclasses import dataclass
from bc.constants import OBS_CHANNELS, H_PADDED, W_PADDED

VALUE_HEAD_VARIANTS = ("direct", "pyramid")

@dataclass(frozen=True)
class ModelConfig:
    # --- swept: the trunk's design ---
    outer_width: int = 128
    middle_width: int = 128
    inner_width: int = 160
    n_outer: int = 2
    m_middle: int = 2
    m_inner: int = 2
    value_head_variant: str = "direct"
    # --- pinned: recorded for self-description, not swept ---
    # in_ch is OBS_CHANNELS (= len(CHANNEL_ORDER)); it's downstream of the obs
    # encoder, not a free knob. Recorded so a future channel-count change fails
    # load with a clear arch-mismatch instead of a cryptic state_dict error.
    in_ch: int = OBS_CHANNELS
    H: int = H_PADDED
    W: int = W_PADDED

    def __post_init__(self) -> None:
        for name, w in (("outer", self.outer_width), ("middle", self.middle_width),
                        ("inner", self.inner_width)):
            if w < 1 or w % 2 != 0:
                raise ValueError(f"{name}_width must be positive and even; got {w}")
        for name, m in (("n_outer", self.n_outer), ("m_middle", self.m_middle),
                        ("m_inner", self.m_inner)):
            if m < 0:
                raise ValueError(f"{name} must be >= 0; got {m}")
        if self.value_head_variant not in VALUE_HEAD_VARIANTS:
            raise ValueError(
                f"value_head_variant must be one of {VALUE_HEAD_VARIANTS}; "
                f"got {self.value_head_variant!r}"
            )
        if self.in_ch < 1 or self.H < 1 or self.W < 1:
            raise ValueError("in_ch/H/W must be positive")
```

Widths are required-even because the bottleneck ResBlock's `C/2` intermediate floors on odd channel counts (silent asymmetry). GroupNorm divisibility is already handled gracefully by `_gn`'s fallback ladder, so no constraint needed there.

`BCModel` takes a `ModelConfig`:

```python
class BCModel(nn.Module):
    def __init__(self, cfg: ModelConfig = ModelConfig()):
        super().__init__()
        self.cfg = cfg
        self.trunk = PyramidModule(
            in_ch=cfg.in_ch,
            n_outer=cfg.n_outer, m_middle=cfg.m_middle, m_inner=cfg.m_inner,
            widths=(cfg.outer_width, cfg.middle_width, cfg.inner_width),
        )
        self.policy_head = PolicyHead(in_ch=cfg.outer_width)
        self.pass_head = PassHead(in_ch=cfg.outer_width)
        self.value_head = ValueHead(
            in_ch=cfg.outer_width, H=cfg.H, W=cfg.W, variant=cfg.value_head_variant,
        )
```

`BCModel()` with no args builds **today's exact model** (the defaults are the current constants), so the no-op fingerprints stay green — see Verification. The loose `OUTER_WIDTH`/… module constants in `model.py` are removed; their values now live as `ModelConfig` field defaults. `self.cfg = cfg` is a plain attribute (not a submodule/buffer/parameter), so it adds no `state_dict` keys — the key-level no-op holds.

## Checkpoint format

The combined dict gains an `arch` key:

```python
torch.save({
    "model": self.model.state_dict(),
    "arch":  asdict(self.model.cfg),   # NEW — plain ints/strs, JSON-trivial
    "optim": self.optim.state_dict(),
    "scaler": self.scaler.state_dict(),
    "epoch": self.epoch,
}, path)
```

`is_combined_checkpoint` is unchanged (the `"model"` key is still the discriminator).

### Source-of-truth rules

| Path | Arch comes from | Recipe comes from |
|---|---|---|
| **Fresh run** | `config.arch` (the `--config` file) | the `--config` file |
| **Resume** | the **checkpoint's** `arch` (you can't reshape weights) | parent config + `--config` overlay |
| **Inference / eval** | the **checkpoint's** `arch` | n/a |
| **Legacy checkpoint** (no `arch` key) | `LEGACY_ARCH` + load-time variant arg | n/a |

On **resume**, recipe changes (e.g. bumping `epochs`) come from a `--config <overlay.json>` applied *over the parent's resolved config* — note the asymmetry: a fresh run's `--config` merges over *defaults*, resume's merges over the *parent*. This replaces the retired flat-flag overlay (`training_overrides`). If the overlay's `arch` disagrees with the checkpoint's, **fail loud** rather than silently override — a silent arch mismatch would waste a multi-hour run. Recipe knobs *may* change on resume; arch may not.

**Drift-check integration (load-bearing).** Resume routes through `check_drift` (`run_dir.py:163`), which buckets `asdict(config)` fields: `_DRIFT_EXCLUDED` (free to change), `_CHECKPOINT_OWNED` (locked — not even `--force-config-mismatch` overrides), everything else (trajectory — abortable but force-overridable). Since `asdict` recurses, `arch` lands as a nested dict in the *trajectory* bucket by default → force-overridable → exactly the silent mismatch this design prevents. **Fix: add `arch` to `_CHECKPOINT_OWNED`** (it's pinned by the restored weights, same as `lr`/`weight_decay` are pinned by optimizer state). This is the real resume gate; the `from_checkpoint` assert above is a redundant second guard. (`manifest`/`intermediate` keep their names and stay in `_DRIFT_EXCLUDED`; `gpu` joins it.) **Legacy-parent edge:** a pre-`arch` parent config has no `arch` key, so a naive compare (`None` vs the default arch dict) would route to the locked bucket and spuriously abort an unchanged resume — skip arch-drift when the parent lacks `arch` (and **log a warning**); the bare state_dict reconstructs via `LEGACY_ARCH` regardless.

`load_state_dict(strict=True)` remains the backstop: any arch↔weights drift that slips past the `arch` reconstruction still raises on mismatched keys.

### `LEGACY_ARCH` — frozen, not aliased

```python
# Describes every checkpoint written before the `arch` key existed. DO NOT EDIT
# — these are historical facts about on-disk checkpoints, NOT live defaults.
# Kept separate from ModelConfig's field defaults on purpose: the day we change
# the default width, aliasing legacy = ModelConfig() would silently mis-load
# every old checkpoint. They're equal today and allowed to diverge.
LEGACY_ARCH = ModelConfig(
    outer_width=128, middle_width=128, inner_width=160,
    n_outer=2, m_middle=2, m_inner=2,
    in_ch=96, H=32, W=32,   # literals, not OBS_CHANNELS/H_PADDED references
)
```

**The value-head variant wrinkle.** Legacy checkpoints don't record their variant anywhere in the checkpoint (it lived in the run dir's `args.json`), and the ones on disk are a mix of `direct` and `pyramid` (e.g. the 5.28-1 pyramid+bs512 run). So `LEGACY_ARCH` can't pin the variant — for a legacy load the variant still comes from the load-time arg:

```python
def _arch_for_load(obj, value_head_variant: str) -> ModelConfig:
    if is_combined_checkpoint(obj) and "arch" in obj:
        return ModelConfig(**obj["arch"])              # authoritative
    return replace(LEGACY_ARCH, value_head_variant=value_head_variant)  # legacy fallback
```

Clean rule: **`arch` present → authoritative (load-time variant arg ignored); absent → `LEGACY_ARCH` widths + load-time variant arg.**

## Code sites touched

The model is constructed in two training paths (`fresh` / `from_checkpoint`), plus separate inference/probe constructions. The substantive surface is the config-plumbing and load sites, not the probes:

- `bc/train_config.py` — `TrainConfig` gains `arch: ModelConfig` (`default_factory`), drops the standalone `value_head_variant` field, gains `gpu`; module-level import of `VALUE_HEAD_VARIANTS`/`ModelConfig` replaces the `__post_init__` deferred import. Add `TrainConfig.from_file`.
- `bc/train_cli.py` — **the substantive change**: the flat `_TRAINING_FIELDS` CLI surface (`--lr`, `--batch-size`, `--value-head`, …) is removed in favor of `--config`; the CLI keeps only bucket-3 operational flags. Retiring `--value-head` also means updating the tests that assert it.
- `bc/state.py` — `TrainingState.fresh` builds `BCModel(config.arch)`; `from_checkpoint` reconstructs arch from the checkpoint (see rules above), asserting against `config.arch` if provided.
- `bc/checkpoint.py` — `load_bc_model` gains the `_arch_for_load` logic; `TrainingState.save` writes the `arch` key.
- `bc/run_dir.py` — `arch` added to `_CHECKPOINT_OWNED`; skip arch-drift (with a warning) when the parent lacks `arch` (see drift-check integration above).
- `bc/resume.py` — `_resume_config` / `bc_resume` overlay a `--config` file over the parent's resolved config, replacing the retired `training_overrides` flat-flag overlay.
- `bc/inference.py` — `BCModelHandle.load` **keeps** `value_head_variant` as an optional legacy-fallback arg (used only when the checkpoint has no `arch`; ignored otherwise). `model_key` drops the variant component for arch-bearing checkpoints; retained on the legacy branch, since the same path could be loaded under different fallback variants and the cache must not collide.
- `scripts/run_bc_modal.py` — reads `config.gpu` for `with_options(gpu=...)`; retires the required `--modal-gpu` flag (the `train_remote` `modal_gpu` param and `_write_args_cloud` signature change to source it from `config.gpu`, so `args_cloud`'s GPU provenance has a single origin).
- `eval-tools/policy_spec.py` — the `value_head_variant` checkpoint opt becomes a legacy-only override (read from `arch` otherwise); `_handle_cache` key follows the `model_key` treatment.
- `smoke_train.sh` — ships a committed sibling `smoke-config.json` (epochs etc.) passed via `--config`, plus bucket-3 operational flags (`--max-batches 5 --skip-val --num-workers 0`). It's the no-op harness, so the committed config makes the fingerprint's inputs an auditable artifact.
- Probe/bench scripts (`flops_probe`, `overfit_one_batch`, `value_head_probe`, `bench_decode_sync`) — each is a one-line `BCModel(value_head_variant=…)` or a load call. **First pass: TODO + accept temporarily broken** (`value_head_probe` builds its own heads, so it barely couples). Migrate when next touched.

## Footgun mitigations (the cheap guarantees)

- **`in_ch` pinned + strict load** → obs-channel drift fails with a clear arch-mismatch, not a cryptic shape error.
- **`LEGACY_ARCH` frozen-not-aliased** → changing default width can't silently mis-load old checkpoints.
- **Resume arch guard** → resuming into a different width fails loud before burning compute.
- **Widths required-even** → no silent channel-count asymmetry from the `C/2` bottleneck.

## Verification

The refactor is a behavioral **no-op**, and we assert it rather than argue it. The two existing fingerprints already cover the two distinct paths — knowing *which* is the point:

- **`smoke_train.sh` → default-fresh path.** It runs a fresh `run_bc_local.py` at the default `direct` head, so its loss fingerprint pins `BCModel(ModelConfig())` == today's `BCModel()`. Its inputs move to a committed sibling `smoke-config.json` (above); because that config is partial-over-defaults (`batch_size`/`seed`/`lr` inherited), the fingerprint stays auditable against it and the fresh-default model is unchanged.
- **`parity_fingerprint` → legacy-load + pyramid path.** `test_parity.py` loads an on-disk bare-`state_dict` (legacy, no `arch`) checkpoint with `value_head_variant=pyramid`, so it pins the `replace(LEGACY_ARCH, value_head_variant="pyramid")` reconstruction. A fat-fingered `LEGACY_ARCH` literal turns this red.
- **Round-trip test** (new, one): build `BCModel(ModelConfig(outer_width=192, …))` → save → load → assert reconstructed `arch` matches and `state_dict` loads strict. Add a **default-arch** case (`state_dict().keys()` equality for `BCModel()` vs `BCModel(ModelConfig())`) as explicit belt-and-suspenders for the no-op.

Per our focused-testing norm that's sufficient — `smoke_train` covers default-fresh, `parity_fingerprint` covers legacy-load, the round-trip test covers a non-default arch + the explicit default-key assertion.

## `constants.py` TODO

Add a TODO flagging the long-term question: which `constants.py` values should eventually move into config, and which are genuine invariants. The non-obvious part — some constants are *quality-affecting obs-encoder hyperparameters* we're consciously deferring, not true invariants:

- **Candidates to surface into config later:** `DENSE_HISTORY_N` (history window) and `CITY_TRAVERSABILITY_FACTOR` (BFS passability) — both change the model's input, hence its quality, and both already carry "tune post-spike" comments.
- **Genuine invariants (stay fixed):** `H_PADDED`/`W_PADDED`, `ELIGIBLE_PLAYER_COUNT`, `MAX_BOARD_SIDE` — sim/data structure, not knobs.

Surfacing the obs-encoder knobs is its own effort (it changes the input tensor, not just the model) and waits for the obs-encoder pass.

## Open / deferred

- **Run-dir artifact naming.** Two files: the verbatim `--config` input and the fully-resolved config. Likely `config.input.json` + `config.resolved.json`, retiring the `args.json` name (predates having a real config object). More than pure bikeshed — the resume-chain walker (`run_dir.py:142,153`) and `run_bc_modal.py`'s `args_cloud` sibling read these filenames, so the rename touches resume provenance.
- **`ModelConfig(**arch_dict)` forward-compat.** Strict kwargs: a checkpoint written by newer code carrying an extra `arch` key fails to load on older code, and a renamed/removed field breaks every arch-bearing checkpoint. Not a v1 concern (no arch-bearing checkpoints exist yet), but a `ModelConfig.from_dict` that filters to known fields would cheaply de-risk it later. Note the constraint; don't build it yet.
- **CLI overrides** of config values — deferred. v1 is disjoint domains (file owns buckets 1–2, CLI owns bucket 3). The `--data-root` mount override lives here too. Add a narrow escape hatch later only if we miss it.
- **Secondary-script migration** — `flops_probe`, `overfit_one_batch`, `value_head_probe`, `bench_decode_sync` carry a TODO and are temporarily broken after this lands; migrate when next touched.
- **Sweep launcher.** With disjoint domains the sweep is "write N config files (each declaring its `gpu`), point the Modal entry at each + set run_dir." How that fan-out is expressed (N files vs a base + programmatic width override) is sweep-design, picked up after this lands.
