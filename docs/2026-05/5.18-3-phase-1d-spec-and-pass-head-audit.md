## D1 — encoder API + tests

**Module:** `training/bc/actions.py`

```python
def encode(
    source: int, dest: int, is50: int,
    W_unpadded: int, W_padded: int,
) -> tuple[bool, int]:
    """Wire move -> (is_pass, flat_idx). flat_idx = -1 when pass."""

def decode(
    is_pass: bool, flat_idx: int,
    W_unpadded: int, W_padded: int,
) -> tuple[int, int, int]:
    """(is_pass, flat_idx) -> (source, dest, is50). (-1, -1, -1) when pass."""
```

**Why `-1` for pass:** 0 is a valid non-pass `flat_idx` (cell 0, dir 0, split 0); `-1` is unambiguously not-an-index. Also enables PyTorch's `F.cross_entropy(..., ignore_index=-1)` idiom downstream — pass-frame targets skip CE automatically without an explicit filter.

**Direction decode uses `W_unpadded`** (per plan §4.3). Wire-space neighbors: `delta = dest - source ∈ {±1, ±W_unpadded}`. The padded flat-index math then converts unpadded `(row, col) = (source // W_unpadded, source % W_unpadded)` into the padded grid via `cell_padded = row * W_padded + col`. `H_unpadded` is not needed by encode/decode (row derives from source); it surfaces in D4 for the mask.

**Tests:** `training/tests/test_actions.py`
- `test_round_trip_fabricated[case]` — ~20 parametrized cases: corners, edges, 8 dir×split combos, boundary of unpadded region, multiple `(W_unpadded, W_padded)` pairs, pass.
- `test_invalid_inputs_raise[case]` — ~3 parametrized cases: diagonal delta, source==dest. No out-of-board bounds check — caller is internal/trusted.
- **Row-wrap not exercised:** with `source % W_unpadded == W-1` and `delta = +1`, flat-index arithmetic would land on the next row's leftmost cell. Real wire data never emits this (the game rejects edge-wrap moves), so the encoder trusts the invariant and produces an "E" encoding without checking. D4's mask catches the illegality downstream. Documented here so the invariant is visible.

**Runner:** `uv run pytest training/tests/test_actions.py` from repo root.

**Out of scope for D1:** mask construction (`compute_legal_mask`), per-cell scatter into `[H_pad, W_pad, 8]`, anything touching PyTorch tensors. Those land in D4.

## D2 — per-game iteration scaffold (tentative)

**Module:** `training/bc/dataset.py`

- **Eligibility-fn seam:** `is_eligible(sim_path: Path) -> bool` lives separate from the `IterableDataset` class. Dataset consumes any iterable of `(sim_path, meta_path)` pairs.
- **File source:** `glob(intermediate/)` + lazy per-iter eligibility check. Glob is instant; eligibility check loads only scalar fields from the sim file (`map_width`, `map_height`, `actions_source.shape[0]`) — cheap with `.npz` lazy loading.
- **Sampling:** random with a required `seed: int` arg (no default, matches plan Phase 3 step 1 split utility pattern).
- **Walk order:** outer perspectives `k`, inner timesteps `t = 0..T-2`. Sequential within a game.
- **Emits:** raw `(sim_data, meta_data, k, t)` tuples — no encoding yet (that's D3+D4).
- **Workers:** single-worker for D5. Multi-worker semantics (split across workers, per-worker seed offset) deferred to Phase 3.

**Why lazy-filter for D2:** D5 smoke only pulls 6.4k samples; pre-filtering 165k files would cost minutes of startup. Phase 3's manifest naturally pre-filters (persisted). Eligibility-fn seam absorbs the swap.

## D3 — 12-channel placeholder + padding + drop filter (tentative)

- **Channel order** (per plan §3 Phase 1 step 6): `[own_0..own_7, neutral, log_armies, mountains, cities]`. Neutral mask = cells where `ownership[t] == -1` (the parser's neutral sentinel).
- **Slot canonicalization on** (perspective at canonical channel 0, opponents in natural generals.io slot order at channels 1..7). Rotation key: `perspective_player_ids[k]` from the meta sidecar.
- **Log-armies formula:** `log(1 + armies)` (per `5.05-1` line 170).
- **Padding fill:** 0 for all channels. Binary masks land at 0 naturally; log values land at 0 since `log(1+0) = 0`. Padded cells are excluded by the action mask everywhere downstream, so the fill value is mostly cosmetic.
- **Drop filter (P=8 only + `max(w,h) > 32`):** lives in `is_eligible(...)` from D2. Same seam swaps to pre-filter when Phase 3's manifest replaces the glob.

## D4 — action target + legality mask + value target (tentative)

- **Action target:** `(action_target_flat: int64, is_pass: bool)` from D1's `encode`. Mask determines legality.
- **`H_unpadded`, `W_unpadded` source:** read from the sim file's `map_height` / `map_width` scalars (per `5.16-3-parser-output-design.md` §3 line 40).
- **Per-cell legality mask:** `[H_pad, W_pad, 8]` bool. A `(cell, dir, split)` is legal at time `t` for perspective `k` iff all of:
  - `ownership[t][source_cell] == perspective_player_ids[k]` — raw slot id, **not** canonical slot 0. (Canonicalization only permutes obs-tensor channels; raw `ownership` values stay in original slot ids.)
  - `armies[t][source_cell] >= 2` — need >1 to leave 1 behind; same threshold for full and split moves.
  - destination cell within `[0, H_unpadded) × [0, W_unpadded)` — edge cells lose 1–3 directions.
  - `mountains_mask[dest_cell] == 0` — cities + generals are passable (consistent with plan Phase 2 step 1 BFS rule).
- **Padded cells:** `mask[r, c, :] = False` for `r >= H_unpadded` or `c >= W_unpadded`.
- **Split-independence invariant:** `mask[r, c, dir*2 + 0] == mask[r, c, dir*2 + 1]` for all `r, c, dir`. Free unit-test for D5.
- **Value target:** `int64` class index = `placement[k] - 1`, range `[0, 7]`. Ready for `F.cross_entropy`.

## D5 — smoke test (tentative)

- **Location:** `training/tests/test_dataset_smoke.py` — pytest only, no script hybrid.
- **Batch size:** 64. Inherits from chunk C MPS benchmark + scratchpad anchor. **Not** a commit for training-time batch size (see deferred-decisions list).
- **Skip-if-missing-corpus:** same pattern as `replay-parser/tests/test_decode.py:20`.
- **Assertions** (per plan §3 Phase 1 step 7): shapes, dtypes, no NaN/inf, action target in-range, mask covers ≥1 legal cell on every non-pass frame. Pass-frame mask state is not asserted — pass is voluntary, players often pass with legal moves available, so the contrapositive ("no legal moves ⇒ pass") doesn't hold.
- **Plus:** split-independence invariant from D4.
- **Runtime budget:** 100 batches × 64 samples = 6.4k samples; ~tens of seconds at plan's anchor wall-clock numbers.

## Cross-cutting constants & conventions (D1 pins; D2–D5 inherit)

Split across two modules. `actions.py` owns action-encoding semantics (direction, sub-channel + flat layouts). `constants.py` owns shared tensor-shape and pipeline constants (padded dims, padding convention, eligibility thresholds). D2–D5 import from whichever module owns each pin.

```python
# training/bc/actions.py
N, E, S, W = 0, 1, 2, 3  # NESW clockwise

# training/bc/constants.py
H_PADDED = W_PADDED = 32
```

| Decision | Value | Home | Used by |
|---|---|---|---|
| Direction enum | `N=0, E=1, S=2, W=3` (NESW clockwise) | `actions.py` | D4 mask construction; Phase 2 policy head Conv→8 must produce channels in matching order |
| Sub-channel layout | `sub = dir * 2 + split` (direction-major) | `actions.py` | D4 scatter into `[H_pad, W_pad, 8]`; Phase 2 model output decode |
| Cell-major flat layout | `flat_idx = cell_padded * 8 + sub` | `actions.py` | D4 tensor flattening for CE target; Phase 2 model output is permuted to match (see permute contract below) |
| Padding convention | top-left (unpadded board at rows `0..H-1`, cols `0..W-1`) | `constants.py` | D3 12-channel placeholder assembly + 32×32 padding; D4 mask + action-target scatter |
| Spike padded dims | `H_PADDED = W_PADDED = 32` | `constants.py` | D3 padding target + `>32`-side drop filter; D4 tensor shapes |
| Drop-filter membership | `P=8` only + `max(w,h) ≤ 32` | `constants.py` | D2 `is_eligible(...)`; Phase 3 manifest replaces |

**Permute contract (Phase 2 model side):** the policy head's natural output shape is `[B, 8, H_pad, W_pad]` (PyTorch `nn.Conv2d` is channels-first). To align with the cell-major flat layout above, the model reshape is `logits.permute(0, 2, 3, 1).reshape(B, -1)` → `[B, H_pad * W_pad * 8]`. The mask flattens directly via `.reshape(B, -1)` — no permute needed on the mask side. Either layout requires one permute somewhere; cell-major was chosen for readability (encoding math is constant in board dims, mask construction iterates cell-outer naturally), and the permute cost is negligible (~2 MB float copy per batch).

When D2–D5 land, they should import from `actions.py` and `constants.py` rather than redeclaring — keeps cross-cutting decisions single-sourced. Per-channel encodings (log formula, ownership one-hot, mountains/cities binary) live upstream in `5.05-1` §A/§B; pulled into D3 as-spec'd.

## Pass-head divergence audit

While re-deriving D1's action target shape we surfaced that the split-pass head was introduced as a deviation from the inherited design *without being flagged as such*. Both Claude and the user missed the divergence — which is itself the useful signal here. When working from scratchpad/plan docs that build on top of evergreen design docs, treat any choice that "feels a bit off" as worth tracing back to the inherited source, rather than accepting it because the plan codified it. The trace below shows the pattern in action; future sessions can apply the same vigilance.

**Trail of decisions:**

| Doc | Position |
|---|---|
| Strakam paper §4, §5 | Action vector `[pass, i, j, direction, split]`; policy head `H×W×9` per-cell, 9 channels = pass + 4 dir × 2 split. Singular softmax. Pass-target construction + pass masking **unspecified**. |
| `network-architecture-design.md` line 210 | Inherits strakam: `H×W×9` masked softmax, "Inherited from Strakam." No alternatives proposed. |
| `replay-parser-design.md` line 154 | "30–45% sits comfortably inside vanilla-cross-entropy comfort range; no class-weighting expected at v1. Revisit only if empirical rate exceeds ~80%." — pass-rate at expected levels does NOT motivate structural change. |
| `5.17-3-training-spike-scratchpad.md` §4.2.3 (lines 200–211) | First introduction of split-pass as an alternative. Motivated by per-cell pass feeling "slightly awkward." Misframes strakam's design as having pass at a "10th class" rather than 9 per-cell channels with `H*W` pass redundancy. Marks the choice as needing resolution before coding. |
| `5.17-4-training-spike-plan.md` §3 Phase 2 step 8 + §4.1 | Promotes split-pass to primary spike design; `H×W×9` listed as fallback. **Does not explicitly flag this as a divergence from the inherited strakam-aligned design.** |

**What this session surfaced under scrutiny:**

- The "gradient drowning" intuition that motivated split-pass in the scratchpad isn't obviously correct. Strakam's `H*W` replicated pass logits don't concentrate gradient on any single logit; aggregate pass mass tracks corpus pass-rate, which is expected. The parser-design doc's own threshold (revisit at >80% pass-rate) is the relevant prior, and our empirical 49.7% sits well below it. This is intuition-vs-intuition rather than an empirical settling — neither side has been tested — but the original argument leaned on framing that doesn't survive scrutiny.
- "Match strakam exactly" turns out to be unachievable as a clean shortcut. The paper doesn't specify pass masking or BC target construction across the `H*W` pass logits, so the H×W×9 route requires inventing a target rule too. The repo's published code is **not** the paper's actual training code (`5.02-5-strakam-paper-summary.md` §9 flags this).
- Split-pass remains defensible on its merits (cleanly factored learning problem, standard ML machinery, no per-cell-pass ambiguity to invent around). But the rationale chain that promoted it to primary in `5.17-4` was thinner than the inherited path it replaced.

**Process guidance going forward:**

When a session note or plan proposes a deviation from an inherited design (`network-architecture-design.md`, `observation-tensor-design.md`, `replay-parser-design.md`, or other core docs), **flag the deviation explicitly**, not just describe the new approach. A reader two sessions later should be able to skim the doc and immediately notice "this differs from the inherited spec because X." Sneaking in a deviation, even an intentional one, breaks the trace future sessions rely on.

## Fallback notes (joint H×W×9 target rules)

Thinking-out-loud notes — Daniel requested these be pinned to help ground the pass-head decision rather than as a binding ranking. Surfaced here so future-us can pick up the thread if we ever revisit and want to match strakam more closely. Four candidate target-construction rules for the `H*W` pass logits, roughly cleanest to crudest:

1. **Sum-then-softmax (marginalize):** `pass_score = log-sum-exp(pass_logits)`. Treats all pass logits as one effective "pass class." Closest in spirit to split-head; no coordination requirement; no arbitrary cell choice.
2. **Uniform target across pass logits:** `target = 1/(H*W)` at every pass logit. Forces the model to learn equal mass spread — an arbitrary coordination requirement that doesn't matter for inference.
3. **Mask pass to owned cells only:** smaller redundancy set; still needs one of (1) or (2) for the within-owned-set redundancy.
4. **Single canonical pass logit:** mask pass at all but one cell (e.g., (0,0) or the perspective player's general). Simplest; arbitrary cell choice; the chosen cell's pass and directional logits compete in the softmax.

Sum-then-softmax is the cleanest joint-design fallback, and it's algebraically very close to the split-head we're going with — pass-mass becomes a single LSE pool rather than a separately-pooled scalar.
