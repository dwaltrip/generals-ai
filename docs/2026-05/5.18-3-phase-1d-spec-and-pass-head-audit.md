## Pass-head divergence audit

While re-deriving D1's action target shape we surfaced that the split-pass head was introduced as a deviation from the inherited design *without being flagged as such*. Both Claude (in the scratchpad-writing session) and the user (during review) missed the divergence at the time. Documenting the trace so future sessions can spot the pattern.

**Trail of decisions:**

| Doc | Position |
|---|---|
| Strakam paper §4, §5 | Action vector `[pass, i, j, direction, split]`; policy head `H×W×9` per-cell, 9 channels = pass + 4 dir × 2 split. Singular softmax. Pass-target construction + pass masking **unspecified**. |
| `network-architecture-design.md` line 210 | Inherits strakam: `H×W×9` masked softmax, "Inherited from Strakam." No alternatives proposed. |
| `replay-parser-design.md` line 154 | "30–45% sits comfortably inside vanilla-cross-entropy comfort range; no class-weighting expected at v1. Revisit only if empirical rate exceeds ~80%." — pass-rate at expected levels does NOT motivate structural change. |
| `5.17-3-training-spike-scratchpad.md` §4.2.3 (lines 200–211) | First introduction of split-pass as an alternative. Motivated by per-cell pass feeling "slightly awkward." Misframes strakam's design as having pass at a "10th class" rather than 9 per-cell channels with `H*W` pass redundancy. Marks the choice as needing resolution before coding. |
| `5.17-4-training-spike-plan.md` §3 Phase 2 step 8 + §4.1 | Promotes split-pass to primary spike design; `H×W×9` listed as fallback. **Does not explicitly flag this as a divergence from the inherited strakam-aligned design.** |

**What this session surfaced under scrutiny:**

- The "gradient drowning" intuition that motivated split-pass in the scratchpad doesn't hold up cleanly. Strakam's `H*W` replicated pass logits don't concentrate gradient on any single logit; aggregate pass mass tracks corpus pass-rate, which is expected. The parser-design doc's own threshold (revisit at >80% pass-rate) is the relevant prior, and our empirical 49.7% sits well below it.
- "Match strakam exactly" turns out to be unachievable as a clean shortcut. The paper doesn't specify pass masking or BC target construction across the `H*W` pass logits, so the H×W×9 route requires inventing a target rule too. The repo's published code is **not** the paper's actual training code (`5.02-5-strakam-paper-summary.md` §9 flags this).
- Split-pass remains defensible on its merits (cleanly factored learning problem, standard ML machinery, no per-cell-pass ambiguity to invent around). But the rationale chain that promoted it to primary in `5.17-4` was thinner than the inherited path it replaced.

**Process guidance going forward:**

When a session note or plan proposes a deviation from an inherited design (`network-architecture-design.md`, `observation-tensor-design.md`, `replay-parser-design.md`, or other core docs), **flag the deviation explicitly**, not just describe the new approach. A reader two sessions later should be able to skim the doc and immediately notice "this differs from the inherited spec because X." Sneaking in a deviation, even an intentional one, breaks the trace future sessions rely on.

## Fallback notes (joint H×W×9 target rules, ranked)

Pinned per the session's "may want to note this somewhere" thread. If we later revisit and want to match strakam more closely, four candidate target-construction rules for the `H*W` pass logits, ranked from cleanest to crudest:

1. **Sum-then-softmax (marginalize):** `pass_score = log-sum-exp(pass_logits)`. Treats all pass logits as one effective "pass class." Closest in spirit to split-head; no coordination requirement; no arbitrary cell choice.
2. **Uniform target across pass logits:** `target = 1/(H*W)` at every pass logit. Forces the model to learn equal mass spread — an arbitrary coordination requirement that doesn't matter for inference.
3. **Mask pass to owned cells only:** smaller redundancy set; still needs one of (1) or (2) for the within-owned-set redundancy.
4. **Single canonical pass logit:** mask pass at all but one cell (e.g., (0,0) or the perspective player's general). Simplest; arbitrary cell choice; the chosen cell's pass and directional logits compete in the softmax.

Sum-then-softmax is the cleanest joint-design fallback, and it's algebraically very close to the split-head we're going with — pass-mass becomes a single LSE pool rather than a separately-pooled scalar.
