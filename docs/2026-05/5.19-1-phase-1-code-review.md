## TL;DR

Code is in good shape. No must-fix items. A handful of should-fix items —
mostly Phase-2-readiness or robustness rather than current-correctness, plus
one genuine test-coverage gap surfaced by a fresh-eyes Opus audit pass over
the test suite. The four pieces I'd want to think about before Phase 2 starts:

1. `encode_frame`'s `(sim, meta, k, t) → dict` signature won't accommodate
   Phase 2's stateful fog computation without growing — worth a small refactor
   choice now rather than mid-implementation.
2. `canonical_slot_order(P=8)` is implicitly coupled to the eligibility
   filter. Spike-safe; one assert would lock the invariant.
3. `iter_frames` has no per-game exception handling. Fine for the 6.4k-sample
   smoke test, latent risk for Phase 3 corpus runs.
4. `test_same_game_frames_share_sim_meta_refs` only half-tests its docstring
   claim — the sim-ref assertion is tautological by construction.

Test baseline: `uv run pytest training/tests/` → **30/30 green** (3.94s).

## Should-fix

Severity-ranked, file-independent.

### S1. `encode_frame` signature will need to grow for Phase 2 fog

**Where:** `bc/dataset.py:79-114` (`encode_frame`); `bc/obs.py:77` (`build_obs`).

**What:** Phase 2's running per-cell memory (`last_seen_owner`, `last_seen_armies`,
`turns_since_seen`, `historically_seen`) plus the monotonic
`mountains`/`cities`/`generals`/`structures_in_fog` channels plus dense recent
history (2N channels) are all stateful per perspective — they update as
`t` walks forward. The current `encode_frame(sim, meta, k, t)` is per-frame
stateless and `build_obs(sim, t, perspective_slot, H, W)` mirrors that.

**Why it's not blocking now:** The Phase 1 placeholder is genuinely stateless,
and the `iter_frames → encode_frame` split is the right seam — the natural
Phase 2 shape is "compute per-k fog state once at the top of the inner k-loop,
thread it into encode_frame as a new arg." The outer iteration order (game →
k → t) is already correct.

**Why it's a should-fix anyway:** Worth deciding *how* the perspective-state
threads through before fog code lands. Two reasonable shapes:

- Add a `PerspectiveState` (or similar) positional arg to both `encode_frame`
  and `build_obs`. The dataset constructs it at the top of each k loop and
  passes it through as t advances.
- Attach the precomputed state to `Frame` itself — `iter_frames` precomputes
  fog for all T timesteps of perspective k in one pass, then yields enriched
  Frames; `encode_frame` reads from `frame.fog_state[t]` instead of recomputing.

The second shape has the nice property that `encode_frame` stays per-frame
pure (just consumes precomputed state). The first is more memory-frugal
(incremental update vs. full precompute). Either works; pick before writing.

### S2. `canonical_slot_order` hardcodes `P=8` with no enforcement

**Where:** `bc/obs.py:22` — `def canonical_slot_order(perspective_slot: int, P: int = 8)`.

**What:** The function is correct *given* the eligibility filter
(`ELIGIBLE_PLAYER_COUNT = 8` in `bc/constants.py:18`). For a hypothetical
P=4 game, it would return 8 entries with phantom channels 4..7 — channels
that would be all-False in obs (no cell has ownership 4..7), but silently
included.

**Why it matters:** The coupling is implicit. Picking up P=4–7 games post-spike
is on the deferred list (plan §4.1) — when that lands, `canonical_slot_order`
needs to either (a) take a real P and produce a P-length list with the obs
tensor's channel count varying accordingly, or (b) keep P=8 channels but
explicitly mask out phantom slots. Right now there's no signal that this is
a load-bearing assumption.

**Suggested fix:** Either add `assert P == 8, "canonicalization assumes P=8 spike data"`
inside `canonical_slot_order`, or move the `P=8` constant into
`constants.py` as `OBS_PLAYER_CHANNELS` so the coupling is visible.

### S3. `iter_frames` has no per-game error recovery

**Where:** `bc/dataset.py:166-187`.

**What:** Per-game block:

```python
with np.load(sim_path) as sim_npz:
    sim = {key: sim_npz[key] for key in sim_npz.files}
with np.load(meta_path) as meta_npz:
    meta = {key: meta_npz[key] for key in meta_npz.files}

T = sim["ownership"].shape[0]
K = meta["perspective_player_ids"].shape[0]
for k in range(K):
    ...
```

A corrupt npz file, missing meta sibling, or unexpected schema would raise
mid-iteration and kill the run.

**Why it's not blocking now:** The smoke test pulls 6.4k samples and exited
clean — corpus is parser-validated, so this is a known-quiet path. The 66
`skip:exception` cases from the parser corpus run (per plan §5 risks table)
were dropped before parsing finished, so they don't reach the intermediate
dir.

**Why it's a should-fix:** Phase 3's full corpus run touches ~165k files
across multiple epochs. One bad file mid-epoch loses the epoch. The pattern is
the same as `replay-parser/replay_parser/validator.py`'s per-game try/except
+ skip-counter (load corpus → walk games → score). Worth lifting that shape
across when Phase 3 starts; not urgent for the spike.

### S4. `test_same_game_frames_share_sim_meta_refs` sim-ref check is tautological

**Where:** `training/tests/test_dataset.py:55-68`.

**What:** The test groups frames by `id(f.sim)`:

```python
by_game: dict[int, list[Frame]] = {}
for f in frames:
    by_game.setdefault(id(f.sim), []).append(f)

for game_frames in by_game.values():
    sim0, meta0 = game_frames[0].sim, game_frames[0].meta
    for f in game_frames:
        assert f.sim is sim0
        assert f.meta is meta0
```

Since `id(f.sim)` is the grouping key, every frame in a group already has
identical `id(f.sim)` to `sim0` by construction — the `f.sim is sim0`
assertion is vacuously true. If the dataset regressed to "fresh sim dict
per frame," the grouping would just split into many singleton buckets and
each per-bucket `is` check would still pass.

**Why it matters (mildly):** The `f.meta is meta0` half is real — meta isn't
in the grouping key, so meta reloads or sim/meta cross-wiring would still be
caught. And in practice the sim/meta dicts are loaded together in the same
`with np.load(...)` block, so the "sim shared but meta not" failure mode is
unlikely. The more general "did the dataset hold one sim dict per game across
all frames of that game" guarantee isn't currently enforced by this test
despite its docstring claim.

**Suggested fix:** Group frames by iteration order instead of `id(f.sim)` —
every `(k=0, t=0)` begins a new game block. Then assert ref equality within
each block. That grouping is independent of the assertion under test.

## Minor findings

Grouped by file. None require action — flagged so they're visible if other
work touches the same code.

### `bc/utils.py`

- No module docstring; `meta_path_for` has no docstring. Every other module
  is heavily commented (per training-code docstring convention) — this one
  is the outlier. Function names are obvious so this is genuinely minor.
- The name `utils.py` is grab-bag. `paths.py` or `corpus_paths.py` would say
  more. Worth renaming if more file-system helpers land; not worth churning
  for two functions.

### `bc/dataset.py`

- `Frame` is a generic name — the in-file comment already self-flags this
  (lines 47–48: "rename if a more specific name emerges (e.g., `RawFrame`
  paired with an encoded `TrainingExample`)").
- `_epoch_counter` mutation isn't thread-safe; safe under the documented
  single-worker constraint. Worth revisiting when DataLoader workers land
  in Phase 3, which the class docstring also self-flags.
- `is_eligible` short-circuits map-dims before reading `actions_source.shape[0]`
  — the comment is honest that `actions_source.shape[0]` materializes ~32 KB
  via npz's eager-per-key semantics rather than reading just the header.
  Acceptable for the spike; manifest-time pre-filtering removes the cost
  entirely.

### `bc/mask.py`

- `np.repeat(legal_per_dir, 2, axis=-1)` to expand 4 directions → 8
  sub-channels is concise but requires the reader to know which direction
  numpy's repeat-with-int picks. The inline comment ("`[a, b, c, d]` becomes
  `[a, a, b, b, c, c, d, d]`") handles this; fine as-is.

### `bc/obs.py`

- The placeholder cities channel (channel 11) is full-board (not
  perspective-fogged). This is plan-doc-correct for Phase 1 step 6 ("no fog
  in Phase 1"), but worth noting for the Phase 2 transition — channels 0..11
  all need to flip to perspective-aware versions at that point.
- The mountains channel is densified per-frame (`mountains_mask = np.zeros(HW, dtype=bool); mountains_mask[sim["mountains"]] = True`).
  Static within a game, so this is wasted work across T frames of the same
  game. The inline comment flags it as a "lift to per-game cache" candidate
  if profiling shows it matters; the same lift would help `build_mask` which
  does the identical densify.

### `bc/__init__.py`

- Empty file. Fine; no re-exports needed at this scale.

### `bc/constants.py`, `bc/actions.py`

- Nothing to flag. Both are clean — `actions.py`'s docstring is particularly
  good about pinning the cell-major flat layout, the unpadded-vs-padded
  coordinate distinction, and the row-wrap invariant (encoder trusts wire
  protocol; mask catches downstream).

### Tests

- `test_obs.py` covers `canonical_slot_order` parametrically + one synthetic
  `build_obs` integration check focused on channel 0. The non-canonical
  channels (log-armies scaling, mountains mask, neutral mask, cities mask)
  aren't unit-tested in isolation. The smoke test catches NaN/inf and shape
  errors, which would surface log-scaling bugs; semantic correctness of the
  individual channels rides on visual inspection. Consistent with the
  project's "one smoke test per module + integration tests for correctness"
  preference — not a coverage gap to fill.
- `test_dataloader_smoke.py`'s strongest assertion is the recorded-action-must-be-legal
  check via `mask.gather(target)` — high-information cross-check between
  encode, mask, and action recording. Good test.
- `conftest.py`'s session-scoped `sim_paths` fixture is the right call —
  `list_sim_paths` walks ~165k files and was previously called per test.

Three "narrower than the name implies" notes from the Opus audit pass — not
broken, but worth knowing when reading the suite:

- `test_actions.py::test_round_trip[pass-is50-0]` and `[pass-is50-1]` —
  both encoder and decoder short-circuit on the pass path before reading
  `is50`. The two parametrizations differ only in an unread argument and
  are equivalent tests labeled as if they varied.
- `test_dataset.py::test_yields_frames_with_expected_keys` — spot-checks
  5 of the sim keys and 2 of the meta keys. "Expected keys" reads broader
  than the assertion.
- `test_dataset.py::test_is_eligible_matches_filter` — re-implements the
  eligibility predicate inline and compares to `is_eligible`'s output. It's
  a differential-against-itself rather than an independent oracle; a bug
  present in both copies (e.g., a typo'd key name) wouldn't be caught.

## Phase 2 readiness summary

The structural seams hold up well:

| Seam | Phase 2 fit |
|---|---|
| `iter_frames → encode_frame` decoupling | Good. Per-k state precompute slots in naturally. |
| `canonical_slot_order` channel ordering | Good. Phase 2 opponent-indexed channels (`opp_N_*`) thread through the same permutation. |
| `actions.py` encode/decode + cell-major flat layout | Good. Layout is fixed across Phase 1 and Phase 2 per plan §3 Phase 1 step 6. |
| `bc/constants.py` padded dims + drop filter | Good. Padding policy doesn't change in Phase 2. |
| `bc/mask.py` legality conditions | Good for now. Phase 2 doesn't add new legality conditions — same source/armies/dest/mountain rules. |

The one place where Phase 2 will need to reach back into Phase 1 code is
`encode_frame`'s signature (S1 above). Everything else extends cleanly.
