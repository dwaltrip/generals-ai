# Survey: the `.pt` checkpoint file I/O boundary

Task 1 of 3 in the checkpoint-config-versioning survey. Read-only map of every site that reads, writes, locates, or inspects a model checkpoint `.pt` file, ahead of the planned reshape that moves the full `TrainConfig` into the `.pt` (`arch` → `config.arch`, `in_ch` → top-level, plus a `config_version` stamp).

## Headline verdicts

- **Raw `.pt` read/write is genuinely owned by two modules**: `bc/state.py` (`TrainingState`, the only production *writer* and the optim/scaler/epoch *reader*) and `bc/checkpoint.py` (every other *reader* + all format-inspection helpers + the filename scheme). No production `torch.save`/`torch.load` of a checkpoint exists anywhere else in the repo.
- **Filename-scheme knowledge is more spread out than the I/O**: the `epoch_NNN.pt` convention is independently parsed in `bc/run_dir.py` (resume latest-finder), `analysis/run_metrics.py` (`resolve_epochs`), `scripts/stratified_val_loss_analysis.py`, and matched by a regex in `eval-tools/policy_spec.py`. These never open the file — they only glob/parse names — so the config reshape doesn't touch them. The reshape does **not** change the filename scheme, so this surface is informational, not at-risk.
- **Three sites structurally key on a top-level `"arch"`** and will break under the reshape: `is_arch_bearing` (`checkpoint.py:107`), `TrainingState.from_checkpoint` (`state.py:109`), and `_arch_for_load` (`checkpoint.py:129`, `:130`, `:143`, `:150`). The writer `TrainingState.save` (`state.py:134`) also bakes the current layout. These four are the real edit surface.
- **Every checkpoint `torch.load` passes `weights_only=True`.** The new `config` block must deserialize under that constraint — see the `weights_only` flag section; `TrainConfig`'s `Path` fields are the live risk.
- **Resume reads its parent config from the `args.json` sidecar, not the `.pt`** (`run_dir.load_parent_config`, `run_metrics.resolve_val_samples`). Config-versioning that relocates config into the `.pt` intersects this path even though it isn't `.pt` I/O today.

## 1. Enumerated sites by kind

**Kind 1 — raw writers (`torch.save` of a checkpoint dict):**
- `bc/state.py:135` `TrainingState.save` — the sole production writer. Keys: `model, arch, optim, scaler, epoch`, with `arch = {**asdict(model.cfg), "in_ch": model.cfg.in_ch}` (`state.py:134`).
- (tests only) `eval-tools/tests/test_multiwidth_acceptance.py:26`, plus the `training/tests/*` fixtures listed above.

**Kind 2 — raw readers (`torch.load` of a checkpoint):**
- `bc/checkpoint.py:94` `is_legacy_checkpoint` — `weights_only=True`.
- `bc/checkpoint.py:106` `is_arch_bearing` — `weights_only=True`.
- `bc/checkpoint.py:180` `load_bc_model` — `weights_only=True`.
- `bc/state.py:107` `TrainingState.from_checkpoint` — `weights_only=True` (a second read of the file, after `load_bc_model` reads it for weights).
- (test only) `training/tests/test_state.py:49` — `weights_only=True`.

**Kind 3 — format-inspection helpers:**
- `bc/checkpoint.py:75` `is_combined_checkpoint` — pure predicate on an already-loaded object; discriminates on the `"model"` key.
- `bc/checkpoint.py:86` `is_legacy_checkpoint` — loads, then `not is_combined_checkpoint`.
- `bc/checkpoint.py:98` `is_arch_bearing` — loads, then `is_combined_checkpoint(obj) and "arch" in obj`.
- `bc/checkpoint.py:110` `_arch_for_load` — pure translator over the loaded dict: reads `obj["arch"]`, migrates the retired `elim_head_enabled` flag, back-fills from `LEGACY_ARCH`/`LEGACY_OBS_CFG`, and pops+validates the `in_ch` checksum.

**Kind 4 — filename-scheme / location logic:**
- `bc/checkpoint.py:65` `ckpt_name` — the single home for the `epoch_{epoch:03d}.pt` format.
- `bc/run_dir.py:144,148,149` `prepare_resume` — globs `epoch_*.pt`, picks latest by `int(p.stem.split("_")[1])`, derives `parent_epoch` the same way.
- `analysis/run_metrics.py:134-135` `resolve_epochs` — globs `epoch_*.pt`, parses epoch ints.
- `scripts/stratified_val_loss_analysis.py:97` — constructs `epoch_{epoch:03d}.pt` directly (does not call `ckpt_name`).
- `eval-tools/policy_spec.py:159` `_CHECKPOINT_RE` — regex extracting run-date + epoch from a checkpoint path for display labels.
- `eval-tools/scripts/run_eval_modal.py` — locates/pulls checkpoint files from the modal volume by path; no format inspection.

## 2. Keys written / assumed, per site

- **Writer** `TrainingState.save`: writes exactly `{model, arch, optim, scaler, epoch}`. `in_ch` is written *inside* `arch` as a derived checksum (`state.py:134`), not as a dataclass field.
- `is_combined_checkpoint`: assumes a dict and discriminates on `"model"`.
- `is_legacy_checkpoint`: assumes only that the load returns *some* object; legacy = "no `model` key".
- `is_arch_bearing`: assumes `"model"` and tests `"arch"`.
- `load_bc_model`: reads `obj["model"]` for the state_dict (`:182`) and routes arch through `_arch_for_load`.
- `_arch_for_load`: reads `obj["arch"]` as a dict (`:130`), expects optional nested `obs` sub-dict (`:142,:145`), and an optional `in_ch` inside arch (`:150`); also tolerates the retired `elim_head_enabled` key (`:137`).
- `from_checkpoint`: reads `arch` (presence-gate for the arch-match assert, `:109`), `optim` (`:117`), `scaler` (`:119`), `epoch` (`:120`).

## 3. `weights_only` audit

Every checkpoint `torch.load` is `weights_only=True` (`checkpoint.py:94,106,180`; `state.py:107`; test `test_state.py:49`). Implication for the new `config` block:

- The block must contain only types in the `weights_only` safe-globals allowlist (tensors, primitives, list/dict/tuple, a few stdlib types). Today's `arch` survives because `asdict(model.cfg)` yields only primitives + tuples + a nested obs dict.
- **`TrainConfig` is not trivially safe**: it has `Path` fields (`run_dir`, `manifest`, `intermediate` — see `run_dir.py:67-68` usage and `_resume_config` at `resume.py:67-68`). `pathlib.Path` is **not** in the default `weights_only` allowlist, so a naively-pickled `asdict(TrainConfig)` containing `Path` objects would fail to load under `weights_only=True`. The config block must store paths as strings (or run through a JSON-native normalization like the existing `json_default` used for `args.json` at `run_dir.py:44`). This is the single most important `weights_only` constraint for the new format.

## 4. Sites that hardcode the current key layout

The reshape `arch` → `config.arch`, `in_ch` → top-level breaks, in order of importance:

1. **`_arch_for_load` (`checkpoint.py:110`)** — the densest dependency. `"arch" in obj` (`:129`), `dict(obj["arch"])` (`:130`), `{**asdict(LEGACY_ARCH), **ckpt_arch}` (`:143`), and `arch_dict.pop("in_ch", None)` (`:150`). Both reshaped keys are consumed here. The `in_ch`-pop-and-validate logic must move to read a top-level `in_ch` against `config.arch`-derived obs.
2. **`is_arch_bearing` (`checkpoint.py:98-107`)** — `is_combined_checkpoint(obj) and "arch" in obj`. Becomes a test for `config`/`config.arch` presence. This predicate also feeds the inference `model_key` (`inference.py:111`), so its semantics matter beyond load.
3. **`from_checkpoint` (`state.py:107-120`)** — `if "arch" in obj` gates the arch-equality assert (`:109,:113`). Must read `obj["config"]["arch"]` (or compare against the stored full config). `optim/scaler/epoch` access is unaffected.
4. **`TrainingState.save` (`state.py:124-145`)** — the writer; redefined wholesale to emit `{model, config, config_version, in_ch, optim, scaler, epoch}` (exact shape per the design).

`is_combined_checkpoint` (`checkpoint.py:75`) keys only on `"model"` and is **safe** as long as `model` stays top-level. The filename-scheme sites (kind 4) are all safe — they never open the file.

Out-of-band but adjacent: resume's parent-config source is the `args.json` **sidecar** (`run_dir.load_parent_config:168`, consumed by `check_drift`/`_resume_config`), and `run_metrics.resolve_val_samples:147` also reads `args.json`. If config-versioning aims to make the `.pt` the source of truth, these sidecar readers are the follow-on surface — not breakage today, but the place the two config homes currently diverge.

## 5. Final verdict

- **Owners of raw `.pt` read/write**: `bc/state.py` (writer + optim/scaler/epoch reader via `TrainingState`) and `bc/checkpoint.py` (all other readers, all format-inspection, the filename scheme). The reshape is implementable by editing these two modules plus their tests; no other production module calls `torch.save`/`torch.load` on a checkpoint.
- **Holders of checkpoint-format knowledge beyond the owners**: only the test fixtures (including the cross-package `eval-tools/tests/test_multiwidth_acceptance.py`).
- **Holders of filename-scheme knowledge**: `bc/checkpoint.py` (`ckpt_name`), `bc/run_dir.py`, `analysis/run_metrics.py`, `scripts/stratified_val_loss_analysis.py`, `eval-tools/policy_spec.py` — independent of the I/O owners, and untouched by the reshape.
- **The four edit sites**: `TrainingState.save`, `_arch_for_load`, `is_arch_bearing`, `TrainingState.from_checkpoint`. Plus the `weights_only=True` constraint forcing the config block to be JSON-native (Path-as-string).
