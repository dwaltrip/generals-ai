# Experiment Design: Learning "Smallest-Army Player" from generals.io Frames

## 0. Purpose and scope

This document specifies a set of toy experiments that train small neural networks
to perform one simple transformation on a single parsed generals.io frame:

> **Given the current game state, return the index of the *alive* player with the
> smallest total army.**

The point is **not** to test whether neural nets are powerful enough to do this —
they trivially are. The target is *linear* in the right representation (see §2). The
point is to study, on a task whose ground truth we can generate analytically and
infinitely:

- whether SGD reliably **finds** the clean solution,
- how much **data** it needs,
- how it **generalizes** outside the training regime,
- and how all of the above depend on **input encoding** and **architectural
  inductive bias**.

A companion document (`pedagogy_and_methodology.md`) explains the *why* behind every
design choice here and is meant to be read alongside or before this spec.

### Why scoped this narrowly (read before the architecture menu)

These experiments exist to support a separate, harder investigation: an auxiliary
head on an FFA agent that is underperforming. The toy task here deliberately isolates
**only the cross-player comparison / argmin step** and hands the per-player totals to
the network as precomputed values. It does **not** test spatial aggregation, harder
targets, or the full observation.

Implication for architecture choices: we keep the *core* menu tight and matched to
this scoped task, but we should **not over-constrain the implementation**. Leave room
(in code structure and naming) for a natural follow-up that moves closer to the real
aux head — e.g. raw per-tile inputs, where convolutions and tile-level aggregation
become relevant again. See the closing note (§9) for more.

## 1. Task definition

### 1.1 Setting

- Game mode: **FFA, fixed at N = 8 players.**
- Replay data is filtered to games where **all 8 players are present** (no
  partially-filled lobbies from low-population times).
- A single training example is one **frame** (one timestep of one game).

### 1.2 Target

For a frame, compute each player's total army:

```python
total_army_N = sum(tile.army for tile in player_N_tiles) / 1000.0
```

The target is:

> `argmin` of `total_army` taken **over alive players only**.

"Alive" is the **elimination-based mask**: a player is alive until their general is
captured. This is *not* the same as `total_army > 0`. The two usually coincide, but
diverge for **surrendered** players — out of the game (not alive), yet still holding
real army on the board for a fixed capture window before their tiles convert to
neutral. The MVP filters surrendered frames out, so `alive ≡ (total_army > 0)` holds
there; handling the surrender population (a status-encoding axis) is an early
follow-up. The alive-masking is the main source of difficulty and is studied
explicitly via the encoding ladder (§3.5) and the alive-filter (§3.6).

### 1.3 Tiebreak rule

Exact ties (equal floats after `/1000`) occur almost entirely in the early game when
several players sit at the same small integer army.

- **Label rule:** the canonical label is the **lowest player index** among the
  argmin set.
- **Decision rule at eval:** take `argmax` over the model's output logits using the
  **same lowest-index tiebreak.**
- Label rule and decision rule **must match**, or correct frames get miscounted as
  wrong purely on ordering convention.

### 1.4 Label format

Each frame's label carries **both**:

1. the **canonical index** (lowest-index argmin), and
2. the **full argmin set** (all players tied for the minimum alive army).

The full set is needed for the tie-aware metrics in §8 (strict-margin accuracy and
in-set accuracy).

---

## 2. The reference solution

The whole experiment is measured against one fact:

> In the clean representation, the optimal model is `score_p = -army_p`, then
> `argmax`. As a single linear layer `Linear(8, 8)`, this is the weight matrix
> **W = -I** (negated identity), bias 0.

Everything below either (a) should recover this, (b) is a harder *container* for the
same function, or (c) has an encoding that breaks the linearity and forces a
nonlinear solution. The reference solution is not a tunable knob; it is the yardstick.

## 3. Input representation and the sweep axes

### 3.1 The ecological (real) format: broadcast channels

The real network presents every per-frame constant as a **channel broadcast across
the board**. So `total_army_N` is the true per-player total **repeated as a constant
at every tile**, giving shape `[N, H, W]` per feature.

Critical property: along H×W each channel is **spatially constant** — the H×W
dimension carries **zero** extra information. Consequences:

- This format tests **only** argmin-of-a-vector, **not** spatial summation.
- Global average pooling over H×W is **lossless** (mean of a constant is the
  constant).
- Convolution depth / kernel size buy **nothing** (a conv over a constant field
  returns a constant; it collapses to a scaled 1×1 conv). See §5 and the pedagogy
  doc.

### 3.2 Board size and padding

Boards vary in size. Current handling: filter to games whose maps fit within a chosen
max width/height, and **pad** smaller maps to that fixed `[H, W]`.

Padding interacts with one architecture only: the **flatten-MLP** (§4, family C),
whose input dimension is `C·N·H·W`. Pooled and vector-native architectures collapse
H×W away and are size-invariant. This makes board-size **extrapolation** (train one
size, eval another) a meaningful test for flatten but trivial for the pooled nets
(§8).

### 3.3 Tensor layout convention (pin this in the encoder)

The true input is 4-D: `C · N · H · W` (channels × players × height × width; the
C/N order in the real model is to be confirmed, but the convention below is what the
code must enforce regardless of physical axis order):

- **Pool over H×W only.** Never pool over N or C.
- **Keep N (players) as its own explicit axis.**
- **Treat C as the per-player feature dimension.**

This matters for the player-structured architectures (families D and E):

- Order-augmentation permutes along **N**, moving each player's entire C-bundle
  (army, land, alive, …) together as a unit. Permuting the wrong axis silently
  scrambles features instead of players — a correctness bug, not a crash.
- The shared per-player head φ maps **ℝ^C → ℝ** (a player's feature bundle → score)
  and is applied along the **N** axis. A transposed C/N would apply φ across channels
  instead of players, which is nonsense.

### 3.4 SWEEP AXIS — input channels (C): "army-only" vs "full obs"

The target depends only on army (+ alive status). Every other channel is an
**irrelevant feature the net must learn to ignore.** Two configurations:

- **army-only** (cleanest; the headline core runs). Cleanest target↔input mapping.
- **full obs** (army + land + whatever the real obs carries). The natural
  *distractor* test, since these channels are already in the real observation.

Caveat that makes "full obs" interesting: **land and army are correlated** in
generals (more land → more production → more army). A net handed both may lean on
land as a proxy for army — fine on average, but it **breaks on off-distribution
frames** where the correlation snaps (big army / little land, or vice versa). So
"full obs" is effectively a **feature-selection / distractor-robustness** test.

Note: the alive-mask channel from the encoding ladder (§3.5) is itself just one of
these C channels. "Explicit mask encoding" = "include the alive channel in C." The
channel axis and the encoding ladder share the same machinery.

**Recommendation:** keep the headline grid **army-only** for a clean target↔input
map; run **full obs** as a deliberate distractor variant.

### 3.5 SWEEP AXIS — alive encoding (the "how much does feature design buy you" ladder)

Three ways to convey alive/dead status. This determines whether the function is even
linear:

- **(a) Explicit alive-mask channel** — a separate `1 = alive / 0 = dead` channel
  broadcast like the others; army stays on its natural scale. Target becomes
  `argmin(army + (1 - alive)·BIG)`, which is **linear in the augmented input**. The
  masking nonlinearity disappears — it was an encoding artifact, not intrinsic.
  *Cleanest.*
- **(b) 0-overload (current real encoding)** — fully-eliminated players have
  `army = 0` (and `land = 0`), their tiles having converted to neutral. (Surrendered
  players keep real army and are the exception — filtered out of the MVP; see §1.2.)
  A dead player is indistinguishable from a legitimately near-zero live
  player; the exclude/include boundary sits **inside** the live data range. Worst
  case for naive argmin: a dead player has the *smallest possible* value and is
  *maximally preferred* by plain argmin. Forces a non-monotonic "notch" that a linear
  layer cannot represent (see §4 family B and the pedagogy doc).
- **(c) -1 sentinel** — dead players get a unique `army = land = -1`. (Like
  0-overload this *overwrites* the army value, so it is faithful only for
  fully-eliminated players; a surrendered player's real army would be falsified —
  they are filtered out of the MVP; see §1.2.) Makes "dead"
  **linearly separable** from all alive states (alive armies ≥ 0, dead strictly -1,
  clean threshold with margin). The *value* alone doesn't fix argmin (it makes dead
  even smaller); what helps is the **separability**. Caveat: -1 sits outside the
  natural value range, so it can distort scale-sensitive nets and flatten-MLPs that
  key on the -1 pixels; it also interacts badly with saturating activations like tanh
  (§3.10).

**Sub-variant of (b): rescaled gap.** Under 0-overload the smallest *live* army is
≥ 1/1000 = 0.001 (a player always holds at least their general), while dead = 0.000.
The required notch must fit inside a **0.001-wide band** — numerically delicate, and
the likely reason 0-overload is the most data-hungry and normalization-sensitive
encoding. Add a **rescaled variant** (widen the gap) to separate "encoding is bad"
from "scaling is bad."

### 3.6 SWEEP AXIS — alive filter (the masking isolation control)

- **all-alive only** — frames where all 8 players are alive. This is the **linear
  oracle / clean control**: no masking, target is pure linear argmin.
- **mixed** — frames where eliminations have occurred. The **real task**, with
  masking.

**Nesting:** the encoding ladder (§3.5) only matters in the **mixed** filter. On
all-alive, all three encodings collapse to the same thing (no dead players to encode).
So encoding × filter is **nested, not a full cross.** The accuracy gap between
all-alive and mixed (per encoding) is the **cost of the masking conditional.**

### 3.7 SWEEP AXIS — broadcast `[N,H,W]` vs plain vector `[N]`

This is **not** a global axis; it is architecture-dependent:

- **Vector-native architectures** (equivariant linear, shared-φ): no spatial dim
  exists; the axis **does not apply.**
- **Collapse-then-act architectures** (pool-first linear, pooled MLP, 1×1-conv→pool,
  DeepSets): avg-pool over a constant channel returns the constant, so broadcast vs
  vector land on identical post-collapse values. Running both is a **one-off
  equivalence / encoder-correctness check**, not a sweep.
- **Flatten-MLP**: the **only** architecture where it genuinely matters. Broadcast
  (`C·N·H·W` inputs, must *learn* the redundancy) vs vector (`C·N` inputs, redundancy
  handed to it) are **different learning problems.** This is the isolated
  inductive-bias gap.

The plain-vector format also serves as the **irreducible-difficulty baseline** — the
absolute easiest version of the task (argmin of 8 numbers, nothing else), setting the
ceiling every spatial architecture is measured against.

**Doc placement:** attach this as a property of the flatten-MLP (headline) plus a
confirmation note on the pooled family; mark N/A for vector-native. Do **not** list it
as a primary-grid row.

### 3.8 SWEEP AXIS — loss function

- **Cross-entropy (CE)** over 8 logits vs the canonical-index label — the real-net
  baseline. **Unmasked:** both the CE and the argmax decision range over all 8 players
  with no external alive mask on the logits — learning to exclude dead players *from
  the encoding* is exactly what the encoding ladder studies (see 6.18-1 Appendix A).
- **Margin / ranking loss** on per-player scores — directly targets "score of true
  min < all others" and naturally **stops penalizing within the tie set**, cleaning
  up the early-game ambiguity.

**Recommendation:** narrow sweep — run both on the clean baseline and on one
nonlinear-encoding case to see if ranking loss helps with ties/margins. Do **not**
cross with the full grid.

*(Optional third option, not in the core sweep: regress `-army` per player as an
auxiliary reconstruction target and argmin a fixed readout — tests whether forcing the
net to recover the actual army value helps. Mention only.)*

### 3.9 SWEEP AXIS — order augmentation (on / off)

Shuffle player order during training (permute along N). Reveals **where the
permutation symmetry comes from**:

- Applies **only to the unconstrained architectures** (plain `Linear(8,8)`,
  flatten-MLP). It is a no-op by construction on the equivariant / shared-φ nets.
- Cross-cut with weight inspection (§8): does the learned `Linear(8,8)` matrix land
  in the symmetric subspace `a·I + b·11ᵀ` only when augmented, or on its own?

### 3.10 SWEEP AXIS — activation function (optional, low priority)

- Default **ReLU** everywhere (and what the real net uses).
- Optional **GELU** (modern smooth default) or **tanh** (classical bounded contrast)
  — run **only** on a depth ≥ 1 architecture crossed with the tight-gap encoding
  (the one cell where fitting a sharp non-monotonic cliff might depend on activation
  smoothness). A no-op for linear / 0-hidden nets (no activation to vary).
- **tanh caution:** it saturates for large-magnitude inputs; the -1 sentinel sits at
  the value-range edge, so tanh can squash the dead-vs-live distinction. Keep any
  tanh runs on the explicit-mask / rescaled encodings, not raw -1-overload.

## 4. Architecture menu

Presented as **families** so the conceptual structure is visible. Overlaps between
families are noted rather than hidden (e.g. a depth-0 pooled MLP *is* the pool-first
linear). Each family gives: reasoning, non-trivial parameters with 1–2 recommended
values, and optional further variations.

All architectures end in 8 output scores → `argmax` (lowest-index tiebreak).

---

### Family A — Pool-first linear (the canonical clean net)

**A1. Pool-first → `Linear(8, 8)` → argmax**

- *Reasoning:* the minimal correct net and the **reference solution incarnate**.
  Global-avg-pool collapses H×W losslessly to 8 per-player scalars, then one matrix.
  Should recover **W ≈ -I**. Doubles as the broadcast-vs-vector equivalence check.
- *Non-trivial params:*
  - pooling op: **avg** (recommended) — see A-note.
  - bias: include (recommended) / exclude. Either works; -I needs no bias.
- *This is the depth-0 anchor of the pooled family (overlaps D1 at depth 0).*

**A2. `1×1 conv(8→8)` → global pool → argmax**

- *Reasoning:* the **geometry-respecting restatement** of A1 — identical function,
  expressed as a conv so weights live in the board's native shape and you can confirm
  they recover ≈ -I. Its purpose is to make the **"spatial structure is gone"** point
  visible: this is the *only* convolution in the menu, and it is deliberately
  degenerate. No 3×3, no kernel-size sweep, no multi-layer CNN — because a conv earns
  nothing on a constant field (§5).
- *Non-trivial params:* none beyond A1.

**A-note (pooling op: avg vs max).** Both are lossless on a constant channel, so on
army-only / all-alive the choice is a no-op. They **diverge under the sentinel/mask
encodings** (max ignores low values; a -1 dead channel maxes differently than it
averages). **Sweep avg vs max only crossed with the -1-sentinel and explicit-mask
encodings**; elsewhere fix avg.

---

### Family B — Pooled-vector MLP (the depth axis)

**B1. Pool → MLP(hidden layers ∈ {0, 1, 2}, ReLU) → argmax**

- *Reasoning:* the axis that tests **nonlinearity**. Stacking linear layers alone is
  still linear; the **activation** is what lets the net bend. This is the family that
  can represent the **masking notch** (score rises as army → 0, then crashes at the
  dead value) that the linear net structurally **cannot** draw.
  - depth 0 = the linear baseline (= A1).
  - depth ≥ 1 = notch-capable. **Prediction:** linear fails on 0/-1-overload + mixed;
    depth ≥ 1 crosses that gap.
- *Non-trivial params:*
  - **hidden layers (depth):** sweep **{0, 1, 2}** (core axis).
  - **width:** **fix 32** for main runs (required capacity is tiny; width mostly
    probes optimization ease, not representational need). *Optional* secondary curve
    **{16, 32, 64}** to document the "width doesn't matter on a trivial task"
    negative result. Do not cross width with everything.
  - **activation:** ReLU default; optional GELU/tanh per §3.10.
- *The headline payoff is the **depth × encoding grid**, not depth alone — depth only
  "earns its keep" exactly where the encoding made the function nonlinear.*

---

### Family C — Flatten-MLP (the hard road / inductive-bias gap)

**C1. Flatten(C·N·H·W) → MLP(ReLU) → argmax**

- *Reasoning:* refuses to collapse H×W. The net sees all `C·N·H·W` inputs and must
  **learn** that all positions within a channel are interchangeable. No built-in
  notion of the redundancy. The gap between this and pool-first (A1) is the **"how
  much does the right inductive bias matter"** measurement. Also the architecture
  where **broadcast vs vector** (§3.7) genuinely differs.
- *Diagnostic:* inspect the per-output **weight map**. Uniform-across-a-channel =
  learned the redundancy. Sparse hot pixels = memorized arbitrary positions (the
  failure to watch for).
- *Non-trivial params:*
  - **width:** width-32 first layer on a ~20×20×8 input is ~100K weights for a
    64-number task — deliberate massive over-provisioning, which is part of the point.
  - **depth:** 1–2 hidden layers.
- *Cost:* the **expensive outlier.** Accepted for now.
  - *Alternative (mention, not core):* **downsample / resize** the board for the
    flatten variant specifically to cut input dimension, at the cost of exact
    fidelity to the broadcast format.

---

### Family D — Equivariant linear (symmetry baked in)

**D1. Equivariant linear (2 parameters) → argmax**

- *Reasoning:* the argmin function treats all 8 players **identically** and needs
  **no cross-player context** (score_p depends only on player p; the comparison is in
  the final argmax). The S₈-equivariant linear maps are exactly:

  ```
  score = a · (own features) + b · (sum over all players of features)
  ```

  i.e. **2 parameters** (per feature) instead of 64. The reference solution is
  **a = -1, b = 0**. Symmetry is enforced by construction; cannot break under
  permutation.
- *Non-trivial params:*
  - with C > 1 features, this generalizes to mixing own-features vs summed-features
    across players — still low-dimensional, but a more substantive object than the
    scalar case.
- *Role:* the middle rung of the equivariance ladder (see the pedagogy doc). The
  comparison **unconstrained `Linear(8,8)` (A1) vs equivariant (D1) vs shared-φ (E1)**
  is the scientific spine.

---

### Family E — Shared per-player head (strongest symmetry constraint)

**E1. Shared φ applied per player → argmax**

- *Reasoning:* the most explicit form of "same rule, applied 8 times." One small
  function **φ: ℝ^C → ℝ** maps a player's feature bundle to their score, applied
  **independently along N**. No pooling branch (no context needed). Tends to be the
  **most sample-efficient** (almost nothing to learn). With C > 1, φ becomes a real
  learned per-player function rather than "negate a scalar," and this is the family
  that **scales most gracefully toward the real aux head** (it treats "per-player
  feature vector → score" as the primitive).
- *Non-trivial params:*
  - **φ depth/width:** start with a **linear φ** (≡ recovers -army on army-only), then
    a tiny **MLP φ (1 hidden, width 16–32)** for the nonlinear-encoding cases.

**E2. DeepSets with a context branch (deliberate overkill)**

- *Reasoning:* a shared per-player encoder **plus** a pooled-context branch feeding
  each player's score. The task is **context-free**, so the interesting result is
  whether the net **learns to ignore the context branch.** Evidence (e.g. near-zero
  weight on the pooled term) confirms the task needs no cross-player context.
- *Non-trivial params:* encoder/context widths small (16–32).

---

### Family overlap summary (stated, not hidden)

- **A1 = B1 at depth 0** (pool-first linear is the 0-hidden pooled MLP).
- **D1 and E1** are the *constrained cousins* of the A/B pooled family — same
  post-collapse per-player scalars, progressively more symmetry baked in.
- The conceptual ladder running through A1 → D1 → E1 (64 free params → 2 → shared-φ)
  is the **equivariance spine**; see the pedagogy doc for the full treatment.

## 5. On convolutions (why there is essentially only one)

On a **spatially-constant** field, convolution earns nothing: a kernel computes local
weighted sums, but every position in a channel is the same number, so a 3×3 conv
returns `(Σ kernel weights) × constant` identically everywhere — it collapses to a
scaled 1×1 conv, i.e. a per-channel linear scaling. Depth and kernel size add **zero**
representational power.

Therefore the menu contains exactly **one** convolution (A2, the degenerate 1×1
restatement of the linear baseline), and its absence elsewhere is itself a **result**:
it demonstrates that the broadcast encoding has discarded any spatial structure a conv
could exploit.

**This is a property of *this input format*, not a verdict on convolutions in
general.** The moment the input becomes raw per-tile army × owner mask (the follow-up
direction, §9), conv + global-pool becomes the natural correct architecture and
kernel/depth start to matter.

## 6. Sweep structure (what crosses with what)

A full Cartesian product would be enormous and mostly empty. The real structure:

**Primary grid (the headline):**

```
architecture (families A–E rungs)
  ×  (encoding  nested in  alive-filter)
  ×  depth (for the pooled-MLP family)
```

with encoding ∈ {explicit-mask, 0-overload, -1-sentinel (+ rescaled-gap sub-variant)}
varying **only** in the mixed-alive filter, collapsing to one case on all-alive.

**Riders (NOT full crosses):**

| Rider | Scope |
|---|---|
| loss (CE vs ranking) | narrow: clean baseline + one nonlinear-encoding case |
| width {16,32,64} | optional secondary curve; else fix 32 |
| pooling op (avg vs max) | only on -1-sentinel + explicit-mask encodings |
| order augmentation (on/off) | only on unconstrained archs (A1, C1) |
| activation (ReLU vs GELU/tanh) | only on depth ≥ 1 × tight-gap encoding |
| channels (army-only vs full obs) | army-only headline; full obs as distractor variant |
| broadcast vs vector | headline for C1 (flatten); equivalence check for A/B; N/A for D/E |

**The headline result is a grid: architecture × encoding.** The interesting cells are
"linear fails but MLP succeeds" — and they fall **exactly where the encoding made the
function nonlinear.** The story the grid tells: failures are not about capacity, they
are about whether the **encoding** made the function linear and whether the
**architecture** matched the symmetry.

## 7. Expected outcomes (predictions to check against)

| Architecture | all-alive | mixed + explicit-mask | mixed + 0/-1 overload |
|---|---|---|---|
| Linear (A1 / B1-depth0) | ✓ ~100%, W≈-I | ✓ (linear in augmented input) | ✗ (notch is nonlinear) |
| Flatten-MLP (C1) | ✓ but data-hungry | ✓ | ~ (can fit notch, more data) |
| Pooled MLP depth≥1 (B1) | ✓ (overkill) | ✓ | ✓ (notch needs ≥1 hidden) |
| Equivariant linear (D1) | ✓ + sample-efficient | ✓ | ✗ if linear φ (notch) |
| Shared-φ (E1) | ✓ + best efficiency | ✓ | depends on φ depth |
| DeepSets+context (E2) | ✓, ignores context | ✓ | depends on φ depth |

Additional predictions:
- Width returns: **flat** (capacity not the bottleneck).
- 0-overload: **most data-hungry / normalization-sensitive** (0.001-gap notch);
  rescaled-gap variant should ease this.
- Unconstrained `Linear(8,8)`: lands in the symmetric subspace `a·I + b·11ᵀ`
  reliably **only with order augmentation**; may or may not on its own.
- full obs: risk of leaning on **land as an army proxy**, breaking on
  correlation-snap frames.

## 8. Metrics and diagnostics

Labels are generated analytically, so data is effectively infinite and cheap. Exploit
that.

**Accuracy reporting (tie-aware — required):**
- **Full-set accuracy** (vs canonical lowest-index label).
- **Strict-margin accuracy** — restricted to frames where the gap between smallest and
  second-smallest alive army exceeds ε. *This is the honest measure of whether the
  comparator was learned*; the full-set number folds in tiebreak luck.
- **In-set accuracy** — whether the predicted player is **in** the true argmin set
  (not just == canonical index).
- **Report the exact-tie fraction** so the effect size is visible (**measured ~12.7%
  on probe_500** — large enough that full-set accuracy sits materially below in-set /
  strict-margin from tiebreak luck alone, so those two are the honest measures).

**Learning / generalization diagnostics:**
- **Sample-complexity curve:** accuracy vs number of training frames.
- **Extrapolation:** train on one regime, eval outside it —
  - army range (train low armies, eval high),
  - board size (meaningful for flatten under broadcast; trivial for pooled/vector),
  - *(player count is fixed at 8, so not an extrapolation axis here).*
  Separates "learned the function" from "memorized the regime."
- **Error vs margin:** plot error rate against the smallest/second-smallest gap;
  errors should concentrate at small gaps. Sharpness of the learned comparator.
  *Note the margin distribution is bimodal — opening near-ties vs late-game
  blowouts/zeros — so which game phase you sample dominates this curve.*

**Weight-inspection diagnostics:**
- **Linear recovery:** confirm `Linear(8,8)` → **W ≈ -I**.
- **Symmetric-subspace check:** does the learned matrix land in `a·I + b·11ᵀ`? (the
  "where does symmetry come from" measurement, cross-cut with order augmentation).
- **Flatten weight map:** uniform-within-channel (good) vs sparse hot pixels (memorized).
- **DeepSets context weight:** near-zero ⇒ task confirmed context-free.

## 9. Closing note — relation to the real aux head (do not over-constrain)

These experiments deliberately isolate the **cross-player comparison / argmin** step
and hand the per-player totals to the network precomputed (broadcast constants). They
**bypass spatial aggregation entirely** — the network never derives a per-player total
from the board, because we precomputed and smeared it.

This is intentional and correct as a **first rung**: it confirms whether the
comparison step is or isn't the problem. But it means a uniformly green result here
would *not*, by itself, explain an aux-head failure whose true difficulty lives
**upstream in spatial aggregation** (deriving per-player features from raw tiles).

Therefore:

- Keep the implementation's architecture/encoder code **modular** so a follow-up can
  swap the broadcast-scalar input for **raw per-tile** input (army × owner mask)
  without rewriting the training harness, metrics, or sweep machinery.
- The **shared-φ head (E1)** is the rung that most naturally generalizes toward the
  real head — keep its "per-player feature vector → score" primitive front and center.
- A likely **second set of experiments** will take these learnings toward the true
  aux head: raw-tile inputs where convolutions / tile-level pooling / DeepSets-over-
  tiles become the real contest, a harder target, and the full observation. Leave the
  door open; do not bake in assumptions (fixed broadcast format, no-conv) that would
  block that bridge.

Concrete questions that follow-up work should pin down before bridging: what the aux
head's **input** actually is (raw tiles vs something pooled), what its **harder
target** is, and its **failure mode** (loss plateau vs trains-but-generalizes-badly vs
