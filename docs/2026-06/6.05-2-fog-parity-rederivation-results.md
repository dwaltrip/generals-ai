# Fog-parity independent re-derivation

## 1. Summary

`training/tests/test_fog_parity.py` is the correctness oracle for the fog-memory logic (`init_memory` / `step_memory`): it drives two synthetic games through the memory updates and pins the running state at checkpoint ticks. A test is only as trustworthy as its expected values, so those checkpoints were re-derived independently — to confirm they're correct, not merely self-consistent.

The re-derivation ran in a separate session given **only** the game-mechanics reference and the scenario prompt ([`6.04-5-fog-parity-rederivation-prompt.md`](./6.04-5-fog-parity-rederivation-prompt.md)); the test file and all source code were withheld. From those inputs alone it computed, by hand, the evolving fog-memory state for:

- **Scenario A** — expanding-vision trajectory on a 5×6 board; checkpoints t=0, 2, 5, 6, 7.
- **Scenario B** — a visible → fogged → re-seen transition on a 3×4 board; checkpoints t=0–3.

**Result: full parity.** Every independently-derived field value matches the corresponding assertion in `test_fog_parity.py`, and the test passes 7/7 against the live code. Doc, test, and implementation all agree.

**Coverage boundary:** both fixtures use perspective = slot 0, so canonical-channel mapping for non-zero perspective slots is exercised by neither the test nor this re-derivation (a follow-up noted in the test's docstring).
