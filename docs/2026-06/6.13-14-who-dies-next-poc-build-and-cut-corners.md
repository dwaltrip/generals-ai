# who-dies-next PoC — build notes and cut-corners ledger

**Date:** 2026-06-13

**Description:** What landed in the first who-dies-next implementation pass (the `next_death` elimination-head variant from [`6.13-12`](6.13-12-who-dies-next-target-reframe.md) / [`6.13-13`](6.13-13-who-dies-next-poc-plan.md)), and a thorough ledger of every corner cut to get a runnable + dump-producing PoC out the door fast. This is the follow-up worklist: read it before launching the first run and before reading its results. Nothing here is a blocker for *training*; several items are blockers for a *legible read*.

## What landed

End-to-end plumbing for a second elimination-head variant, selected by config and coexisting with the time-bin head:

- **Config** — `elim_head_enabled` (bool) was folded into `elim_head_variant` (`None` | `"time_bin"` | `"next_death"`); `None` is the off state, the single gate. `LEGACY_ARCH` pins `variant=None`; `_arch_for_load` migrates the retired bool on old checkpoints (`enabled → "time_bin"`).
- **Heads** — `EliminationHead` → `ElimTimeBinHead` (`heads/elim_time_bin.py`); new `ElimNextDeathHead` (`heads/elim_next_death.py`): `Conv2d(C→8) → masked lse pool → [B, 8]`. The masked mean/lse pools were extracted to `heads/pool.py`, shared by both.
- **Target** — `_next_death_target` off the existing per-game death precompute: the soonest-death alive channel is the victim; the alive mask is the softmax domain; winner-tail frames (no future death) get `target = -1` (CE `ignore_index`). `_ElimCtx` now carries the winner sentinel.
- **Loss** — masked cross-player CE at `lambda_elim` (shared with time_bin — the variants are mutually exclusive), hard CE only. Accumulator + summary carry `next_elim`.
- **Eval/dump** — raw columns `next_elim_probs` / `next_elim_target` / `next_elim_alive_mask` / `next_elim_dt` dumped so the deferred diagnostics are computable offline without a re-run. Only the `next_elim` loss is surfaced in-loop.
- **Tests** — head shapes + isolated state_dict keys (both variants), the lse finite-β-grad guard, target extraction (soonest-death / winner-tail mask / tie convention), the checkpoint migration shim. Full suite green (326).

## Cut corners / deferred — the worklist

### Diagnostics & baselines (the legibility gap)

1. **No in-loop `next_death` meter.** Only the `next_elim` loss rides the val pass. None of the plan's diagnostics are implemented in-loop: top-1 next-victim accuracy, confidence-ramp, horizon-stratified accuracy, self-vs-opp split, collapse check. **All are computable offline** from the dumped raw columns (join on `frame_info`'s `persp_val_index` + `frame_t`). TODO: write an offline analysis module mirroring `analysis/elim_metrics.py`.
2. **Confidence-ramp / memorization diagnostic not built.** This is the *key safety check* — does prediction confidence sharpen as the next death nears (genuine), or is it flat-confident from frame 1 (fingerprinting the piecewise-constant label)? The horizon (`next_elim_dt`) is dumped; the analysis that reads it is not written. Build it before trusting a "do-no-harm" read.
3. **No collapse alarm in-loop.** Prediction entropy isn't surfaced; check offline from `next_elim_probs`. A cheap in-loop entropy meter is worth adding if we keep iterating.
4. **Neither heuristic baseline is implemented** — lowest-total-army ("who's weakest", level) and most-negative per-tick army-delta ("attacked hardest", rate; Daniel's pick). They are *model-free* (computed from sim ground-truth), so they need no training run, but they are the legibility anchor the head must beat. The army-delta baseline's **smoothing window K** is unset (per-tick delta is noisy) — Stage 0 sets it.
5. **Open decision (Daniel deferred):** block the first run on baselines, or compute them after? Either way the offline join (dump head-preds ⋈ Stage-0 baseline-preds + truth, on `persp_val_index`/`frame_t`) needs a Stage-0 producer that doesn't exist yet.

### Stage 0 & the input gap

6. **Stage 0 corpus measurement skipped entirely.** The plan calls for measuring the two baseline accuracies, the marginal over the next-victim channel, and the time-to-next-death distribution (which fixes the horizon-stratification bins *and* the baseline-#2 smoothing window). We went straight to Stage 1 plumbing. Do this before/alongside the first read.
7. **No opponent army-*rate* channel — confirmed input gap, not acted on.** `constants.py` carries opp army *level* (`opp_N_army_count`), land level, and land *rate* (`opp_N_land_delta`), but **no opp army-delta**. So the "attacked hardest" signal is computable for eval (ground-truth) but the *model* can't see opponent army-rate directly (only the land-rate proxy + visible dense-history). If Stage 0 shows army-rate is the stronger predictor, adding 7 `opp_N_army_delta` channels is a cheap, scale-free lever worth doing before/alongside the PoC. Not done.

### Config & architecture knobs

8. **Param scoping is still flat.** `elim_pool` / `elim_bin_edges` / `elim_head_hidden` remain top-level `ModelConfig` fields that are now time_bin-only; `next_death` ignores them (documented, not enforced). The clean per-head scoped sub-config is a deliberate TODO — config is where we chose not to sprint.
9. **`next_death` pool hardcoded to lse.** No `pool` knob on the new head (Daniel chose lse; door left open). `masked_mean_pool` exists in `pool.py` but isn't wired to `next_death`. Thread a knob when we want to A/B mean.
10. **`next_death` has no pre-pool capacity knob** (the time_bin head's `elim_head_hidden`). It's single-conv only. Add capacity if the readout underfits.
11. **`elim_target_tau` / `elim_bin_weights` are silently inert for `next_death`.** They're time_bin-only; nothing forbids setting them on a next_death config (they'd just do nothing). Consider validating-or-documenting. Also `lambda_elim`'s `LossConfig` comment and `train_config` doc still reference 6.13-5 (time_bin); the knob now serves both — minor doc debt.
12. **`elim_bin_edges` still required for `next_death`.** The dataset uses the edges only to size the winner sentinel for the next_death precompute — an indirect coupling. The default edges suffice; documented, but not conceptually clean.

### Loss & target details

13. **No label smoothing on `next_death`.** Hard CE only, per plan (start hard, watch the ramp, add uniform smoothing only if it fingerprints). The memorization mitigation is *not* wired — it needs a new path if the ramp diagnostic shows fingerprinting.
14. **Tie convention differs from the doc.** Ties (two deaths at the same tick) resolve to the **lowest canonical channel index** (`argmin` first-min), not the plan's "first `death_events` row." Deterministic and documented; rare. Worth a glance from Daniel — the related winner-tail edge he already called "anything fine there," but ties weren't explicitly discussed.
15. **Self always in the softmax** (plan default). Not A/B'd against excluding self.

### Testing

16. **No end-to-end training smoke test through `train.py` for `next_death`.** Covered: forward/backward, head shape, target extraction, config, checkpoint migration. Not covered: a full mini training loop with the variant on (existing train smoke tests run no-elim or time_bin).
17. **The new dump-capture branch isn't unit-tested** (`test_eval_dump.py`) — exercised only via the manual smoke test. The in-training dump-vs-val `next_elim` cross-check (train.py) is likewise only lightly exercised.

### Run sequence (not started)

18. **No run launched.** The PoC cell config (sub_5k, `lambda_elim=0.15`, `next_death`, lse) isn't written; nothing kicked off. Pool=lse and 5k are decided; baseline strategy + Stage 0 are the open pre-launch items.
19. **Stage 2 (24k trunk transfer) deferred** — the actual bet (does the head enrich the trunk for the value head), gated on a promising Stage-1 read, to be run with a shuffled-target control for attribution.
