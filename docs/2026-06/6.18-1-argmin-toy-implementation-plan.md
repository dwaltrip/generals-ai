## 0. Scope & framing

The toy task: from one frame, return the index of the alive player with the smallest army. Ground truth is analytic, so the study is *how* SGD finds the clean solution and how that depends on input encoding and architecture — and, instrumentally, whether the argmin step is the aux head's bottleneck (6.17-1 §9).

Three framing commitments shape everything below:

- **MVP population = filter surrendered frames.** "Dead" is not binary: a *surrendered* player is out of the game (the elim-based `alive` mask reads False) yet still holds real army on the board for a fixed capture window before their tiles convert to neutral. On `probe_500` val this is ~3.7% of frames (495/13344); the live side is clean (`alive ⟹ army ≥ 1`, global min exactly 1.000). Filtering frames that contain any surrendered slot (`~alive & army>0`) leaves a clean **alive/eliminated binary** where every dead player is genuinely at army 0 — and the full 6.17-1 §3.5 encoding ladder (explicit-mask / 0-overload / −1-sentinel) is faithful exactly as written, notch and all. Surrender handling is an early follow-up (§12), not the MVP.
- **Unmasked loss and decision.** The model argmaxes over all 8 logits and is trained with plain cross-entropy over all 8; we never apply the `alive` mask as `−inf` to the model's outputs. External masking would do the dead-player exclusion *for* the model — collapsing the encoding axis and erasing Claim 1 (the notch). This corrects 6.17-4 §4's `reuse masked_cross_player_ce` instruction. Full treatment in **Appendix A**.
- **fq for data, own loop for training.** fq materializes one columnar table; a small table-reading loop trains over it (not the probe `ProbeCache` path — the toy's player-axis models take real inputs, not a `(feats, aux)` head contract). The loop is the minimal seed of the 6.17-3 training engine, deliberately not over-built.

Tags below: `[new]` = code to write, `[reuse]` = existing code.

## 2. Data layer — the fq table

- `[new]` **`LAND_SIM` deriver** — mirrors `ARMY_SIM` / `army_totals_per_tick`, summing owned *tiles* (`(own==s).sum`) instead of army. Same `per_game` shape, indexed per frame via `raw_order`.
- `[new]` **toy `FrameTableSpec`** — `dataset_kwargs = dict(emit_alive_mask=True, include_frame_info=True, unsafe_attach_sim_frame=True)` (all three: `emit_alive_mask` for `alive`, `include_frame_info` for `frame_t`/`sample_idx` that `build_frame_table` needs, `unsafe_attach_sim_frame` for the sim the army/land derivers read — 6.17-4 named only the first); `emit_cols={"alive_mask": "alive"}`; `derivers=[ARMY_SIM, LAND_SIM]`; `derived_cols={"label", "margin", "n_alive", "argmin_set"}`.
- `[reuse]` `ARMY_SIM` (exact int64 ground truth), `lowest_army_victim` → `label` (lowest-index argmin over alive), `bottom_two_margin` → `margin` (both in `families/elim_head_debug.py`), `build_frame_table` + `GROUND_TRUTH_OBS_CFG`.
- `[new]` derived cols: `n_alive = alive.sum(1)`; `argmin_set` = `[N,8]` bool membership in the alive-argmin set, needed for in-set accuracy (6.17-1 §1.4 / §8 — the canonical `label` alone can't credit a tied alternate). Computed as `masked_army == row-min` on the **raw integer-valued** army (`army_sim` is int64 sums; the encoder owns `/1000`, so `==` is exact — do not move normalization upstream of this), dead slots `False` by construction. `label`, `margin`, and `argmin_set` all key off this one masked-army definition, so the tie boundary is shared (Risk #6).
- **Columns (one row per frame):** `army[8]`, `land[8]`, `alive[8]`, `label`, `margin`, `n_alive`, `argmin_set[8]`, `game_id`. **Army and land are in raw units; the encoder owns the `/1000` normalization** (so `margin`'s ε is in raw-army units).
- `[new]` **`to_tensors`** (cols → torch) and **`split_by_game`** (partition on `game_id`, not perspective — a frame's target is a pure function of `(army, alive)`, so adjacent ticks in a game are near-duplicate `(input, label)` pairs; a game-level split prevents that leakage).
- Build the table **once** from the manifest's val split (§8), apply the surrender filter, then `split_by_game` into train/val sub-splits. For these tiny models val-accuracy ≈ train-accuracy is expected; the split is hygiene against degenerate memorization, not a hard generalization test.

## 3. Encoder

`[new]` pure function `encode(army, land, alive, cfg) -> Tensor`, called inside `model.forward` so one cached table feeds every variant (the cache only busts when the frame *population* changes — extrapolation regimes / synthetic data, both deferred).

`EncoderCfg` axes (the 6.17-1 §3 sweep surface):

- `encoding ∈ {explicit_mask, zero_overload, neg1_sentinel}`, plus a `gap_scale` float on `zero_overload` for the rescaled-gap sub-variant (kept one flag away as insurance — see §9).
- `channels ∈ {army_only, army_land}`.
- `layout ∈ {vector, broadcast}`.

**MVP = `army_only`, `vector`.** Output shape `[B, 8, C]` (batch × player × per-player feature) — the player axis stays explicit (6.17-1 §3.3). Broadcast (`[B, 8, C, H, W]` with a synthesized spatial dim) and the flatten family are deferred; the encoder is structured so adding them is a layout branch, not a rewrite.

Encoding semantics on the filtered binary population (every dead player genuinely at army 0):

- **`explicit_mask`** → channels `[army_norm, alive]`. Pushes dead *high* effectively (`alive=0` lets the model add a big penalty), so `argmin(army + (1−alive)·BIG)` is **linear in the augmented input** — linear-solvable. `BIG` is a fixed constant chosen to exceed max normalized army (asserted in the encoder test).
- **`zero_overload`** → `army_norm` as-is; eliminated players sit at exactly 0 (the smallest value, which plain `−army` *most* prefers but must never pick). Dead is *low* → the required score curve is a **non-monotonic notch** → a linear model structurally cannot draw it; depth-1 can.
- **`neg1_sentinel`** → dead overwritten to −1. Dead is low *and* linearly separable from all live (≥0); still a notch for the comparator, but the separability lets a depth-1 model carve dead out cleanly. (Overwriting army is faithful only because, post-filter, dead are genuinely 0 — see Appendix A / 6.17-1 §3.5.)

## 4. Models — the A–E families

`[new]` small modules. `ArgminModel(encoder_cfg, scorer)` wraps an encoder cfg + a scorer; `forward(army, land, alive)` runs `encode` then the scorer to `[B, 8]` logits. Decision is `argmax` with the lowest-index tiebreak (must match the label rule). `land` is threaded through `forward` from the start (unused in `army_only`, wired for the `+land` rider).

The four scorers (input `x = [B, 8, C]`):

- **A1 — unconstrained ("pool-first" linear).** Flatten to `[B, 8·C]` → `Linear(8·C, 8)`. For `C=1` this is `Linear(8,8)`; reference solution `W ≈ −I`. The depth-0 anchor and the unconstrained rung of the equivariance spine.
- **B1 — pooled-MLP, depth-1.** Flatten → `Linear(8·C, 32) → ReLU → Linear(32, 8)`. The minimal notch-capable model. (B1 at depth 0 = A1.)
- **D1 — equivariant linear.** `score_p = A·x_p + B·Σ_q x_q`, `2C` params (`C=1` → 2 scalars); reference `A ≈ −1, B ≈ 0`. Permutation-equivariant by construction.
- **E1 — shared-φ.** `φ(x_p)` applied per player, φ shared; linear φ → `w ≈ −1`; a tiny MLP φ (1 hidden, width 16–32) for the nonlinear encodings. The context-free rung that bridges toward the real aux head (6.17-1 §9).

Reference solutions above are `C=1` (army-only); the `+land` rider extends D1 to a 2×2 own/sum mix and φ to `ℝ²→ℝ`.

Per-model **`.inspect() -> dict`** (the weight-inspection interface is architecture- *and* encoding-aware, since "the matrix" only exists for A1/`C=1`):

- A1 → `{W, sym_subspace_residual}` (the `a·I + b·11ᵀ` projection residual);
- D1 → `{A, B}`; E1 → `{w}` (linear φ) or `None` (MLP φ);
- B1 → `{}` (no clean `W` — an MLP; weight inspection N/A).

The equivariance spine A1 / D1 / E1 shares A1's per-player scalars; D1/E1 are tiny.

## 5. Training loop — the engine seed

`[new]` **table-reading loop** (~40 lines). Reads `(train_view, val_view, role_assignment, model, hparams)` where:

```
role_assignment = {
    "inputs": ["army", "land", "alive"],   # -> model(*inputs)
    "target": "label",
    "aux":    ["alive", "margin", "argmin_set"],   # for metrics
}
```

AdamW, per-epoch train/val eval, returns per-epoch curves (entry 0 = pre-training baseline) mirroring `train_probe_head`'s conventions so output stays comparable with probe runs. **Loss = plain `F.cross_entropy(scores, label)` over all 8 logits — unmasked** (Appendix A). Every frame has a valid label (≥1 alive player always), so no `ignore_index` is needed. Hyperparam defaults: AdamW (`weight_decay=1e-4`), `lr=1e-2`, `batch_size=256`, `epochs=200` — a starting point, not a finding; `zero_overload` may need more epochs to resolve represent-vs-optimize (Risk #3).

This is the *seed* of the 6.17-3 table-reading engine — a table view + an explicit role-assignment rather than hardcoded `army`/`alive`. It is deliberately **not** `ProbeCache` and **not** the device-bundle abstraction: a dict of column names and a loop, promotable later only if the P4 (real-aux-head) consumer pulls it. Holding that scope line is itself a goal (6.17-3 §1, §7). The cached tensors are tiny (`[N,8]`), so device residency is a non-issue; follow the simple CPU-table + per-batch-move path.

## 6. Metrics & diagnostics

`[new]` **tie-aware accuracy** (decision = `argmax` over all 8, lowest-index tiebreak, matching the label rule — `torch.argmax`'s own tiebreak rarely fires since continuous logits ~never tie exactly; the genuine ambiguity is in the label, where the *armies* tie):

- **full-set** — `argmax == label` (canonical lowest-index).
- **strict-margin** — full-set restricted to frames with `margin > ε`. The honest comparator measure; the plain number folds in tiebreak luck. ε is a threshold on the **raw-army** `margin` column (ε=0 excludes only exact ties; ε≥1 excludes the minimal-gap tail), independent of the encoder's `/1000`.
- **in-set** — `argmax ∈ argmin_set` (credits identifying *a* true minimum).
- **exact-tie fraction** — `mean(margin == 0)` over frames with ≥2 alive. **Measured ~12.7% on probe_500** — *not* the low-single-digit % earlier assumed; ties are early-game, so expect similar magnitude elsewhere. Large enough that **in-set and strict-margin are the load-bearing measures**: full-set running ~10% below in-set is the expected tie gap (a model ranking tied players in any order), not a representational failure. Frames with `n_alive < 2` (`margin = −1` sentinel; 7 on probe_500) fall out of the margin-gated metrics and this denominator by construction, with exactly one `True` in `argmin_set`.
- **error-vs-margin curve** — error rate binned by `margin`; errors should concentrate at small margins. Sharpness of the learned comparator.

`[new]` **weight inspection** via `.inspect()`: A1 `W ≈ −I` recovery and the symmetric-subspace `a·I + b·11ᵀ` residual; D1 `(A,B) ≈ (−1,0)`; E1 `w ≈ −1`. All reference values are in **normalized units** (the encoder's `/1000` runs inside `forward`). The weights *are* the experiment for the symmetry question.

All metrics are **unmasked** — if a model picks a dead player it counts as wrong, which is the honest read of whether the encoding taught exclusion (masking would hide exactly the failure we study).

## 7. Driver & the first-slice grid

`[new]` `run.py`: build the table once → surrender filter → for each cell, `to_tensors` + `split_by_game`, train, eval, `.inspect()`. The grid (6.17-4 §6):

- **all-alive** (`n_alive == 8`): encodings collapse (no dead to encode), so **1 encoding (army-only) × 4 models = 4 runs** — the linear oracle, `W ≈ −I` with no confound.
- **mixed** (`n_alive < 8`, surrender-filtered): **3 encodings × 4 models = 12 runs** — where the encoding bites.

**≈ 16 tiny runs on cached 8-vectors, seconds each.** **Seeds:** the overload encodings (`zero_overload`, `neg1_sentinel`) × the notch-capable models (B1-depth-1, E1 with MLP φ) run **≥3 seeds**, so a depth-1 failure isn't read as a single seed missing the notch (Risk #3); one seed elsewhere. Outputs: structured **JSON** (full per-cell curves + metrics + `.inspect()` dumps) and a streamed human-readable **log** (per-epoch lines + run summaries), borrowing the probe `summary.json` field conventions where they fit.

The cell the instrumental goal needs: clean **A1 / mixed + explicit-mask** recovering `W ≈ −I` at ~100% strict-margin ⇒ the argmin step is *not* the aux-head bottleneck ⇒ next round pivots upstream to spatial aggregation.

## 9. Risks (ranked)

1. **Unmasked loss/decision (Appendix A).** The experiment is only meaningful unmasked; masking collapses the encoding axis and erases Claim 1. Corrects 6.17-4 §4. *Highest — it's the spine.*
2. **Encoder correctness *is* the experiment.** A silent encoding bug doesn't crash — it produces a clean-looking wrong result, and the headline *is* a comparison across encodings. The encoder test (§10) is load-bearing: assert each cfg against a hand-computed tensor; prove `BIG` exceeds max army; keep `/1000` in exactly one place.
3. **Optimization vs representation on the notch.** A *negative* depth-1 result on `zero_overload` is ambiguous — "can't represent" vs "SGD didn't land it in the 0.001-wide band." Funded with **≥3 seeds** on the overload × notch-capable cells (§7) so a single seed missing the notch isn't read as a representational failure. The rescaled-gap control (separates encoding-bad from scaling-bad) is a rider, so keep `gap_scale` one flag away and run it iff depth-1 fails. A *positive* result is clean and needs no control.
4. **Weight-inspection interface** is architecture- and encoding-aware (no single `W`); the `.inspect()` hook (§4) keeps it per-model rather than the driver reaching into internals.
5. **Engine-seed scope discipline.** The loop is the seed of a future unified engine; the risk is over-building it now. Keep it a table-view + role-assignment + loop, nothing more (6.17-3).
6. **Tie-semantics consistency.** Label (numpy argmin, lowest-index), decision (`argmax`), margin, and `argmin_set` must all key off the same tie definition (exact-equal masked army), or the three accuracies disagree spuriously.
7. **alive↔army coupling — resolved.** The encoding ladder rests on `alive ≡ (army>0)`, which holds only after the surrender filter restores it on the MVP population — listed so the dependency is explicit, not because it's unhandled.
8. **probe_500 small-margin tail is thin** for the strict-margin read the bottleneck decision rests on — make the *decision* on the `cloud_24k_sub_5k` re-run, not probe_500.

## Appendix A — The masking decision, in detail

The single load-bearing implementation choice: the toy is **unmasked**. This appendix explains what that means, why it's required, and where the `alive` signal legitimately enters — because 6.17-4 §4's `reuse masked_cross_player_ce` would have quietly broken the experiment.

### What masking is, mechanically

A model outputs 8 logits, one per slot: `scores = [s₀, …, s₇]`. Two consumers:

- **decision:** `prediction = argmax(scores)`.
- **loss:** cross-entropy, which softmaxes first — `pᵢ = exp(sᵢ) / Σⱼ exp(sⱼ)` — then `CE = −log(p[label])`.

"Masking" overwrites dead players' logits with `−inf` (via the external `alive` mask) before either step: `masked = scores.masked_fill(~alive, -inf)`. Since `exp(−inf)=0`, a masked player gets probability 0 — can never be the argmax, and drops out of the softmax denominator. It is a hard external override, independent of what the model actually computed.

### Why it's right for the probe and wrong for the toy

`masked_cross_player_ce` was built for the **who-dies-next** head, whose question is "among the *currently-alive* players, which dies next?" There the alive set is a *given*, part of the question; masking dead players correctly focuses probability on legitimate candidates, and prod does exactly this.

The toy's question is the opposite: **can the model learn to exclude dead players, and how does that depend on how "dead" is encoded?** Exclusion *is* the object of study. Handing the model the alive mask at decision time does the exclusion for it — nothing left to measure. The notch pedagogy (6.17-2 Decision 4) only exists because the model must infer exclusion from the army value alone.

### Worked example

A 3-player mixed frame (raw army, ÷1000 normalized):

| player | army | norm | alive | |
|---|---|---|---|---|
| p0 | 500 | 0.500 | ✓ | |
| p1 | 3 | 0.003 | ✓ | ← true label |
| p2 | 0 | 0.000 | ✗ | eliminated |

Run the clean linear solution `score = −army` (reference `W = −I`) under `zero_overload`:

- `s0 = −0.500`, `s1 = −0.003`, `s2 = 0.000`.

**Unmasked** `argmax` → `s2 = 0.0` (largest) → predicts **p2 (dead)**. Wrong — and wrong *by design*: dead-at-0 is the value `−army` most prefers, but must never be picked. That requires a non-monotonic notch (prefer small army, crash at exactly 0) a straight line cannot draw and one ReLU layer can. **This is Claim 1.**

**Masked** (`s2 → −inf`) → `argmax` → `s1` → predicts **p1 (correct)**. The *same failing linear model now passes* — the mask did the exclusion, not the model. Linear "succeeds" on `zero_overload`, `explicit_mask` becomes redundant with it, the encoding axis measures nothing, and Claim 1 evaporates.

The unmasked grid is what we want:

- `zero_overload`, linear → picks p2, **fails** (as designed);
- `zero_overload`, depth-1 → learns the notch → **succeeds**;
- `explicit_mask`, linear → with `[army, alive]` learns `score = −army + BIG·alive` → `s1 = BIG−0.003` wins → **succeeds with linear**.

That divergence is the headline result. Masking erases it.

### The loss side too

Under **unmasked** CE (label p1): `CE = −log( exp(s1) / (exp(s0)+exp(s1)+exp(s2)) )`. To minimize, the model must make `s1 ≫ s0, s2`. A linear model has `s2 = 0` sitting high in the denominator and structurally cannot push it down while keeping `s1` high (armies 0.000 ≈ 0.003) → the loss hits a **floor**, which *is* the representational failure showing up in the curve. A depth-1 MLP carves the notch and drives CE → 0.

Masking the loss drops `s2` from the denominator, and the linear model minimizes it trivially — no floor, "learns" it. The unmasked loss is exactly the learning pressure the experiment studies; loss and decision must both be unmasked to stay coherent.

### Where `alive` legitimately enters

Not banned — used precisely:

1. **label computation** — `label = argmin over alive` (offline, in the deriver);
2. **the `explicit_mask` encoding** — `alive` as an *input channel* the model processes (faithful encoding, not an output override);
3. **metric context** — margin and tie-set computed over alive (offline).

Never: `alive` as `−inf` on the model's *output logits* at train or eval time.

### Why this isn't a departure from the design

6.17-1 is already written assuming unmasked: §2's reference `−army → argmax` works "in the clean representation" and §7 predicts it *fails* under overload encodings — failures that exist only unmasked. §3.8 specifies CE "over 8 logits." The "handed the clean alive signal" case isn't lost; it's the `explicit_mask` rung. So unmasked + the encoding ladder *subsumes* the masked scenario as one rung instead of collapsing every rung into it. Only 6.17-4's reuse line — a copy-paste from the probe scaffolding — slipped.
