## Notes for sequencing (suggestions, not a plan)

- Display-layer freebies before the historical analysis — best-epoch `val_value` and the gap column are exactly the lenses that analysis needs.
- Floors are split properties, so cross-run comparison requires the per-manifest marginal entropy next to each run's numbers. We want an easy way to get the floor for any manifest — `scripts/marginal_entropy.py` is the starting point.
- "Computable with existing data" has three tiers: (a) from existing `epochs.jsonl` (display-layer), (b) manifest-only (floors), (c) forward pass over val with an existing checkpoint (policy entropy, value-collapse check) — (c) needs no training re-runs, just an offline eval pass.
- Variant archaeology: modern checkpoints embed `arch`; legacy checkpoints don't — their variant lived in the run config in the run dir (see `bc/checkpoint.py` docstrings).
