# fq analysis-toolkit MVP — build session

**Date:** 2026-06-16

Built the `fq` MVP on branch `fq-mvp` against the [`6.15-3`](6.15-3-fq-analysis-toolkit-design.md) design, after resolving the three open design questions and doing a prerequisite cleanup of `dataset.py`. Two commits: the `bc/targets/` extraction, then the fq package.

## Prerequisite: target logic out of `dataset.py`

`dataset.py` had accreted ~110 lines of target-computation that isn't plumbing, and `who_dies_next_baselines` was reaching into its privates (`_ElimCtx`, `_next_death_target`, `_precompute_elim`). Extracted both into a new `bc/targets/` package:

- `elim_targets.py` — the per-game elim precompute + per-frame target builders, de-underscored to a public API: `ElimCtx`, `precompute_elim`, `alive_mask`, `next_death_target`, and `_elim_targets` → `time_bin_targets` (renamed to avoid colliding with the module name and to parallel `next_death_target`).
- `core_targets.py` — `value_target` and `policy_pass_target`, pulled from `encode_frame`'s tail, leaving that tail as pure tensor-packing.

`who_dies_next_baselines` and `test_dataset` repoint onto the public API. Pure move + rename, no behavior change; the dataloader smoke test + the elim-target unit tests cover it.

## The fq package — `training/analysis/fq/`

- `derivers.py` — `Frame` (the deriver-facing view), `Deriver`, `per_game` (caches `prepare(sim)` on an explicit per-game token, not `id(sim)`), the canonical `army_totals_per_tick`, and `ARMY_OBS` / `ARMY_SIM`.
- `frame_table.py` — `FrameSpec`, the dumb `FrameTable`, `select`, `cap_by_games`, `build_frame_table` (asserts `shuffle_buffer_size=0` and the axis-0 invariant), and the opt-in `check_representative` guard.
- `families.py` — the `ELIM_HEAD_DEBUG` family, the `lowest_army_victim` / `bottom_two_margin` derived columns (the lowest-army rule as a computed column, matched to the eval frames by construction), and the `--table` registry.
- `cli.py` — `-e` expression and stdin-snippet modes.

## Design questions resolved

- **Q2 (deriver shape):** keep two mechanisms — `emit_cols` for quantities the dataset's encode path already computes (alive/victim/dt), `derivers` for quantities computed from the `Frame` (army). No multi-column derivers and no dataset-fields-as-derivers: the provenance split (copied-from-dataset vs. derived-from-sim) is worth keeping visible, and forcing uniformity would either duplicate the dataset's target logic or relocate it for no gain. Trigger to revisit: two derivers wanting the same expensive `prepare`.
- **Q3 (`check_representative`):** helper-only. No build-time warning or auto-surfacing — not enough established usage to justify the machinery; add it if a pattern demands it.
- **Q10 (naming):** `FrameView` → `SimFrame` (it holds sim-domain data + indices; `Frame` is that plus encoded obs — the same sim-vs-obs axis as the `army_sim`/`army_obs` derivers), and the enabling flag → `unsafe_attach_sim_frame` (named to deter accidental use: the attached numpy dicts are non-collatable and break any DataLoader path). `Frame`, `Deriver`, `FrameSpec`, `FrameTable`, `fq` kept.

Single-source army: `_army_totals_per_tick` was a private in `who_dies_next_baselines`; promoted it to `fq.derivers.army_totals_per_tick` and repointed the script, so the two never ship divergent army logic (the root of the 6.14-1 baseline mismatch).

CLI end-to-end — the Tier-1 read as a stdin snippet, no script file:

```
uv run python -m training.analysis.fq.cli --table elim_head_debug --split val \
    --manifest data/training/splits/poc_2kish_perspecs.json --max-games 15 <<'PY'
imm = select(t, (t.cols['dt'] >= 0) & (t.cols['dt'] < 10))
flat = t.cols['army_sim'][t.cols['alive']]
print(f"alive army: mean {flat.mean():.0f}  median {np.median(flat):.0f}  max {flat.max():.0f}")
print(f"imminent frames {imm.frame_t.size} / {imm.n_games} games")
vmask = imm.cols['victim'] >= 0
rule = (imm.cols['low_army_victim'][vmask] == imm.cols['victim'][vmask]).mean()
print(f"lowest-army RULE top1 (imminent): {rule*100:.1f}%")
PY
```

```
built 'elim_head_debug' [val]: 7461 frames / 15 games  cols=['alive', 'victim', 'dt', 'army_obs', 'army_sim', 'margin', 'low_army_victim']
alive army: mean 355  median 101  max 4146
imminent frames 758 / 15 games
lowest-army RULE top1 (imminent): 45.0%
```

The 45.0% (15 games) is a small-sample sanity check, consistent with the design doc's ~48% at 100 games — not a precise reproduction.
