# Fog-memory re-derivation spec (`test_fog_parity`)

## Goal

A fresh agent independently re-derives the expected fog-memory state at each checkpoint tick from the game trajectory alone, with no access to the implementation or existing test. We compare its answers to what the test asserts; disagreements flag a possible correlated bug (code + test agree but are both wrong), a derivation error, or a spec ambiguity.

## How it works

Two documents:

- **This spec** (not shown to the agent): describes the testing intent, the design philosophy of the prompt, and the full answer key with derivations.
- **The prompt doc** (`6.04-5-fog-parity-rederivation-prompt.md`): everything the agent sees. Contains two scenarios' boards and trajectories, the shared memory-update rules, checkpoint instructions, and flagged conventions. References `docs/generals-io-game-mechanics.md` for fog-of-war and structure-visibility rules.

### Prompt design principles

Same principles as the BFS-passability rederivation:

- **No visibility giveaways.** The prompt never states which cells are visible or fogged — the agent derives vision from ownership + Moore-neighborhood rules in the mechanics doc.
- **No pre-stated resolutions.** Checkpoint titles describe structural changes (e.g. "first structure resolutions"), not what the resolved types are.
- **Field rules are precise but answer-neutral.** Each rule states the update logic without pre-resolving any cell.
- **§8 flags reasoning traps as questions.** Scenario A's traps — stale-flag behavior, capture timing, conversion timing — are flagged for explicit reasoning, not pre-answered.
- **Scenario B is deliberately un-flagged.** Its fog-memory behavior (last_seen staleness, turns_since_seen increment/reset) gets no §8 flag and no checkpoint steer — the agent must derive the seen→fogged→re-seen arc and its memory consequences from the §3 rules alone. A cleaner independent check on the path that previously had zero coverage. (If you ever add a steering hint to §6, you've weakened this.)

## The rules under test

Fog-memory state tracking — a project-specific observation pipeline for the model, not a generals.io mechanic. Stated in full in the prompt doc §3. Ten tracked fields:

1. **historically_seen** — cumulative vision (monotonic OR).
2. **known_mountain** — mountain type resolution (requires vision).
3. **known_city** — city type resolution (requires vision + city status at that tick).
4. **known_general** — general sighting (never cleared, even on conversion to city).
5. **general_locations** — per-opponent pin on first general sighting.
6. **last_seen_owner** — fog-of-war owner memory (-2 sentinel for never-seen).
7. **last_seen_armies** — fog-of-war army memory (-1 sentinel for never-seen).
8. **turns_since_seen** — staleness counter (0 / incrementing / -1 sentinel).
9. **opp_contacted** / **opp_captured_by** — opponent contact and capture tracking.
10. **opp_has_seen** — estimated opponent vision (Moore dilation of visible opponent cells).

## Board and trajectory

**Scenario A** — Board: 5×6 with 7 mountains, 2 neutral cities, 2 generals (prompt §2). Trajectory: 8 ticks; perspective expands one cell per tick from (4,0) toward (1,4); capture at action t=6, post-capture ownership flip at snapshot 7 (prompt §4). Vision expands monotonically, so it covers structure resolution, capture/conversion timing, and the stale-flag — but never a seen→fogged transition.

**Scenario B** — Board: 3×4, no structures (prompt §6.1). Trajectory: 4 ticks; the perspective sees cell (0,3), loses the vantage that saw it, then re-sights it (prompt §6.2). This is the seen→fogged→re-seen path Scenario A can't reach: it exercises last_seen_owner/armies staleness, the turns_since_seen increment, and the reset/overwrite on re-sighting.

## Answer key — Scenario A

The expected derivations and verdicts for comparing against the agent's output.

| 1 | (4,1) | adds (3,2), (4,2) | (3,2), (4,2) |
| 2 | (3,1) | adds (2,0), (2,1), (2,2) | (2,0), (2,1), (2,2) |
| 3 | (3,2) | adds (2,3), (3,3), (4,3) | (2,3), (3,3), (4,3) |
| 4 | (3,3) | adds (2,4), (3,4), (4,4) | (2,4), (3,4), (4,4) |

- (2,5) M — first visible at t=5, in Moore((2,4)).
- (0,5) M — first visible at t=7, in Moore((1,4)).
- (0,0) — **never seen** through t=7. Would require owning (0,0), (0,1), (1,0), or (1,1), none of which are ever owned.

### Checkpoint t=0 — initial state

**historically_seen** = {(3,0), (3,1), (4,0), (4,1)}. Vision is the Moore neighborhood of the single owned cell (4,0), clipped to board bounds.

**known_mountain** = {} (all False). Visible cells are (3,0), (3,1), (4,0), (4,1); none are mountains.

**known_city** = {} (all False). Cities at tick 0 are (2,0) and (3,4); neither is in vision.

**known_general** = {(4,0)}. Self general, set in initialization. (1,4) is not visible.

**general_locations** = [24, -1]. Self known (cell(4,0)=24); opponent unknown.

**opp_contacted[OPP]** = False. No opponent cells visible.

**opp_captured_by[OPP]** = -1. No capture event.

**last_seen_owner at (0,0)** = -2 (never-seen sentinel). (0,0) is not in any owned cell's Moore neighborhood.

**last_seen_armies at (0,0)** = -1 (never-seen sentinel).

**turns_since_seen at (0,0)** = -1 (never-seen sentinel).

### Checkpoint t=2 — first structure resolutions

**historically_seen** = {(2,0), (2,1), (2,2), (3,0), (3,1), (3,2), (4,0), (4,1), (4,2)}. Cumulative: t=0 base + (3,2), (4,2) from t=1 + (2,0), (2,1), (2,2) from t=2.

**known_mountain** = {(4,2), (2,1)}.
- (4,2) resolved at t=1: visible from Moore((4,1)); ownership = mountain.
- (2,1) resolved at t=2: visible from Moore((3,1)); ownership = mountain.

**known_city** = {(2,0)}.
- (2,0) resolved at t=2: visible from Moore((3,1)); is a city at all ticks (initial city with cities_present_at=0).

**known_general** = {(4,0)}. No new generals discovered; (1,4) is far outside vision.

**last_seen_owner values:**
- (2,0) = -1 (neutral). Visible at t=2; the city is unowned.
- (0,0) = -2 (never seen). Not in any owned cell's Moore neighborhood through t=2.
- (4,0) = 0 (PERSPECTIVE). Owned by perspective, always visible.
- (4,1) = 0 (PERSPECTIVE). Owned from t=1 onward; visible from t=0.

**opp_contacted[OPP]** = False. (1,4) not yet in vision.

**opp_captured_by[OPP]** = -1. Alive.

**opp_has_seen[OPP]** = {} (all False). No opponent cells have been sighted.

### Checkpoint t=5 — opponent general discovered

**known_general** = {(4,0), (1,4)}. (1,4) enters vision at t=5 via Moore((2,4)). It is still an active general: cities_present_at for (1,4) is 7, and 7 > 5, so it is not in cities_at_t. The known_general rule fires.

**general_locations** = [24, 10]. Opponent pin set: cell(1,4) = 1×6+4 = 10.

**opp_contacted[OPP]** = True. At t=5, the perspective sees (1,4), which is owned by OPP. First sighting of an opponent cell.

**last_seen_owner at (1,4)** = 1 (OPP). Visible at t=5; ownership[5, (1,4)] = OPP.

**opp_captured_by[OPP]** = -1. Capture event is at t=6.

**known_mountain** = {(4,2), (2,1), (2,3), (4,4), (2,5)}. Accumulated:
- (4,2) at t=1, (2,1) at t=2, (2,3) at t=3, (4,4) at t=4, (2,5) at t=5.

**known_city** = {(2,0), (3,4)}. (2,0) at t=2; (3,4) at t=4 (visible from Moore((3,3)), is an initial city).

**opp_has_seen[OPP]** = {(0,3), (0,4), (0,5), (1,3), (1,4), (1,5), (2,3), (2,4), (2,5)}.
Derivation: visible_owned_by_OPP at t=5 = {(1,4)}. Moore dilation of {(1,4)}: the 3×3 block rows 0–2, cols 3–5, all in-bounds on the 5×6 board. OR'd into opp_has_seen (previously empty).

### Checkpoint t=6 — capture event processed

**opp_captured_by[OPP]** = 0 (PERSPECTIVE). Capture event [tick=6, captor=0, captured=1] fires at tick 6.

**last_seen_owner at (1,4)** = 1 (OPP). Snapshot 6 is the pre-action state. ownership[6, (1,4)] = OPP. The perspective sees this directly (vision unchanged from t=5).

**known_city at (1,4)** = False. cities_present_at for (1,4) is 7. At tick 6, 7 > 6, so (1,4) is not in cities_at_t. Not recognized as a city.

**known_general at (1,4)** = True. Same logic: (1,4) is not in cities_at_t at tick 6, so it is still an active general per is_general_now. Already marked known from t=5. No change.

### Checkpoint t=7 — post-capture state

**known_city at (1,4)** = True. cities_present_at=7, and 7 ≤ 7, so (1,4) is now in cities_at_t. Perspective has vision of (1,4) (owns it). new_city fires.

**known_general at (1,4)** = True. Stale-flag behavior. At tick 7, (1,4) IS in cities_at_t, so is_general_now excludes it — the new_general rule does not fire. But known_general was set at t=5 and is never cleared. Both known_city and known_general are True at (1,4).

**last_seen_owner at (1,4)** = 0 (PERSPECTIVE). ownership[7, (1,4)] = PERSPECTIVE. Visible (perspective owns it).

**known_mountain at (0,5)** = True. At t=7, perspective owns (1,4). Moore((1,4)) includes (0,5). First time (0,5) is visible. It is a mountain.

**last_seen_owner at (0,0)** = -2 (never seen). (0,0) requires vision from a cell at (0,0), (0,1), (1,0), or (1,1). None are ever owned. Still at the never-seen sentinel.

**opp_has_seen[OPP]** = {(0,3), (0,4), (0,5), (1,3), (1,4), (1,5), (2,3), (2,4), (2,5)}. Unchanged from t=5.
- t=6: same vision as t=5. visible_owned_by_OPP = {(1,4)} (still owned by OPP in pre-action snapshot). Moore dilation is the same 3×3 block already in opp_has_seen.
- t=7: OPP owns nothing (captured). visible_owned_by_OPP = {}. No dilation fires.

**turns_since_seen at (0,0)** = -1 (never-seen sentinel). Never-seen cells are never touched by the increment logic.

## Answer key — Scenario B

A 3×4 board (idx = row × 4 + col), no structures. The point is the fog-memory path Scenario A's monotonically-expanding vision can never reach: a cell seen once, fogged when the perspective loses its vantage, then re-sighted after its true state has changed.

### Vision at each tick

Moore-neighborhood dilation of owned cells, clipped to the 3×4 board.

| Tick | Perspective owns | Current-tick vision | (0,3) visible? |
|------|-----------------|---------------------|----------------|
| 0 | (2,0), (1,3) | (1,0), (1,1), (2,0), (2,1), (0,2), (0,3), (1,2), (1,3), (2,2), (2,3) | yes |
| 1 | (2,0) | (1,0), (1,1), (2,0), (2,1) | no |
| 2 | (2,0) | (1,0), (1,1), (2,0), (2,1) | no |
| 3 | (2,0), (1,3) | same as t=0 | yes |

- (0,3) is visible at t=0 and t=3 because it sits in Moore((1,3)); it is fogged at t=1–2 because the perspective then owns only (2,0), and Moore((2,0)) does not reach (0,3).
- historically_seen at (0,3) is True from t=0 onward (monotonic OR), at every tick — including while fogged.

### Checkpoint — cell (0,3) across all ticks

True state of (0,3): owner OPP / army 7 at t=0; neutral / army 0 at t=1–3.

| Tick | Visible | historically_seen | last_seen_owner | last_seen_armies | turns_since_seen |
|------|---------|-------------------|-----------------|------------------|------------------|
| 0 | yes | True | 1 (OPP) | 7 | 0 |
| 1 | no | True | 1 (stale) | 7 (stale) | 1 |
| 2 | no | True | 1 (stale) | 7 (stale) | 2 |
| 3 | yes | True | -1 (neutral) | 0 | 0 |

- **t=0** — (0,3) visible, owned by OPP with army 7: last_seen_owner=1, last_seen_armies=7, turns_since_seen=0 (first sighting → reset).
- **t=1** — (0,3) fogged. last_seen_owner/armies are **not** rewritten (Step C touches visible cells only), so they hold the stale (1, 7) even though the cell is now truly neutral with 0 army. turns_since_seen: in historically_seen but not in vision → increment 0 → 1.
- **t=2** — still fogged. Same stale (1, 7). turns_since_seen 1 → 2.
- **t=3** — (0,3) re-sighted (perspective retook (1,3)). last_seen_owner/armies refresh to the now-visible truth: neutral (-1), army 0. turns_since_seen resets to 0.

This is the first checkpoint in either scenario where a remembered value diverges from the cell's true state, and the only place last_seen_armies is exercised beyond the never-seen sentinel.
