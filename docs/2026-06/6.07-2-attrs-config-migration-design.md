# Design: migrate config classes to attrs

Date: 2026-06-07

## Motivation

`ModelConfig`, `ObsConfig`, and `TrainConfig` validate their fields via hand-written checks in `__post_init__`. The constraints are load-bearing data (choices, numeric bounds, even-ness) but buried in imperative code. This makes it hard for downstream tooling (eval-tools diagnostics, sweep validators) to introspect what values a field accepts without duplicating the knowledge.

The immediate trigger: loading a legacy checkpoint with the wrong `value_head_variant` produces a cryptic PyTorch `load_state_dict` error (a wall of missing keys) rather than a clear "you asked for pyramid but this checkpoint is direct." A declarative constraint system lets eval-tools read the valid choices directly from the config class and produce targeted diagnostics.

Beyond that, as the model architecture evolves (new head variants, new configurable submodules), each new structural knob will need the same validation pattern. A declarative approach scales without growing the `__post_init__` bodies.

## Decision: attrs over alternatives

Considered:
- **Hand-rolled** (`dataclasses.field(metadata={...})` + ~30-line `_validate_fields` helper). Zero dependencies, covers our vocabulary. Downside: we own the validator dispatch loop, the error formatting, and the converter pattern (obs dict coercion). No ecosystem tooling benefits.
- **pydantic v2** (`@pydantic.dataclasses.dataclass` or `BaseModel`). Rich constraint system, but automatic type coercion by default (opt-out, not opt-in) conflicts with our strict-config philosophy. Heavier dependency. `dataclasses.asdict` compatibility has known edge cases.
- **msgspec**. Constraints only enforced during deserialization, not at construction time — doesn't solve our problem.
- **beartype**. Validates at function call boundaries, not field-level dataclass construction.

**attrs** fits because:
- Built-in validators cover our exact vocabulary: `in_()`, `ge()`, `gt()`, `instance_of()`, plus composability via `and_()`.
- Converters (run before validators) map directly to our obs dict coercion pattern.
- `@attrs.frozen` gives the same immutability semantics as `@dataclass(frozen=True)`.
- Validation is opt-in and explicit — no automatic coercion, no magic.
- Lightweight: 67 kB wheel, zero transitive dependencies, pure Python.
- `attrs.asdict()`, `attrs.fields()`, `attrs.evolve()` are direct analogs of the stdlib equivalents.

The main cost: `dataclasses.asdict` / `dataclasses.replace` / `dataclasses.fields` do not work on attrs classes. All call sites must migrate to attrs equivalents. Migrating all three config classes together avoids a hybrid serialization problem (stdlib `asdict` can't recurse into a nested attrs object).

## Scope

All three config classes migrate together: `ObsConfig`, `ModelConfig`, `TrainConfig`.

Files that change:
- `training/bc/obs_config.py` — class definition
- `training/bc/model_config.py` — class definition + `build_model_cfg`
- `training/bc/train_config.py` — class definition + `from_file`
- `training/bc/checkpoint.py` — `asdict` → `attrs.asdict`, `replace` → `attrs.evolve`
- `training/bc/run_dir.py` — `asdict` calls
- `training/bc/state.py` — checkpoint save `asdict`
- `training/bc/resume.py` — no dataclass utility usage; unaffected
- `training/tests/test_checkpoint.py` — `asdict`, `replace`
- `training/tests/test_resume.py` — `asdict`
- `training/tests/test_dataloader_smoke.py` — `replace`
- `packages/eval-tools/tests/test_multiwidth_acceptance.py` — `asdict`

Not affected:
- `packages/game-runner/game_runner/viewer.py` — uses `dataclasses.replace` on its own unrelated dataclass.
- `training/shared/timing_run.py` — its own dataclass.

## Detailed design

### ObsConfig

```python
import attrs
from attrs.validators import ge, in_

OBS_DTYPES = ("fp32", "fp16")

@attrs.frozen
class ObsConfig:
    dense_history_n: int = attrs.field(validator=[ge(0)])
    obs_dtype: str = attrs.field(validator=[in_(OBS_DTYPES)])

    @property
    def obs_channels(self) -> int:
        return obs_channel_count(self.dense_history_n)

    @classmethod
    def validate_partial(cls, d: dict) -> list[str]:
        valid = {f.name for f in attrs.fields(cls)}
        return [f"unknown ObsConfig field: {k!r}" for k in d if k not in valid]
```

### ModelConfig

```python
import attrs
from attrs.validators import ge, in_

VALUE_HEAD_VARIANTS = ("direct", "pyramid")


def _positive_even(instance, attribute, value):
    if value < 1 or value % 2 != 0:
        raise ValueError(f"{attribute.name} must be positive and even; got {value}")


def _coerce_obs(value):
    """Accept a dict (JSON / checkpoint arch) or an ObsConfig instance."""
    if isinstance(value, dict):
        merged = {**attrs.asdict(OBS_CONFIG_DEFAULTS), **value}
        return ObsConfig(**merged)
    return value


@attrs.frozen
class ModelConfig:
    outer_width: int = attrs.field(validator=[_positive_even])
    middle_width: int = attrs.field(validator=[_positive_even])
    inner_width: int = attrs.field(validator=[_positive_even])
    n_outer: int = attrs.field(validator=[ge(0)])
    m_middle: int = attrs.field(validator=[ge(0)])
    m_inner: int = attrs.field(validator=[ge(0)])
    value_head_variant: str = attrs.field(validator=[in_(VALUE_HEAD_VARIANTS)])
    obs: ObsConfig = attrs.field(converter=_coerce_obs)
    H: int = attrs.field(default=H_PADDED, validator=[ge(1)])
    W: int = attrs.field(default=W_PADDED, validator=[ge(1)])

    @property
    def in_ch(self) -> int:
        return self.obs.obs_channels

    @classmethod
    def validate_partial(cls, d: dict) -> list[str]:
        valid = {f.name for f in attrs.fields(cls)}
        valid.add("in_ch")
        errors = []
        for key in d:
            if key == "obs":
                if isinstance(d[key], dict):
                    errors.extend(ObsConfig.validate_partial(d[key]))
            elif key not in valid:
                errors.append(f"unknown ModelConfig field: {key!r}")
        return errors
```

`build_model_cfg` changes from `dataclasses.replace` to `attrs.evolve`:

```python
def build_model_cfg(**overrides: Any) -> ModelConfig:
    overrides.pop("in_ch", None)
    return attrs.evolve(MODEL_CONFIG_DEFAULTS, **overrides)
```

### TrainConfig

```python
import attrs
from attrs.validators import ge, gt, in_, instance_of, optional


VALID_DEVICES = ("auto", "cuda", "mps", "cpu")
VALID_PRECISIONS = ("auto", "fp32", "fp16")


def _optional_ge(min_val):
    """Validator for Optional[int] fields: None passes, otherwise >= min_val."""
    def _check(instance, attribute, value):
        if value is not None and value < min_val:
            raise ValueError(f"{attribute.name} must be >= {min_val} or None; got {value}")
    return _check


@attrs.frozen
class TrainConfig:
    # required paths
    manifest: Path
    intermediate: Path
    run_dir: Path
    # arch
    arch: ModelConfig = attrs.Factory(build_model_cfg)
    # recipe
    epochs: int = attrs.field(default=1, validator=[ge(1)])
    batch_size: int = attrs.field(default=64, validator=[ge(1)])
    lr: float = attrs.field(default=3e-4, validator=[gt(0)])
    weight_decay: float = attrs.field(default=1e-4, validator=[ge(0)])
    seed: int = 0
    shuffle_buffer_size: int = attrs.field(default=2048, validator=[ge(0)])
    gpu: str = "T4"
    precision: str = attrs.field(default="auto", validator=[in_(VALID_PRECISIONS)])
    # operational
    device: str = attrs.field(default="auto", validator=[in_(VALID_DEVICES)])
    log_every: int = attrs.field(default=50, validator=[ge(1)])
    max_batches: int | None = attrs.field(default=None, validator=[_optional_ge(1)])
    num_workers: int = attrs.field(default=2, validator=[ge(0)])
    pin_memory: bool | None = None
    prefetch_factor: int = attrs.field(default=2, validator=[ge(1)])
    skip_val: bool = False
```

Notes:
- Fields without constraints (`seed`, `gpu`, `pin_memory`, `skip_val`) use plain defaults with no `attrs.field()` wrapper. This should work — attrs documentation shows bare defaults alongside `attrs.field(...)` declarations — but should be verified early in implementation.
- `max_batches: int | None` needs a custom `_optional_ge(1)` since attrs' built-in `ge()` doesn't handle `None`. This is the only custom validator beyond `_positive_even`.
- `from_file` and `validate_partial` translate directly — only `fields(cls)` → `attrs.fields(cls)` changes.
- `attrs.Factory(build_model_cfg)` replaces `field(default_factory=build_model_cfg)`.

### Serialization paths

Every `asdict(config)` → `attrs.asdict(config)`. The behavior is the same: recursively converts nested attrs instances to dicts.

`json_default` (the `Path` stringifier) stays unchanged — `attrs.asdict` supports a custom `value_serializer` hook, but passing `json.dump(..., default=json_default)` is simpler and already works.

### checkpoint.py changes

```python
# Before
from dataclasses import asdict, replace
arch_dict["obs"] = {**asdict(LEGACY_OBS_CFG), **obs}
return replace(LEGACY_ARCH, value_head_variant=value_head_variant)

# After
import attrs
arch_dict["obs"] = {**attrs.asdict(LEGACY_OBS_CFG), **obs}
return attrs.evolve(LEGACY_ARCH, value_head_variant=value_head_variant)
```

### Eval-tools diagnostic (the original motivating use case)

With constraints declared on fields, eval-tools could introspect valid choices at runtime (e.g. reading the `in_()` validator's allowed values from a field to power diagnostic hints like "value_head_variant must be one of ..."). The exact introspection API depends on attrs' validator internals, which would need to be verified before building on. Whether we build this introspection or stick with a simpler catch-and-explain approach in eval-tools is a separate decision that doesn't block the migration.

## Migration plan

1. Add `attrs` to `pyproject.toml` (workspace-level dependency).
2. Migrate `ObsConfig` first (smallest, no nested objects).
3. Migrate `ModelConfig` (depends on ObsConfig; converter replaces `__post_init__` coercion).
4. Migrate `TrainConfig` (depends on ModelConfig; largest field count).
5. Update all call sites (`asdict` → `attrs.asdict`, `replace` → `attrs.evolve`, `fields` → `attrs.fields`).
6. Run tests: `pytest training/tests/ packages/eval-tools/tests/`.
7. Verify pyright is happy (attrs has full type stubs).

Steps 2–5 can land in a single commit — the three classes form a dependency chain and the call site updates are mechanical. Splitting them would leave the serialization in a broken intermediate state (stdlib `asdict` can't recurse into attrs objects).

## Open questions

- **`validate_partial` value checking**: should we extend `validate_partial` to check constraint satisfaction on provided values (not just unknown-field detection)? This would let `prep_sweep.py` catch invalid config values in sweep YAML before instantiation. Low priority; the current unknown-field check is the main value.
- **Pyright + converter type inference**: When a field has `converter=_coerce_obs`, pyright infers the `__init__` parameter type from the converter's input signature, not the field annotation. If `_coerce_obs` is typed `(value: Any) -> ObsConfig`, the init param becomes `Any` — losing type safety. If `(value: dict | ObsConfig) -> ObsConfig`, it becomes `dict | ObsConfig` — accurate but different from the current `ObsConfig` annotation (which is what callers see today, since `__post_init__` coercion is invisible to the type checker). Needs a concrete test with our pyright setup before committing. The converter signature becomes part of the public typing contract.
- **attrs version pinning**: pin to `>=24.0` (when the modern `attrs` namespace stabilized) or leave unpinned? The API we use has been stable since ~v21.
- **`LEGACY_OBS_CFG` / `LEGACY_ARCH`**: these become attrs instances. They're constructed at module load with valid values, so no issue — just noting that `LEGACY_ARCH` gains the same frozen/validator behavior.
