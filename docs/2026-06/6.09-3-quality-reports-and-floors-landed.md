# Session summary — quality reports + per-manifest floors

Date: 2026-06-09

Session goal was increment 1 of the 6.09-1 instrumentation plan (display-layer freebies, then floors). Both landed, in two commits on `model-arch-work`.

## What landed

**Report split.** `report.md` is retired: every run now writes `quality.md` (config header, standing-panel summary, per-epoch table) and `perf.md` (the former perf-spike report, quality section removed). Old run dirs keep their stale `report.md`; `scripts/build_run_report.py` regenerates both (`--write`) for any run dir.

**`run_comparison` refactor.** Column registry now separates numeric extraction from formatting, enabling derived columns and reductions on shared definitions. New: `gap` column (`val_value − train_value`, the memorization lens) and `build_summary_table` — one row per run: best-epoch `val_value` + epoch, floor, Δbest, last `val_value`, gap@best, final policy/top-k/pass metrics. `compare_runs` prepends it for multi-run comparisons (`--summary-only` / `--no-summary`).

**Floors.** Every manifest gets a `<stem>.metrics.json` sidecar holding its val placement marginals; the frame-weighted entropy is the `val_value` floor. Pieces: pure compute in `analysis/marginal_entropy.py`; sidecar IO + run-dir→manifest resolution in `analysis/run_metrics.py` (`floor_for_run`); creation hooks in `splits.py` build, `subset_manifest.py` (computes its own — a prefix slice has its own distribution), and `build_cloud_slice.py` (ships the sidecar with the slice). Display reads floors as data; runners backfill missing sidecars (`create=True`). Cost: ~1s per 1k val perspectives, so backfill-on-first-use is the default everywhere.

**Architecture rule established:** renderers (`run_comparison`, report builders' table code) are pure functions of values; all filesystem/manifest IO lives in `run_metrics` and the runner layer. `run_metrics` is the intended home for future run-metric normalization (legacy args schemas, checkpoint-era arch lookup).
