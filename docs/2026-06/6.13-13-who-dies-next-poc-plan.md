# who-dies-next — PoC and experiment plan

**Date:** 2026-06-13

**Description:** The proof-of-concept and experiment plan for the **who-dies-next** auxiliary head — the target redesign decided in [`6.13-12`](6.13-12-who-dies-next-target-reframe.md). This is forward-looking and less settled than 6.13-12: two design decisions are deliberately left open for session start (flagged below). Scope: validate that the head learns the predictable signal and does no harm at small scale, before any 24k transfer run.

## Decision framing

The pivot to who-dies-next is the working direction ([`6.13-12`](6.13-12-who-dies-next-target-reframe.md)); this PoC exists to validate that it learns and does no harm, and to produce a *legible* read (beats a heuristic baseline vs not) where the time-bin head's reads were murky. Re-evaluate if Stage 1 reads poorly or a design blocker appears — the latter looks unlikely, since most plumbing is reused.

## The target

Per frame, predict **which player is eliminated next**: the first `death_events` row with `timestep > t`, mapped to its canonical channel (0 = self, 1–7 = opponents via `opp_slots`). A single categorical per frame over the currently-alive real players. Reuses the elim head's `real_slots` / `death_by_slot` precompute ([`6.13-5`](6.13-5-next-elimination-head-design.md)).

- **Include self** (channel 0): "do I die next" is a strong, value-relevant survival signal, so self is included in the softmax.
- **Masking:** the target is defined wherever a future death exists. A non-winner always has one (its own death, at minimum); a winner's frames *after* the final elimination carry no next death and are masked from the loss.
- **New sample key:** `next_elim_target` (int64 scalar; the canonical channel index), plus the existing alive mask.
- **Ties** (two deaths at the same tick): resolve by a fixed convention (first `death_events` row); rare, noted for the implementer.

## Architecture

`Conv2d(C → 8) → ×valid_mask → pool over the board → [B, 8]`, then set dead/phantom channels to −∞ and softmax across the alive players. Cross-entropy against the next-victim index. Arch-gated exactly like the elim head, so existing checkpoints still load `strict=True`. This is *simpler* than the time-bin head (8 outputs, not 8·n_bins).

- **Pooling — OPEN (mean vs lse), to settle at session start.** lse preserves the localized "player i under attack" peak that mean-pool dilutes (the readout-sweep finding, [`6.13-11`](6.13-11-elim-readout-sweep-results.md)), which matters here because who-dies-next is partly a localized-danger detector; mean is simpler, gives parity with the current head, and reads the broadcast leaderboard scalars perfectly. Genuinely undecided — discuss.
- **Keep the time-bin head in the tree** (arch-gated): it carries the diagnostic tooling and may return as the ordinal-CDF variant. *(default.)*

## Loss

A single masked cross-entropy over the alive-player softmax against the next-victim index. Weighted into the trunk at `λ = 0.15` to start (do-no-harm parity with the elim head; [`6.13-7`](6.13-7-elim-head-stage1-read-and-weighting-sweep-handoff.md) §2 validated 0.15 as do-no-harm).

- **Label smoothing — lean: start hard CE, watch the confidence-ramp, add uniform smoothing only if it fingerprints.** The piecewise-constant label is the memorization risk ([`6.13-12`](6.13-12-who-dies-next-target-reframe.md) §main risk); the ramp diagnostic detects fingerprinting directly, so we don't pre-emptively smooth.

## Baselines — the legibility anchors

Two heuristics, both read off the leaderboard/scoreboard and computed from sim ground-truth for evaluation. The head must beat them to count as learning — this is the legible read the time-bin head's "beats its soft floor by 0.02 nats" never gave us.

1. **Lowest total army** — predict the alive player with the smallest total army dies next. The "who's weakest" (level) signal.
2. **Most-negative per-tick total-army delta** — predict the player losing army fastest right now ("being attacked hardest"). The "who's collapsing" (rate) signal. *(Daniel's domain pick.)* Per-tick delta is noisy; a short smoothing window (K ticks) is likely needed — set K in Stage 0.

Stage 0 measures how often *each* baseline predicts the true next-victim. That both sets the bar the head must clear and tells us which signal — level or rate — is more predictive, which is itself informative about what the head should be learning.

**Input-availability caveat surfaced by baseline #2 (worth confirming, then acting on).** The obs carries opponent army *level* (`opp_N_army_count`) and *land*-rate (`opp_N_land_delta`), but appears to carry **no opponent army-*rate* channel** — so the "being attacked hardest" signal is not directly available to the model for fogged opponents (only inferable via land-rate as a proxy, or the visible-tile dense history). This mildly qualifies 6.13-12's "cues are present" finding, which was about *levels*. If Stage 0 shows army-rate is the stronger predictor, **adding an opponent army-delta channel is a cheap, scale-free lever** worth doing before (or alongside) the PoC. *(reasoning from the channel list, `constants.py:60` — confirm there is no opp army-delta before acting.)*

## Diagnostics

- **Top-1 next-victim accuracy vs both baselines**, plus do-no-harm `val_policy` (`compare_runs`).
- **Confidence-ramp** (the memorization check): max-prob / prediction entropy as a function of time-to-next-death — should sharpen as the kill nears; flat-confident-from-frame-1 indicates fingerprinting.
- **Horizon-stratified accuracy**: accuracy bucketed by time-to-next-death — high when imminent, decaying toward baseline when far. The predictability-conditioned read; it falls out naturally here.
- **Self-vs-opp split** ("do I die next" vs which opponent).
- **Collapse check**: prediction entropy does not pin to a single player.

## Staging

- **Stage 0 (read-only corpus measurement, cheap):** the two baseline accuracies, the marginal over next-victim channel, and the time-to-next-death distribution (sets the horizon-stratification bins and the baseline #2 smoothing window). De-risks the run and fixes the baselines before any training. Mirrors the elim head's Stage 0 ([`6.13-6`](6.13-6-elim-head-stage0-corpus-measurements.md)).
- **Stage 1 (the PoC):** one cell — who-dies-next, λ=0.15, **end-to-end** (decided: no frozen-trunk probe first; the current trunk was shaped by a different target, so a negative probe would be ambiguous). Reads: beats both baselines? do-no-harm holds? confidence ramps genuinely? no collapse? Per pause-between-experiments, run this one cell, read it, *then* decide the small follow-up sweep (λ, pool mean-vs-lse, manifest size). **Manifest size + compute: OPEN** (see below).
- **Stage 2 (24k):** trunk transfer to the value head — the actual bet, deferred until Stage 1 is promising, run with the shuffled-target control for attribution ([`6.13-5`](6.13-5-next-elimination-head-design.md) §confound).

## Implementation scope

Bounded — most of the elim head's plumbing is reused. Touch points: `dataset.py` (next-victim extraction off the existing death precompute); a new head module; the loss term (single masked CE); model-config gating; `eval` metrics (accuracy, the two baselines, ramp, horizon-stratified); stratified-dump extension. Estimate: ~a day of careful work plus a smoke test, since the death precompute, arch-gating, and dump/compare tooling already exist.

## Open decisions (settle at session start)

1. **Manifest size + compute** — sub_5k vs ~10k, local vs cloud. Left open; "measure local sub_5k-vs-10k wall-clock first, then decide" is on the table. The larger-manifest rationale: the within-bucket wall was blamed on sub_5k, so the new target deserves a fairer first test, and learning at 10k-but-not-5k is itself a clean data-scale read.
2. **Pooling (mean vs lse)** — see Architecture.

Defaults taken above, open to revision: keep the time-bin head alongside; start without label smoothing; include self in the softmax; one PoC cell before any sweep.

## What "Stage 1 promising" means (the green light)

A legible, convergent picture rather than a single number: the head **clearly beats both baselines** on next-victim accuracy, its **confidence ramps** as deaths approach (genuine, not fingerprinting), the **horizon-stratified read** is high-near / honest-far (learning the predictable part, declining the unpredictable), and **do-no-harm holds**. That combination is the green light to spend a 24k transfer run; absent it, we re-evaluate the target rather than scale a murky head.
