# 6.25-3 — Survey: loaded-model usage trace (Task C)

Read-only survey. Traces every site that obtains a loaded `BCModel` and follows the instance ~2–4 layers deep: load → wrap/extract → forward, with obs source noted at each forward site. Grounds the contract decision for the checkpoint-loading refactor.

## Loaders (the entry points)

| Loader | File:line | Returns | Notes |
|---|---|---|---|
| `load_bc_model` | `packages/training/training/bc/checkpoint.py:161` | `BCModel` | the base loader; builds arch from the `.pt`'s `arch` key (else `LEGACY_ARCH` + fallback variant), strict `load_state_dict`, eval mode. |
| `BCModelHandle.load` | `packages/training/training/bc/inference.py:94` | `BCModelHandle` | calls `load_bc_model`, wraps model+device, computes `model_key` (re-reads file via `is_arch_bearing`). |
| `TrainingState.from_checkpoint` | `packages/training/training/bc/state.py:76` | `TrainingState` | calls `load_bc_model`, then **re-reads the same `.pt`** (`torch.load` at `state.py:107`) for `optim`/`scaler`/`epoch`. |
| `load_frozen_model` | `packages/training/training/analysis/probes/core.py:150` | `BCModel` (frozen) | calls `load_bc_model`, `.float()`, `requires_grad=False`, eval. |

## Per-consumer traces

### A. Inference / gameplay path — via `BCModelHandle`

The dominant consumer. `BCModelHandle` owns the model; everything forwards the **whole model** through `handle.forward_batch` → `self.model(obs_t, valid_t)` (`inference.py:135`).

- **`eval_tools/policy_spec.py`** — `_get_or_load_handle` (`:37`) → `BCModelHandle.load` (`:48`), caches by `model_key` (`:49`). `_parse_checkpoint_spec` reads **`handle.model.cfg.obs`** (`:102`) to build the `BCPerspective`, then wraps both in `NNAgent`.
- **`self-play/self_play/driver.py`** `play_game` (`:36`) — reads `handle.model.cfg.obs` to build two `BCPerspective`s, wraps in `NNAgent`s, runs `run_game`.
- **`self-play/self_play/cli.py:69`** — `BCModelHandle.load`, then into `play_game`.
- **`scripts/eval_poc.py:38,58`** — `BCModelHandle.load`, reads `handle.model.cfg.obs`, wraps in `NNAgent` vs `EvalBotAgent`.
- **`eval-tools/scripts/probe_row_independence.py:91`** — `BCModelHandle.load(..., value_head_variant="pyramid")`, reads `handle.model.cfg.obs` (`:47`), forwards via `handle.forward_batch` (`:64,98,112`) to check batch-invariance.
- **`game-runner/game_runner/batched.py:139`** — groups perspectives by `row.policy.model_handle.model_key` for one shared forward.

**Forward layering:** `NNAgent.act` (`nn_agent.py:79`) → `handle.forward_batch` → `model(obs, valid)` → `handle.decode_batch` → `perspective.select_action`. `NNAgent` holds the handle behind the `game_runner.brain.ModelHandle` protocol — model interiors are *not* touched here.

**Obs source:** built from the **loaded** config. `BCPerspective` is constructed with `handle.model.cfg.obs` (`inference.py:248-249` documents this explicitly: "source from the loaded checkpoint's `handle.model.cfg.obs` so the built obs matches `in_ch`"), and `encode()` builds the obs from `self.obs_cfg`.

### B. Training / resume path — via `TrainingState`

- **`bc/resume.py:124`** → `TrainingState.from_checkpoint` → `state.model`.
- The model is forwarded **whole** in `train.py:218` (`model(obs_for_model(batch), batch["valid_mask"])`) and in the warmup dummy forward `train.py:106`.
- Reads off the instance: `model.cfg.in_ch` (`train.py:102`, dummy-input shape), `model.active_aux_specs` (`train.py:181,244,253,714`, drives the loss accumulator / aux-head loops).
- `from_checkpoint` asserts `model.cfg == config.arch` (`state.py:113`) when the checkpoint is arch-bearing.

**KEY:** this consumer needs **more than a `BCModel`**. `from_checkpoint` re-opens the `.pt` (`state.py:107`) to restore `optim`, `scaler`, and `epoch` — metadata `load_bc_model` doesn't return. The full `TrainConfig` is *not* read from the checkpoint; it arrives from the caller and is used to rebuild optim/scaler and to assert against the recorded arch.

### C. Offline val-pass consumers — receive a `model` param

`run_val` / `capture_val_frames` take a `model` argument. In-training the model is `state.model`; offline it's a fresh `load_bc_model`.

- **`scripts/stratified_val_loss_analysis.py:99`** — `load_bc_model(ckpt, device, value_head_variant=...)` → `capture_val_frames` (`eval/dump.py:221`). Reads `model.cfg.elim_head_variant` and `model.cfg.elim_bin_edges` (`:124,128`) to label the report.
- **`eval/dump.py` `capture_val_frames`** — reads `model.cfg.elim_head_variant`, `model.cfg.elim_bin_edges`, `model.cfg.obs` (`:242,243,252,255`); forwards the **whole model** at `dump.py:217` (`out = model(obs_for_model(moved), moved["valid_mask"])`).
- **`eval/run.py` `run_val`** — reads `model.active_aux_specs` (`:103,112`); forwards whole model via `iter_val_forward`.

**Obs source:** loaded config — `capture_val_frames` passes `obs_cfg=model.cfg.obs` (`dump.py:252`). In-training `run_val` is handed `obs_cfg` from the train config (consistent with `state.model.cfg`).

### D. Probe path — extracts the **trunk**, discards the rest

- **`analysis/probes/cli.py` `run_probe_cli`** — `load_frozen_model` (`:82`), then `obs_cfg = model.cfg.obs` (`:83`) and `source = TrunkSource(model.trunk)` (`:84`). `TrunkSource.__call__` (`core.py:104`) forwards **`self.trunk(obs)`** — the trunk alone, no heads. `RawObsSource` ignores the model entirely (the checkpoint is loaded *only* to read its obs config).
- **`scripts/value_head_probe.py`** — `load_frozen_trunk` (`:185`) returns `model.trunk` directly (`:200`); forwarded as `trunk(x)` / `trunk(obs_batch)` (`:285,507`). The full model is never retained.

**Obs source:** mixed.
- `probes/cli.py` builds obs from the **loaded** `model.cfg.obs` (`:83`) — correct.
- `value_head_probe.py` `gather_stratified_frames` builds its dataset with **`OBS_CONFIG_DEFAULTS`** (`:227`), a hardcoded default, **not** `model.cfg.obs`. Independent obs path — flagged below.

**Note on `probes/cross_player.py` and `probe_runs/army_regression_task.py`:** these import `ElimNextDeathHead` / `masked_mean_pool` (`cross_player.py:38-39`, `army_regression_task.py:28`) to build **fresh probe heads sized to match**, not to extract from a loaded model. Not internal extraction.

### Tests touching internals (for completeness)

`tests/test_model_masked_pool.py` reads `m.value_head.variant`, `m.value_head.pre`, `m.elim_head` (`:84,86,123,139,159`); `tests/test_model_arch_consistency.py:54` takes `BCModel(cfg).trunk`. Test-only; not production consumers, but they confirm the same internal attribute surface (`trunk`, `value_head`, `elim_head`) is depended on.

## Three verdicts

### (i) Is `-> BCModel` a sufficient public contract?

**Sufficient for all consumers except the resume path.** Inference (`BCModelHandle`), self-play, offline eval, and probes need only a `BCModel` — they read everything else (`cfg.obs`, `cfg.elim_*`, `active_aux_specs`) **off the returned instance**, which `BCModel` already carries via its plain `cfg` attribute (`bc_model.py:48`).

The one exception is **`TrainingState.from_checkpoint`**, which needs `optim` + `scaler` + `epoch` in addition to the model. Today it gets them by a **second `torch.load` of the same file** (`state.py:107`) after `load_bc_model` already read it — a re-read the loader could fold in. No consumer needs the full `TrainConfig` or the loss recipe *from the checkpoint*: the resume path receives `TrainConfig` from its own caller (run dir / args) and only cross-checks it against the recorded `arch`. So the richer metadata any consumer actually wants from the loader is the optim/scaler/epoch trio — and only the resume consumer wants it.

Implication for the refactor: a routing/result object that surfaces `{model, optim_state, scaler_state, epoch}` (or the raw loaded dict) would let `from_checkpoint` drop its redundant second read. For every other caller, keeping (or wrapping) a plain `BCModel` accessor is enough.

### (ii) Is obs built from the loaded config or sourced independently?

**Built from the loaded config nearly everywhere**, via `model.cfg.obs` read off the loaded instance:
- inference / self-play / eval_poc / probe_row_independence — `handle.model.cfg.obs`.
- offline eval (`capture_val_frames`) — `model.cfg.obs`.
- probe framework (`probes/cli.py`) — `model.cfg.obs`.

**One independent/hardcoded exception:** `value_head_probe.py` `gather_stratified_frames` (`:227`) builds its dataset from `OBS_CONFIG_DEFAULTS`, not the loaded `model.cfg.obs`. If a loaded checkpoint's obs config diverges from the live default, this script's obs would silently mismatch the trunk it loaded. (This is an older one-off probe script; `probes/cli.py` is the maintained successor and does it correctly.)

### (iii) Which consumers reach into model internals, and what they touch

Two production consumers extract a **sub-module** and forward on it rather than the whole model:

1. **`probes/cli.py` + `core.py` `TrunkSource`** — `model.trunk` (`cli.py:84`), forwarded as `self.trunk(obs)` (`core.py:106`). Heads never run.
2. **`value_head_probe.py` `load_frozen_trunk`** — returns `model.trunk` (`:200`), forwarded as `trunk(x)` (`:285,507`). The rest of the model is discarded at load.

Both depend on the trunk being (a) a named attribute `.trunk` and (b) independently callable as `trunk(obs) -> [B, C, H, W]` feature map. This is a deeper coupling than `model(obs)`: it pins the `BCModel.trunk` submodule's name and standalone forward signature.

Lighter internal reads (attributes, no sub-forward) that the refactor should also keep stable: `model.cfg` (read everywhere — `.obs`, `.in_ch`, `.elim_head_variant`, `.elim_bin_edges`) and `model.active_aux_specs` (loss/train/eval loops). Tests additionally touch `model.value_head` and `model.elim_head`.

## Surprises / flags

- **`from_checkpoint` double-reads the `.pt`** (`load_bc_model` reads it, then `state.py:107` reads it again). Acknowledged in its own docstring as "a one-time cost paid only at resume startup," but it's the concrete reason this consumer wants a richer loader result.
- **`value_head_probe.py` uses `OBS_CONFIG_DEFAULTS`, not the loaded obs config** (`:227`) — the lone obs-source inconsistency. Older script; the maintained probe path (`probes/cli.py`) is correct.
- **The trunk's standalone forward contract is a real coupling.** Two probe consumers forward on `model.trunk` directly, so the refactor must not bury the trunk behind a forward-only `BCModel` facade without keeping `.trunk` reachable and callable.
