# Next-elimination auxiliary head — design sketch

**Date:** 2026-06-13

Implementation-ready design for the first auxiliary head: a per-player, per-frame **time-to-elimination** prediction read off the shared trunk. Intended for a separate implementation session — this is the spec, not the code.

Motivation and lit grounding: [`6.13-4`](6.13-4-aux-head-literature-synthesis.md) (aux-head synthesis), built on the Wave A conclusion that the value head's within-bucket placement signal is starved at sub_5k ([`6.12-4`](6.12-4-wave-a-results-and-synthesis.md)) and the aux-head direction in [`6.09-1`](6.09-1-value-head-direction-and-head-metrics.md). Full reports: [`6.13-2`](6.13-2-aux-heads-fundamentals.md), [`6.13-3`](6.13-3-aux-heads-applied-per-entity-hidden-info.md).

## What this head is, and why this form

For each frame and each player, predict **how soon that player is eliminated**, as an ordinal-bucketed categorical (soft-ordinal targets). The eventual winner falls in a terminal "never" bucket.

The form was chosen over a categorical "who dies next" (single identity) head because it carries strictly more of the signal the value head lacks. Predicting per-player time-to-death recovers "who dies next" as the arg-min, *and* yields a full predicted elimination **ordering** across all alive players — which is the reverse of placement order, i.e. exactly the within-bucket discrimination ("which survivor wins") that every Wave A value-head config failed to learn. It is also per-frame-varying (a countdown), so it sidesteps the memorization risk a piecewise-constant identity target carries, and its targets are free from the replay's elimination schedule.

This is an **auxiliary** head, not a value-head redesign: the value head predicts the *perspective's own* final placement; this head predicts the *whole field's* elimination dynamics. Its job is to shape the shared trunk (which the BC policy and the future PPO critic both inherit), not to replace the value target.

Precedents (verified, see [`6.13-4`](6.13-4-aux-head-literature-synthesis.md)): OpenAI Five's net-worth-rank head (per-entity end-of-game ordering, value-style, off a shared trunk), ToMnet's per-object future-event head, Agent-Modeling-as-Auxiliary (predicting others enriches a shared conv trunk), Terminal Prediction (dense per-frame time-to-terminal regression as a trunk-shaping aux).

## Decisions locked

- **Target:** per-player time-to-elimination, ordinal-bucketed, soft-ordinal targets (τ).
- **Bins:** 9 classes, geometric, with the top bin merged — edges `(5, 10, 20, 40, 80, 160, 320, 640)`, giving `[0,5) [5,10) [10,20) [20,40) [40,80) [80,160) [160,320) [320,640) [≥640-or-never]`.
- **"never":** the top ordinal class (merged with "dies ≥640 ticks out"); see *Known limitations*.
- **Head shape:** `Conv2d(C → 8·n_bins)` → masked global average pool → `[B, 8, n_bins]`. No ReLU. Global pool (not footprint-masked) for v1.
- **Gradient into trunk:** on, at a small weight `ν = 0.15` (the head's purpose is to shape the trunk; `stop_gradient` is the documented fallback if it harms policy/value).
- **`τ_elim = 1.0`** (rationale under *Defaults grounding*).
- **Arch-gated:** the head is constructed only when `elim_head_enabled`, so every existing checkpoint still loads `strict=True`.

## Target definition

Per-game precompute (once per sim load, alongside the scoreboard precompute): `death_by_slot[s]` = elimination timestep for raw slot `s`, or `+∞` (large sentinel) for the winner. Source: `sim["death_events"]`, rows `(timestep, slot)` — confirm the column order at implementation (the dataset already consumes `death_events[:, 0]` as timestep for `players_alive`).

In `encode_frame`, for each canonical channel `i ∈ 0..7` (channel 0 = perspective via `perspective_slot`; channels 1..7 via `opp_slots[i-1]`, the same per-opp ordering the obs uses):

- `raw = perspective_slot if i == 0 else opp_slots[i-1]`
- `alive = death_by_slot[raw] > t` — matches the existing aliveness convention (a player eliminated at `t` counts dead at frame `t`).
- if alive: `Δ = death_by_slot[raw] − t`; `bin = digitize(Δ, edges)` (winner's `Δ = ∞ → bin 8`, so the merge is automatic — no special-casing). `alive_mask[i] = True`.
- else: `alive_mask[i] = False`, `bin = 0` (ignored by the mask).

New sample keys (collate stacks to `[B, 8]`): `elim_bin_target` int64 `[8]`, `elim_alive_mask` bool `[8]`.

Channel 0 (self) is always alive within the perspective's own trajectory (frames stop at the perspective's elimination), so its target is the perspective's own survival horizon — the self-outcome signal, folded in for free. For non-winning perspectives self resolves to a finite bin near trajectory end; for winners, the top "never" bin.

## Bins and known limitations

The geometric scheme concentrates resolution at the short end, which is where the value-relevant signal lives — imminent eliminations are the high-information frames, and they cluster in the late game / endgame, exactly the regime where the value head is starved. The coarse top end captures "safe for a long time / wins."

**NOTE — the top-bin merge.** Merging "dies ≥640 ticks out" with "never" loses information only in a minority regime: a slow endgame where a losing player survives 640+ more ticks before dying lands in the same bin as the winner. In typical games the field is down to 2–3 players well within ~640 ticks, so the finite `Δ ≥ 640` tail is sparse and the bin is dominated by genuine winners; the late-game discrimination we care about (winner = "never" vs. soon-loser = a low bin) is preserved. Revisit if the stratified-by-players-alive reads show the top bin doing heavy lifting at 2-alive — the refinement is splitting `≥640` from `never`, or making bins game-phase-conditional.

**NOTE — absolute ticks vs. game phase.** Bins are absolute ticks. Time-to-elimination is correlated with game phase (players-alive), and the trunk already has players-alive available, so the head can condition on phase. Absolute bins keep "imminent danger" meaning game-length-independent. Normalized-by-game-length bins are a deferred alternative.

**NOTE — tick scale unmeasured.** Edges were set from domain knowledge, not a corpus death-Δ histogram. Harmless: empty/rare bins simply get no gradient. A quick measurement (read-only) would confirm the top bins are populated and is worth doing before a real run.

## Model

### `ModelConfig` (`model_config.py`)

New fields (validated in `__post_init__`):

- `elim_head_enabled: bool`
- `elim_bin_edges: tuple[int, ...]` — strictly increasing, positive. `n_bins = len(edges) + 1` is derived (single source of truth; the head sizes its output from it).

`MODEL_CONFIG_DEFAULTS`: `elim_head_enabled=False`, `elim_bin_edges=(5,10,20,40,80,160,320,640)`. The head is opt-in; the experiment config sets `arch.elim_head_enabled=True`.

### Backward-compat — the load-bearing constraint (`checkpoint.py`)

The head adds parameters, so a checkpoint with it has extra `state_dict` keys. Add the same fields to **`LEGACY_ARCH`** with `elim_head_enabled=False` (and the default edges). `_arch_for_load` back-fills missing keys from `LEGACY_ARCH`, so every pre-elim checkpoint reconstructs as "no elim head" and `load_state_dict(strict=True)` still passes. This is the entire reason the head is arch-gated rather than always-constructed.

### `BCModel` (`model/bc_model.py`)

Construct `self.elim_head` only when `cfg.elim_head_enabled`. `forward` adds `"elim_logits"` to the output dict only when the head exists. Everything downstream presence-gates on that key.

### Head module (`model/heads/elimination.py`, new)

```
trunk [B, C, H, W]
  → Conv2d(C → 8·n_bins, k=3, pad=1)     # per-(player, bin) per-cell evidence
  → × valid_mask
  → masked global avg-pool over the unpadded board   # like PassHead's pool
  → reshape [B, 8, n_bins]               # per-player bin logits
```

No ReLU (we pool straight to logits; a ReLU would discard signed evidence). Global masked-avg-pool, not footprint-masked, for v1. ~83k params at C=128, n_bins=9 — modest vs. the policy head's ~1.1M; Wave A found head capacity is not a strong lever, so the head is deliberately minimal. Alive-masking is applied at loss time, not in the head (the head always emits all 8 channels). Knobs flagged for later A/B: ReLU, footprint/attention pooling, deeper head.

## Loss (`loss.py`)

`LossConfig` new fields: `lambda_elim: float = 0.0`, `elim_target_tau: float = 0.0`.

`bc_loss` computes the elim term **only if `"elim_logits" in model_out`** (a disabled head is a clean no-op; existing consumers unaffected):

- soft targets: reuse `_soft_target_kernel(elim_target_tau, n_bins, device)` (cached per `(τ, n_classes, device)`; the value head's `(·, 8, ·)` entry and the elim head's `(·, 9, ·)` entry don't collide). `kernel[elim_bin_target]` → `[B, 8, n_bins]`.
- per-player CE: reshape logits to `[B·8, n_bins]`, targets likewise; `F.cross_entropy(reduction="none")` → `[B·8]` → reshape `[B, 8]`; `× elim_alive_mask`; sum / `alive_mask.sum()` → mean over alive (player, frame) pairs.
- returns `elim` (hard CE against the bin label — the reporting metric) and `elim_soft` (the trained objective; equals `elim` at τ=0), plus `n_elim` = `alive_mask.sum()` (the accumulator weight).
- `total += lambda_elim · elim_soft`.

This mirrors the value head's `value`/`value_soft` split exactly, with the per-player masked-mean reduction added.

`LossAccumulator`: add `sum_elim` / `sum_elim_soft` weighted per batch by `n_elim`; `summary()` emits `elim` / `elim_soft`; `total` derivation includes `lambda_elim · elim_soft` to preserve the component-sum identity. Presence-gate the new fields so non-elim runs are unchanged.

## Plumbing

- **`TrainConfig` (`train_config.py`):** add `lambda_elim: float = 0.0`, `elim_target_tau: float = 0.0` (recipe fields; defaults reproduce historical "no elim head"). Build into `LossConfig` at the `loss_cfg = LossConfig(...)` site in `train.py`. Validate `>= 0`. Add a consistency check: `lambda_elim > 0` requires `arch.elim_head_enabled` (no weight on an absent head). Same resume-legacy-pinning caveat as `lambda_value`/`value_target_tau` applies — defaulting to 0 keeps pre-field runs correctly described.
- **Per-batch JSONL (`train.py` `log_batch`):** add `elim` / `elim_soft` when present.
- **Per-epoch JSONL:** flows automatically via the `val` summary.

## Metrics (`eval/run.py`, `eval/metrics.py`)

`run_val` pulls `elim` / `elim_soft` from `acc.summary()` and feeds a new **`ElimMeter`** (in `metrics.py`, sibling to `PolicyEntropyMeter`), accumulating over alive (player, frame) entries:

- **top-1 bin accuracy** — argmax bin == target bin.
- **prediction entropy** — the collapse check, over the per-player bin softmax.
- **marginal-bin floor** — for the MVP, the empirical val marginal `H(p̄)` over alive entries; the head beats its trivial baseline iff `elim` (hard CE) `< floor`.

New `run_val` return keys: `elim`, `elim_soft`, `elim_top1`, `elim_floor_ce`, `elim_pred_entropy`. All presence-gated so non-elim runs are unchanged.

## Defaults grounding

- **`ν = 0.15` — a sweep start, not a cited value.** OpenAI Five specifies its aux-head trunk-gradient weight only as "very small" (1912.06680, Appendix D); no scalar appears in the text or hyperparameter table. The transferable precedent is structural (one head leaks a small gradient to the trunk, the rest `stop_gradient`), which we adopt; the magnitude is ours to sweep. Also consistent with the Wave A damage law (trunk harm tracks the value gradient's magnitude) — keep the new pressure modest.
- **`τ_elim = 1.0` — softer than the value head's 0.6, on two independent signals.** (1) HL-Gauss (Farebrother 2024, 2403.03950) uses σ ≈ 0.75 bin-widths and reports the optimum is robust and ~independent of bin count ("pick a sensible value") — softer than τ=0.6's near-peaked kernel. (2) Wave A found `tau1.0` was the strongest value-head cell ([`6.12-4`](6.12-4-wave-a-results-and-synthesis.md)). Both lean softer than 0.6. Tempered by our coarse 9-bin axis (HL-Gauss tuned σ on 21–201-bin axes, where wide smoothing is relatively narrow; on 9 bins over-softening washes toward uniform), so τ=1.0 rather than chasing HL-Gauss's literal width. Cheap to A/B once the head exists. SORD (Diaz & Marathe 2019) uses no separate temperature — smoothing is the distance metric's scale; not directly portable.

## Success criteria and staging

The head's purpose is trunk transfer to the value head, so the criterion is the **value head's within-bucket stratified reads, with vs. without the elim head** (the Wave A measurement, repurposed) — does the below-conditional-floor margin in the 2-/3-alive buckets improve when the elim head is present? Plus **do-no-harm to policy/value** (val_policy not degraded), and a **gradient-conflict diagnostic** (cosine between the elim-head trunk gradient and the policy/value trunk gradient; persistent negative cosine = real conflict, candidate for the `stop_gradient` fallback or PCGrad).

The elim head's own health is the nearer milestone: beats its marginal floor, no prediction-entropy collapse, bounded train−val gap.

Staging:
- **Stage 1 (sub_5k, cheap):** does the head learn its task above floor, and do no harm to policy/value? Exercises all new plumbing before committing compute. (Within-bucket *value* transfer is not expected to be readable here — Wave A showed within-bucket value signal only appears at scale.)
- **Stage 2 (24k):** does the value head's within-bucket signal move? The actual transfer test; needs the scale where within-bucket signal can appear.

## Deferred / fast-follow

- **Stratified dump** (`eval/dump.py` `FrameRecordCapture`): add `elim_probs` / `elim_ce` / `elim_bin_target` / `elim_alive_mask` columns + the report extension. The targets are already in `host_batch` once added in `encode_frame`.
- **Conditional floor** by players-alive (the value head's conditional-floor analog); per-channel breakdown.
- **"never" as a separate (non-ordinal) class** — A/B against the merged-ordinal choice if the head shows promise. Driven by whether "identify the winner" sharply matters.
- **Footprint / attention pooling** A/B (the "evidence localizes near a player's general" hypothesis); ReLU; deeper head.
- **Top-bin split** (`≥640` vs `never`) and **game-phase-normalized bins**, if the stratified reads show the merge/absolute-tick scheme losing late-game resolution.
- **Time-to-elimination as regression** (Terminal-Prediction form) as a sibling A/B against the bucketed-categorical form.
- **Corpus death-Δ measurement** to confirm bin population.
