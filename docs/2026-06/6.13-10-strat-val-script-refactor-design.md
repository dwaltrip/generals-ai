# Refactor of `stratified_val_loss_analysis.py` 

Design sketch:

**Feature (single-run, lands *after* the refactor)**
- New columns in the elim per-bin table: **precision** + **pred-freq**, beside the existing recall.
- New `report --confusion` flag: the 8×8 confusion matrix (rows=true, cols=pred).
- Both derive from one primitive: `confusion_counts(probs, bins, n_bins) → [n_bins, n_bins]`; `per_bin_metrics(C)` reduces it to recall/precision/pred-freq/support. Cross-cell 2×2 read stays docs/ad-hoc — no cross-run logic in the tool.

**Refactor — homes**
- `training/analysis/run_metrics.py` gains the run-dir resolvers: `resolve_epochs`, `resolve_val_samples`, and a canonical `load_epoch_rows` (returns `[]` on missing) that folds the `load_epochs`/`load_epoch_rows` duplication — `run_comparison` + `quality_report` repoint to it.
- `training/analysis/elim_metrics.py` (new) — full extract of the elim calc as pure functions: `elim_flat`, `elim_stats`, `confusion_counts`, `per_bin_metrics`, `bin_labels`. Importable, so the cross-cell synthesis stops re-deriving from npz by hand.
- `bc/eval/dump.py` gains `iter_val_forward(...)` — the shared forward-capture loop generator, yielding `(host_batch, moved_batch, out)` *outside* autocast. (Lives here, not a new module: `run.py` already imports from `dump.py`, so no import cycle.)
- `bc/eval/dump.py` also gains `capture_val_frames(...)` — the offline driver: loops `iter_val_forward`, fills `FrameRecordCapture` + heartbeat, returns finalized columns. Replaces `_val_pass` (deleted).
- `run_val` rewired to loop over `iter_val_forward`, re-entering autocast only for `bc_loss`. Numerically a no-op (loss reuses no model weights; reductions are fixed-fp32 under autocast either way).

**Script → thin CLI (`stratified_val_loss_analysis.py`)**
- `run_dump`: resolve via `run_metrics`, do frac subsampling (stays — a CLI concern), call `capture_val_frames`, `save_dump`, then the unchanged column-derived `_check_against_epoch_row`.
- `run_report`: load npz → printers only, as formatters over `elim_metrics` results.

**Formatting**
- All hand-built markdown tables → `utils.format.md_table`; numerics → `format_pct`/`format_loss`. Covers elim printers, the value-side bucket table, and `_print_histogram`'s table.
- `_print_histogram` stays its own function (2-D contingency table — not a `utils.distribution` dup) but routes its table through `md_table`.

**Verification (gates)**
- Training-behavior: before/after `smoke_train.sh` (fixed-seed `smoke-config.json`), diff `epochs.jsonl` val rows — expect exact match. Capture the baseline before touching `run_val`. Stop if anything drifts past float-accumulation noise.
- Feature correctness: precision reproduces 6.13-8's appendix on the on-disk sweep dump — baseline ep3 bin-0 = 21.7%, bin-7 = 48.5%.

**Commit**
- One bundle, including the already-uncommitted `run_comparison.py` elim column group.

**Order**
1. `run_metrics` resolvers + epochs-reader dedup.
2. `iter_val_forward` + `run_val` rewire + `capture_val_frames`, delete `_val_pass` → **smoke-train gate here**.
3. `elim_metrics.py`.
4. Feature wiring: precision/pred-freq columns + `--confusion` + table sweep.
5. Verify precision vs appendix.
6. Commit bundle.

Starting with step 1 — capture the baseline smoke-train output first so step 2's gate has something to diff against.
