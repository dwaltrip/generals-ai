# Timing-profiler infra — build plan (`6.05-4`)

**Date:** 2026-06-05

**Status:** Design locked; pre-implementation. Build the infra (timer + run-glue + wiring) and prove it end-to-end with a local multi-worker smoke run *before* placing any real `build_obs` seams.

## Goal

A reusable, low-overhead, named-span timer we can switch on for a perf spike and re-run after the obs tensor changes — to locate the on-target (Modal) producer/pipeline bottleneck we proved M1 can't show (obs-build is ~0.32 ms/frame on M1 vs ~2.3 ms on a Modal core; the bandwidth-bound stages are nearly free on M1). Two workflows share one core: **W1** = the real training run with a `--profile` flag (realistic, multi-worker, consumer side); **W2** = a thin single-process driver that calls the real obs path with no train loop (producer detail, fast iteration). This note covers only the shared infra.

## Module layout

Separation is load-bearing: the timer knows nothing about workers, files, or the run.

- `shared/timing.py` — `Timer` class + the `timer` singleton. Pure (stdlib `time`/`contextlib`/`warnings` only). Imported by the seams: `from shared.timing import timer`.
- `shared/timing_run.py` — `FileSink` + lifecycle (`begin` / `active_sink` / `end_and_report`) + merge + report. Knows about workers, json, the run dir. *Uses* `timer`; `timer` never imports it.

## Per-process model (the constraint everything bends around)

Producer code (`IterableDataset.__iter__` → `step_memory`, `encode_frame`/`build_obs`, collate) runs **in the N DataLoader workers**; the train-loop body (model, loss, H2D, logging) runs in **main**. Workers are separate processes (Python 3.14 on Modal/Linux → `forkserver`/`spawn`, not `fork`), fresh-imported and the dataset is **pickled** to them. Fresh workers per epoch (`persistent_workers` is forbidden).

Consequences:
- Each process has its own `timer`; producer tallies accumulate in the workers, not main.
- Enablement rides on the **sink object carried on the pickled dataset instance** — the natural cross-process signal, since the worker needs the sink to flush anyway. Worker sees `self._prof_sink is not None` → flips its own `timer.enabled`. (An env var would *also* propagate — `spawn`/`forkserver` inherit `os.environ` — but the sink is the object we already have to ship, so it's the cleaner carrier.)
- Worker tallies get out via per-worker json files written on `__iter__` teardown (Option A); the driver merges. This cross-worker aggregation is the one genuinely custom part; no profiling library does it for us.
- **`run_val` is auto-excluded:** it builds its own `IterableDataset` with no `prof_sink` (`eval.py`), so val-phase workers keep `timer` disabled and write no files. The val pass never pollutes the merge — intentional, not incidental.

## `shared/timing.py`

```python
"""Process-local named timer for perf spikes. Off by default; enabled per-process
by shared.timing_run. Knows nothing about workers/files."""
from __future__ import annotations
import time, warnings
from collections import defaultdict
from contextlib import contextmanager, nullcontext

_NULL = nullcontext()                              # shared no-op for the disabled path

class Timer:
    def __init__(self) -> None:
        self.enabled = False
        self._tot: dict[str, int] = defaultdict(int)   # name -> total ns
        self._cnt: dict[str, int] = defaultdict(int)   # name -> calls
        self._open: dict[str, int] = {}                # name -> start ns (manual)

    def reset(self) -> None:
        self._tot.clear(); self._cnt.clear(); self._open.clear()

    def snapshot(self) -> dict[str, tuple[int, int]]:
        if self._open:
            warnings.warn(f"snapshot with timers still open: {list(self._open)}")
        return {n: (self._tot[n], self._cnt[n]) for n in self._tot}

    def _record(self, name: str, ns: int) -> None:
        self._tot[name] += ns; self._cnt[name] += 1

    def section(self, name: str):                  # ctx manager; one branch when off
        return self._section(name) if self.enabled else _NULL

    @contextmanager
    def _section(self, name: str):
        t = time.perf_counter_ns()
        try: yield
        finally: self._record(name, time.perf_counter_ns() - t)

    def timed(self, name: str):                    # decorator sugar over _section()
        def deco(fn):
            def wrap(*a, **k):
                if not self.enabled: return fn(*a, **k)
                with self._section(name): return fn(*a, **k)
            return wrap
        return deco

    def start(self, name: str) -> None:            # manual, crosses function boundaries
        if not self.enabled: return
        if name in self._open:
            warnings.warn(f"start({name!r}): already running")
        self._open[name] = time.perf_counter_ns()

    def stop(self, name: str) -> None:
        if not self.enabled: return
        t = self._open.pop(name, None)
        if t is None:
            warnings.warn(f"stop({name!r}): no timer running"); return
        self._record(name, time.perf_counter_ns() - t)

timer = Timer()
```

Three front-ends, one accumulator (`_record`): `timer.section(name)` (ctx), `@timer.timed(name)` (deco), `timer.start/stop(name)` (manual). **Disabled is one branch for all three:** `timed` short-circuits to the bare call, `start`/`stop` return immediately, and `section` returns a shared `nullcontext()` (no generator constructed). One caveat: `section` keeps a local start var, so a *recursive same-name* span would double-count its overlap — fine for the coarse, non-recursive seams we'll place.

## `shared/timing_run.py`

```python
from __future__ import annotations
import json
from collections import defaultdict
from dataclasses import dataclass
from pathlib import Path
from shared.timing import timer

@dataclass
class FileSink:
    dir: Path
    def flush(self, epoch: int, wid: int, snap: dict[str, tuple[int, int]]) -> None:
        (self.dir / f"worker_{epoch}_{wid}.json").write_text(json.dumps(snap))

_active: FileSink | None = None

def begin(prof_dir: Path) -> None:
    global _active
    prof_dir.mkdir(parents=True, exist_ok=True)
    for p in prof_dir.glob("*.json"):     # clear stale files (resume reuses the run_dir)
        p.unlink()
    _active = FileSink(prof_dir)
    timer.enabled = True                  # main process (consumer seams)

def active_sink() -> FileSink | None:
    return _active

def _merge(paths) -> dict[str, tuple[int, int]]:
    tot: dict[str, int] = defaultdict(int)
    cnt: dict[str, int] = defaultdict(int)
    for p in paths:
        for n, (ns, c) in json.loads(p.read_text()).items():
            tot[n] += ns; cnt[n] += c
    return {n: (tot[n], cnt[n]) for n in tot}

def end_and_report(prof_dir: Path) -> dict:
    main_snap = timer.snapshot()                        # main-process consumer tally
    if main_snap:
        (prof_dir / "main.json").write_text(json.dumps(main_snap))
    producer = _merge(prof_dir.glob("worker_*.json"))   # explicit globs — never summary.json
    consumer = _merge([prof_dir / "main.json"]) if main_snap else {}
    _report(producer, consumer)
    out = {"producer": producer, "consumer": consumer}
    (prof_dir / "summary.json").write_text(json.dumps(out, indent=2))
    return out
```

Note the explicit `worker_*.json` glob (not `*.json`) so `summary.json` and `main.json` are never folded into the producer sum, and `begin()` clears stale files so a resumed segment (which reuses the run_dir) can't re-sum a prior run's tallies.

## Reporter — two tables, separate denominators

Producer regions are summed across **N parallel workers** (overlapping wall-clock); consumer regions are **serial** in main. Putting both in one `%share` mixes N-parallel CPU-time with serial wall-time and inflates the producer by ~N (a region can read as near-100% when it's really spread across N cores). So `_report` prints two tables:

- **Producer** (from `worker_*.json`): per-region **µs/sample on one core** (`Σns / n_samples`, where `n_samples` is an anchor region's call count, e.g. `build_obs`), calls, and an internal `%share` (valid — all serial *within* a worker). The producer means sum to the per-sample build cost on one core. This is the parallelism-invariant number to compare across n=5/10/20 and before/after a fix — it answers *where the obs-build cost is*.
- **Consumer** (from `main.json`): per-region **ms/batch (wall)** plus the `fetch-wait` fraction, on its own denominator. Answers *whether the GPU is starved*.

Deliberately **not** a single merged pie — the two tables answer two different questions and a cross-boundary fraction is meaningless.

## Wiring

### Local (`run_bc_local.py`) — one process

- `IterableDataset.__init__`: add `prof_sink=None`, store `self._prof_sink`.
- `IterableDataset.__iter__` (runs in worker):
  ```python
  wid = (wi.id if (wi := torch.utils.data.get_worker_info()) else 0)
  if self._prof_sink is not None:
      timer.enabled = True; timer.reset()
  try:
      yield from <existing walk/shuffle body>
  finally:
      if self._prof_sink is not None:
          self._prof_sink.flush(self._epoch, wid, timer.snapshot())
  ```
- `train.build_dataloader`: `IterableDataset(..., prof_sink=active_sink())` — one line; `None` when not profiling → fully inert.
- Entry: a `--profile` flag on `build_arg_parser` (CLI/runtime only — **not** a `TrainConfig` field; profiling is how-we-ran, not what-we-trained) bookends `bc_run`:
  ```python
  if args.profile: begin(config.run_dir / "prof")
  bc_run(config)
  if args.profile: end_and_report(config.run_dir / "prof")
  ```

### Modal (`run_bc_modal.py`) — laptop + container split

`args` is parsed in the **local entrypoint** (`train()`, on the laptop) while `bc_run`, the workers, and the prof files all live in the **remote container** (`train_remote`), and `train()` `.spawn()`s fire-and-forget. So the bookend must run **in the container**, not the entry script:

- `train()` reads `args.profile` and passes it as a new positional into `train_remote.spawn(...)` — same pattern as the existing `force_config_mismatch` / `legacy_lr_warmup_batches` args.
- `train_remote` gains `profile: bool` and bookends the run where the workers actually live, with `prof_dir` under the `/runs` Volume:
  ```python
  from shared.timing_run import begin, end_and_report
  prof_dir = (Path(resume_run_dir) if resume_run_dir else fresh_config.run_dir) / "prof"
  if profile: begin(prof_dir)
  try:
      ... initialize_run_dir / bc_run(fresh_config)   # (or the resume branch)
  finally:
      if profile: end_and_report(prof_dir)            # finally → partial report survives a raise
  ```
- **Retrieval is free:** `prof_dir` is under `/runs` (the `training-runs` Volume), so `summary.json` persists there and the printed tables tee into `run.log`. Pull with the `modal volume get generals-ai.training-runs /<run_dir>` command `train()` already prints. `shared` is already in the image's `add_local_python_source`, so the import resolves.
- Operational: a profiling run still uses `--detach` + `--max-batches` (short window); the report only materializes after the run finishes.

## File format + merge

Per-worker-per-epoch `worker_{epoch}_{id}.json`, plus `main.json` (whole-run consumer tally). Each is `{name: [total_ns, calls]}`. `end_and_report` merges the two groups with separate denominators and writes `summary.json` = `{"producer": ..., "consumer": ...}`. Worker timers reset per epoch (file is per-epoch); the main timer accumulates across the window (flushed once). Output dir: `run_dir/prof/` (throwaway; gitignore).

## Boundary condition (documented, not engineered around)

With `num_workers=0` the producer runs in main: `__iter__` flushes `worker_{epoch}_0.json` *and* `end_and_report` snapshots the same (un-reset) main timer into `main.json` — so the same work is **double-counted** across the producer and consumer tables (and `__iter__`'s `reset()` first clobbers any prior main tally). A `num_workers=0` profiling table can't be trusted as-is. Doesn't arise in practice — W1 uses workers (separate timers), W2 has no consumer seams/train loop — so leave it documented.
