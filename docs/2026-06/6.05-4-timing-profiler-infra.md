# Timing-profiler infra — build plan (`6.05-4`)

**Date:** 2026-06-05

**Status:** Design locked; pre-implementation. Build the infra (timer + run-glue + wiring) and prove it end-to-end with a local multi-worker smoke run *before* placing any real `build_obs` seams.

## Goal

A reusable, low-overhead, named-span timer we can switch on for a perf spike and re-run after the obs tensor changes — to locate the on-target (Modal) producer/pipeline bottleneck we proved M1 can't show (obs-build is ~0.32 ms/frame on M1 vs ~2.3 ms on a Modal core; the bandwidth-bound stages are nearly free on M1). Two workflows share one core: **W1** = the real training run with a `--profile` flag (realistic, multi-worker, consumer side); **W2** = a thin single-process driver that calls the real obs path with no train loop (producer detail, fast iteration). This note covers only the shared infra.

## Module layout

Separation is load-bearing: the timer knows nothing about workers, files, or the run.

- `shared/timing.py` — `Timer` class + the `timer` singleton. Pure (stdlib `time`/`contextlib`/`warnings` only). Imported by the seams: `from shared.timing import timer`.
- `shared/timing_run.py` — `FileSink` + lifecycle (`begin` / `active_sink` / `end_and_report`) + merge + report. Knows about workers, json, the run dir. *Uses* `timer`; `timer` never imports it.

## Per-process model (the constraint everything bends around)

Producer code (`IterableDataset.__iter__` → `step_memory`, `encode_frame`/`build_obs`, collate) runs **in the N DataLoader workers**; the train-loop body (model, loss, H2D, logging) runs in **main**. Workers are separate processes (Python 3.14 on Modal/Linux → `forkserver`/`spawn`, not `fork`), fresh-imported and the dataset is **pickled** to them. Fresh workers per epoch (`persistent_workers` is forbidden).

Consequences:
- Each process has its own `timer`; producer tallies accumulate in the workers, not main.
- Enablement can't ride an env var reliably. **The sink object, carried on the pickled dataset instance, is the cross-process enable signal.** Worker sees `self._prof_sink is not None` → flips its own `timer.enabled`. No env var needed.
- Getting worker tallies out = each worker flushes its `snapshot()` to a per-worker json file on `__iter__` teardown (Option A); the driver merges. This is the one part that's genuinely ours; no library solves cross-worker aggregation.

## `shared/timing.py`

```python
"""Process-local named timer for perf spikes. Off by default; enabled per-process
by shared.timing_run. Knows nothing about workers/files."""
from __future__ import annotations
import time, warnings
from collections import defaultdict
from contextlib import contextmanager

class Timer:
    def __init__(self) -> None:
        self.enabled = False
        self._tot: dict[str, int] = defaultdict(int)   # name -> total ns
        self._cnt: dict[str, int] = defaultdict(int)   # name -> calls
        self._open: dict[str, int] = {}                # name -> start ns (manual)

    def reset(self) -> None:
        self._tot.clear(); self._cnt.clear(); self._open.clear()

    def snapshot(self) -> dict[str, tuple[int, int]]:
        if self._open:
            warnings.warn(f"snapshot with timers still open: {list(self._open)}")
        return {n: (self._tot[n], self._cnt[n]) for n in self._tot}

    def _record(self, name: str, ns: int) -> None:
        self._tot[name] += ns; self._cnt[name] += 1

    @contextmanager
    def section(self, name: str):
        if not self.enabled:
            yield; return
        t = time.perf_counter_ns()
        try: yield
        finally: self._record(name, time.perf_counter_ns() - t)

    def timed(self, name: str):                  # decorator sugar over section()
        def deco(fn):
            def wrap(*a, **k):
                if not self.enabled: return fn(*a, **k)
                with self.section(name): return fn(*a, **k)
            return wrap
        return deco

    def start(self, name: str) -> None:          # manual, crosses function boundaries
        if not self.enabled: return
        if name in self._open:
            warnings.warn(f"start({name!r}): already running")
        self._open[name] = time.perf_counter_ns()

    def stop(self, name: str) -> None:
        if not self.enabled: return
        t = self._open.pop(name, None)
        if t is None:
            warnings.warn(f"stop({name!r}): no timer running"); return
        self._record(name, time.perf_counter_ns() - t)

timer = Timer()
```

Three front-ends, one accumulator (`_record`): `timer.section(name)` (ctx), `@timer.timed(name)` (deco), `timer.start/stop(name)` (manual). Disabled → near-zero (one attribute read + branch), and `timed` short-circuits to the bare call.

## `shared/timing_run.py`

```python
from __future__ import annotations
import json
from collections import defaultdict
from dataclasses import dataclass
from pathlib import Path
from shared.timing import timer

@dataclass
class FileSink:
    dir: Path
    def flush(self, epoch: int, wid: int, snap: dict[str, tuple[int, int]]) -> None:
        (self.dir / f"worker_{epoch}_{wid}.json").write_text(json.dumps(snap))

_active: FileSink | None = None

def begin(prof_dir: Path) -> None:
    global _active
    prof_dir.mkdir(parents=True, exist_ok=True)
    _active = FileSink(prof_dir)
    timer.enabled = True              # main process (consumer seams, added later)

def active_sink() -> FileSink | None:
    return _active

def end_and_report(prof_dir: Path) -> dict[str, tuple[int, int]]:
    main_snap = timer.snapshot()      # main-process consumer tally (may be empty)
    if main_snap:
        (prof_dir / "main.json").write_text(json.dumps(main_snap))
    tot: dict[str, int] = defaultdict(int)
    cnt: dict[str, int] = defaultdict(int)
    for p in sorted(prof_dir.glob("*.json")):
        for n, (ns, c) in json.loads(p.read_text()).items():
            tot[n] += ns; cnt[n] += c
    agg = {n: (tot[n], cnt[n]) for n in tot}
    _report(agg)                      # region | total_ms | calls | mean_us | %share
    (prof_dir / "summary.json").write_text(json.dumps(agg, indent=2))
    return agg
```

`_report` prints region / total_ms / calls / mean_us / %-share. Per-*sample* normalization (ms/frame) waits until a per-sample seam exists (e.g. `cnt["build_obs"]` == sample count) — deferred with the seam set.

## Wiring (three touch points, all thin)

- `IterableDataset.__init__`: add `prof_sink=None`, store `self._prof_sink`.
- `IterableDataset.__iter__` (runs in worker):
  ```python
  wid = (wi.id if (wi := torch.utils.data.get_worker_info()) else 0)
  if self._prof_sink is not None:
      timer.enabled = True; timer.reset()
  try:
      yield from <existing walk/shuffle body>
  finally:
      if self._prof_sink is not None:
          self._prof_sink.flush(self._epoch, wid, timer.snapshot())
  ```
- `train.build_dataloader`: `IterableDataset(..., prof_sink=active_sink())` — one line; `None` when not profiling → fully inert.
- Entry script (`run_bc_local.py` / `run_bc_modal.py`): a `--profile` flag (CLI/runtime only — **not** a `TrainConfig` field; profiling is how-we-ran, not what-we-trained) bookends `bc_run`:
  ```python
  if args.profile: begin(config.run_dir / "prof")
  bc_run(config)
  if args.profile: end_and_report(config.run_dir / "prof")
  ```

## File format + merge

Per-worker-per-epoch `worker_{epoch}_{id}.json`, plus `main.json` (whole-run consumer tally). Each is `{name: [total_ns, calls]}`. `end_and_report` globs `*.json` and sums into `summary.json`. Worker timers reset per epoch (file is per-epoch); the main timer accumulates across the window (flushed once). Output dir: `run_dir/prof/` (throwaway; gitignore).

2. Local multi-worker smoke: add **one temporary** `@timer.timed("build_obs")`, run `run_bc_local.py --profile --max-batches 5 --num-workers 2` (CPU/MPS), confirm two `worker_0_*.json` files appear and `end_and_report` prints a merged table. Remove the temporary seam. This proves the worker→file→merge path before any real seams go in.

## Boundary condition (documented, not engineered around)

Main-process consumer seams + a `num_workers=0` run collide: `__iter__`'s `reset()` runs in main and wipes the consumer tally. Doesn't arise in practice — W1 uses workers (separate timers), W2 has no consumer seams — so leave it documented.
