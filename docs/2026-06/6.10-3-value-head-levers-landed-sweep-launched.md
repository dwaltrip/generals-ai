## Landed (all inert at defaults — a default-config run is behavior-identical to before)

- **`LossConfig`** (`bc/loss.py`): replaces the `LAMBDA_VALUE`/`MU_PASS` module constants; threaded from `TrainConfig` (new recipe fields `lambda_value`, `value_target_tau`) into `bc_loss`/`LossAccumulator` as one object.
- **Soft ordinal placement targets**: `value_target_tau > 0` trains the value head against row-softmax `exp(−|Δrank|/τ)` distributions. Metric contract: `value` stays hard CE everywhere (comparable to floors and all history); the trained objective is logged as new key `value_soft` (equals `value` at τ=0). Adjacent-rank mass fraction is `exp(−1/τ)`.
- **Head-side dropout**: arch fields `value_head_dropout2d` (channel dropout after the pyramid pre-module) and `value_head_dropout` (pre-linear). Train-time only; no state_dict impact.
- **Legacy top-level back-fill**: `_arch_for_load` now back-fills missing top-level arch keys from `LEGACY_ARCH` (mirroring the obs sub-key fill) — missing key ⇒ predates the field ⇒ pin historical value, never the driftable live default. The dropout fields are the first top-level additions since the `arch` key existed.
- **`prep_sweep`**: optional `skip` list in `sweep.json` (excludes named grid cells, typo-guarded), and a bash-3.2 fix for the generated scripts' `EXTRA_ARGS` expansion under `set -u`.

## Side finding: opponent aliveness is in the obs

Resolves the 6.10-1 open question: `opp_captured_by` (cat 9) is updated from `sim["capture_events"]` globally, fog-independent — matching the game's board-wide capture announcements. So `players_alive` is recoverable in principle and the conditional floors are fair. Encoding caveat: captor identity is magnitude-coded in one broadcast channel (0 = alive), so aliveness needs a learned nonzero-detector rather than a clean binary mask.
