# Argmin toy: build steps

*Date: 2026-06-17. Status: implementation plan. Builds the modest first step from 6.17-3 §7 to run the experiments designed in 6.17-1 (experiment design) and 6.17-2 (pedagogy). The science lives in 6.17-1/2; the engineering direction — fq for data, an own table-reading training loop — lives in 6.17-3. Open build decisions (§8) are left for the next session, where the implementation gets planned in detail.*

## 0. Scope & framing

The toy task: from one frame, return the index of the alive player with the smallest army. Ground truth is analytic, so the study is about *how* SGD finds the clean solution, how it depends on input encoding and architecture, and — instrumentally — whether the argmin step is the aux head's bottleneck (6.17-1 §9).

Engineering decisions carried in from 6.17-3 (one line each):

- **fq for data, own loop for training** — fq materializes a columnar table; a small table-reading loop trains over it. (Not the probe `ProbeCache` path; the toy's player-axis models don't fit the `(feats, aux)` head contract.)
- **Encoder lives in `model.forward`** — so one raw table serves every encoding × model × filter × size. The cache only busts when the *frame population* changes (extrapolation regimes, synthetic data — both deferred).
- **Build a thin vertical slice first** (§6); defer riders.

Tags below: `[new]` = code to write, `[reuse]` = existing code.

## 1. Data layer — the fq table

- `[new]` **land deriver** (`LAND_SIM`) — mirrors `army_totals_per_tick` in `analysis/families/army_derivers.py`, summing owned tiles instead of army.
- `[new]` **lean toy `FrameTableSpec`** — derivers `[ARMY_SIM, LAND_SIM]`; emit `alive` (dataset_kwargs `emit_alive_mask=True`); derived cols `label`, `margin`, `n_alive`.
- `[reuse]` existing `lowest_army_victim` (lowest-index argmin over alive) and `bottom_two_margin` from `analysis/families/elim_head_debug.py`; `ARMY_SIM` (exact int64 ground truth); `build_frame_table` + `GROUND_TRUTH_OBS_CFG` (obs dtype is moot here — the army label comes from `ARMY_SIM`, not the obs planes).
- **Columns produced (one row per frame):** `army[8]`, `land[8]`, `alive[8]`, `label`, `margin`, `n_alive`, `game_id`.
- `[new]` **`to_tensors`** (cols → torch) and **`split_by_game`** (partition on `game_id`, not perspective-level — avoids near-duplicate leakage for a target that's a pure function of `(army, alive)`).
- Notes: alive comes from the elim-based mask (decoupled from the army *value*, which the encoding ladder then manipulates); numpy argmin gives the correct lowest-index tiebreak by construction.

## 2. Encoder

- `[new]` **pure function** `encode(army, land, alive, cfg) → input`, called inside `model.forward`.
- cfg axes (the 6.17-1 §3 sweep surface): **encoding** (explicit-mask / 0-overload / −1-sentinel / rescaled-gap) × **channels** (army-only / +land) × **layout** (vector / broadcast).
- Keeping it in `forward` is what lets one cached table feed every variant.

## 3. Models — the A–E families

- `[new]` small modules, signature `model(army, alive) → [B, 8]` scores; decision is argmax with the lowest-index tiebreak (must match the label rule).
- **A** pool-first linear · **B** pooled-MLP (depth 0/1/2) · **D** equivariant linear (2 params) · **E** shared-φ · **C** flatten (later).
- The equivariance spine A1 / D1 / E1 share A1's per-player scalars; D/E are tiny.

## 4. Training loop + metrics

- `[new]` **table-reading loop (the engine seed)** — ~40 lines: AdamW, per-epoch train/val eval, reads a table + an explicit role-assignment (inputs/target/aux) rather than hardcoding `army`/`alive`; mirrors `train_probe_head`'s per-epoch curve conventions so output stays comparable with probe runs.
- `[new]` **plain cross-entropy over all 8 logits**, **unmasked** — the model must learn dead-player exclusion *from the encoding*, so we do **not** apply the alive mask to the logits (external masking collapses the encoding axis and erases the notch claim; full argument in 6.18-1 Appendix A). The probe's `masked_cross_player_ce` / `masked_top1` are therefore **not** reused. Single-sourcing CE to prod's loss is a separate P4-bridge concern, deferred per 6.17-3 §5.
- `[new]` **tie-aware metrics** — full-set / strict-margin / in-set accuracy + exact-tie fraction; error-vs-margin curve. Strict-margin is the honest comparator measure; the rest contextualize ties.
- `[new]` **weight inspection** — `W ≈ −I` recovery and the symmetric-subspace (`a·I + b·11ᵀ`) check, on the trained model we hold after the loop returns.

## 5. Driver — the thin diagnostic layer

- `[new]` **population select** (numpy masks on the one table): alive-filter (`n_alive == 8` vs `< 8`), sample-complexity (size subset), regime (army-band — later).
- `[new]` **variant × diagnostic loop** — over `(encoder cfg × model)` and any diagnostic axis, calling the engine.
- This is where the §8 axes that don't fit a single training run live (they're loops/selections we own, not new abstractions).

## 6. The first slice

Build the minimum that produces both headline results *and* reaches the aux-head decision, with one cache and the fewest model types. Everything cut is a separate question, the expensive outlier, or a rider that refines rather than establishes (full reasoning + tradeoffs in **Appendix A**).

- **Models:** A1 (= depth-0 baseline *and* the reference solution *and* the unconstrained spine rung) + B1-depth-1 (minimal notch-capable) + D1 + E1.
- **Axes:** army-only; encoding ∈ {explicit-mask, 0-overload, −1-sentinel}; alive-filter ∈ {all-alive, mixed} (encoding varies only in mixed — nested, not crossed).
- **Read-outs:** tie-aware metrics + `W≈−I` / symmetric-subspace inspection.
- **Size:** ≈ 4 model types × (all-alive[1] + mixed[3]) ≈ **16 tiny runs** on cached 8-vectors — seconds each.
- **Claims tested:** Claim 1 — linear fails on 0/−1-overload + mixed where depth-1 crosses (failure is the *encoding*, not capacity); Claim 2 — where the player symmetry comes from (does A1 land in the symmetric subspace on its own?). And the instrumental cell: clean A1 recovering `W≈−I` at ~100% strict-margin on **mixed + explicit-mask** ⇒ the argmin step is *not* the bottleneck ⇒ next round pivots upstream.

## Appendix A — The first-slice cut: reasoning and tradeoffs

The driving principle: the first slice should be **the minimum that produces the two headline results *and* reaches the decision the toy exists to inform**, at near-zero compute, with one data cache and the fewest model types. Everything else is a separate question, the expensive outlier, or a rider that *refines* rather than *establishes*. The experiment (6.17-1) has exactly two load-bearing claims, and the slice is built backwards from them.

### What's IN, and which claim it serves

**Claim 1 — the depth × encoding grid (the notch).** A linear model succeeds where the encoding keeps the function linear (all-alive; explicit-mask), but *structurally cannot* draw the non-monotonic notch that 0-overload / −1-overload + masking require; one hidden layer crosses that gap. The minimal test is:

- **A1 (pool-first linear)** — the depth-0 baseline and the reference solution (should recover `W≈−I`).
- **B1-depth-1** — the minimal notch-capable model.
- **× encodings** — the encoding is the independent variable that creates or removes the nonlinearity; ≥2–3 are needed to show the linear/MLP divergence is about *encoding*, not capacity.
- **× alive-filter** — the masking-isolation control. all-alive is the linear oracle (all encodings collapse; confirm `W≈−I` with no confound); mixed is where the encoding bites; the *gap* is the cost of masking. Without both, "argmin is hard" and "masking is hard" are not separable.

**Claim 2 — the equivariance spine.** A1 (unconstrained, 64 params) vs D1 (equivariant, 2 params) vs E1 (shared-φ). Tiny and sharing A1's per-player scalars, so nearly free. They answer "did SGD find the symmetry on its own?", and E1 is the rung that bridges toward the real aux head (6.17-1 §9), so it earns inclusion from the start.

**Tie-aware metrics and `W≈−I` / symmetric-subspace inspection are IN, not riders** — they are *how the slice is read*. Strict-margin accuracy is the honest measure of whether the comparator was learned (the plain number folds in tiebreak luck); and the weights *are* the experiment for the symmetry question.

A1 carries both claims (reference solution + depth-0 baseline + unconstrained spine rung) — the most leverage per model.

### What's OUT, grouped by why

- **Separate question:** full-obs / +land (distractor robustness — needs the real army-land joint); sample-complexity (measures *how much data*, not *whether* the predictions hold); extrapolation (needs regime-based splits, which bust the single-cache simplicity); loss-fn rider (CE vs ranking).
- **Expensive outlier:** flatten (C) — its payoff (the inductive-bias gap) is pedagogical, doesn't bear on depth/encoding/symmetry or the aux-head bridge (the real head pools, not flattens), and it is the one arch where broadcast-vs-vector adds moving parts.
- **Refines, doesn't establish:** width {16,32,64} (capacity isn't the bottleneck — expect flat returns, itself a clean negative result); activation (matters only in the tight-gap × depth cell); B1-depth-2 (depth-1 already proves "depth≥1 crosses").

### The order-aug subtlety (out, but the symmetric-subspace check is in)

These look in tension but aren't. The data carries a real asymmetry: slot 0 is always the perspective player (a curated strong player), so the 8 slots are not exchangeable. So the first slice's symmetric-subspace read asks "does A1 find `−I` / symmetry *on its own*, given that slot-0 bias?" — expecting a legitimate deviation in the slot-0 row, not a pathology. The **order-aug rider** (later) asks the complementary "does augmentation *push* it to symmetry?" Splitting them keeps the first read clean; bundling order-aug in would entangle the spine result with the augmentation pipeline.

### Why this is the right size

The matrix is ≈ 4 model types × (all-alive[1] + mixed[3]) ≈ 16 tiny runs on cached 8-vectors — seconds each. And it contains exactly the cell the instrumental goal needs: clean A1 recovering `W≈−I` at ~100% strict-margin on **mixed + explicit-mask** ⇒ the argmin step is not the aux-head bottleneck ⇒ the next round pivots upstream to spatial aggregation. So the slice is not just "minimal science" — it is the minimal cut that lets us make the decision the whole toy was built to inform.

### The most arguable inclusion

D1 / E1 are the most droppable: a still-thinner first cut is "just the depth × encoding grid" (A1 + B1-depth-1), with the equivariance spine as the immediate next step. They're kept in because they're nearly free and E1 is the aux-head bridge — but if the spine's weight-inspection plumbing proves fiddly, dropping to the depth × encoding grid alone is a clean fallback that still lands Claim 1 and the instrumental decision.
