# Value-head levers: results reference (sweep + λ=0 + 24k runs)

Date: 2026-06-10

Reference doc for the results of the runs launched in [`6.10-3`](6.10-3-value-head-levers-landed-sweep-launched.md): the 6-cell lever sweep, the λ=0 discriminator, and the full-24k "bonus" run. Tables, reproduction commands, and breadcrumbs for the one-off analyses. Interpretation lives in [`6.10-5`](6.10-5-value-head-synthesis.md); failure-mode background in [`6.10-1`](6.10-1-value-head-two-failure-modes.md).

All commands below run from the repo root. `compare_runs` tables use the per-run summary format (best `val_value`, Δbest vs manifest floor, gap = `val_value − train_value`); see `./packages/training/scripts/compare_runs.py -h`.

## One-off analyses (breadcrumbs)

These were ad-hoc numpy passes over the dump npz files (per-frame fields: `value_probs` [N,8], `value_ce`, `policy_ce`, `policy_entropy`, `n_legal`, `top1/3`, `pass_prob`, `is_pass`, `placement`, `players_alive`, `p_start`, `frame_t`, `persp_val_index`). The snippets weren't preserved; methods are described to reproduction precision.

### Bucket-Δ sampling error vs sample-frac

Method: value CE has roughly one effective sample per *perspective* per bucket (the label is per-game), so bucket Δ noise is governed by perspectives in the bucket, not frames. Bootstrap: resample perspectives with replacement (B=2000) from the tau0.6-drop-n20 ep3 dump, recomputing bucket mean CE *and* the bucket's conditional floor jointly per resample; scale perspective counts to the 24k val set (1,182 perspectives; the estimates below used the frame-count ratio ~4.6, slightly under the true perspective ratio 4.7).

| bucket | sub_5k persp | est. 24k persp | SE @frac 0.25 | @0.10 | @0.05 |
|---|---|---|---|---|---|
| 2-alive | 137 | ~634 | 0.031 | 0.051 | 0.075 |
| 3-alive | 177 | ~819 | 0.052 | 0.086 | 0.124 |

Scaling 1/√n gives full-frac 24k estimates ≈ 0.016 / 0.026, and ≈ 0.033 at sub_5k's own size (137 perspectives, 2-alive). Session decisions this drove: the bonus dumps ran at frac 0.5 rather than the 0.25 planned in 6.10-3, and the sub_5k below-floor margins are treated as ≤1.5σ reads.

### Paired ep2↔ep6 comparison (bonus run)

Method: the two dumps share frames exactly (same seed/frac), so compute per-frame `value_ce(ep6) − value_ce(ep2)` and bootstrap the per-bucket mean at the perspective level (B=2000). Conditional floors cancel exactly. Prediction entropy H = −Σ p log p from `value_probs`, mean per bucket.

| bucket | paired ΔCE (ep6−ep2) | SE | pred H ep2→ep6 |
|---|---|---|---|
| 2-alive | +0.059 | 0.023 | 0.79 → 0.90 |
| 3-alive | +0.061 | 0.026 | 0.97 → 1.07 |
| 4-alive | +0.061 | 0.037 | 1.14 → 1.27 |
| 5-alive | +0.003 | 0.043 | 1.28 → 1.38 |
| 6-alive | −0.089 | 0.052 | 1.42 → 1.45 |
| 7-alive | −0.029 | 0.049 | 1.51 → 1.53 |
| 8-alive | −0.007 | 0.043 | 1.62 → 1.56 |

Late-game CE degrades (2/3-alive at ~2.5σ); the 6-alive improvement is ~1.7σ; prediction entropy rises in every bucket except 8-alive. Note the early/mid-bucket SEs are ~2× the late-bucket ones despite more perspectives — early-game CE changes vary more across games.

### Policy entropy from dumps

Mean H over masked legal-action logits, non-pass frames (`is_pass` filter). All values nats. Perplexity figures throughout are e^(mean H) — the perplexity of the average entropy, not the mean of per-frame e^H (which is substantially larger; the per-frame distribution is right-skewed).

| checkpoint | mean H | perplexity | mean n_legal |
|---|---|---|---|
| bonus-24k ep6 | 0.811 | 2.25 | 643 |
| tau0.6-drop-n20 ep3 | 0.920 | 2.51 | 664 |
| tau0.6-nodrop-n20 ep3 | 0.952 | 2.59 | 664 |
| 06-05 n5 leg ep3 | 0.934 | 2.54 | 664 |

Bonus ep6 distribution: quantiles p5/p25/p50/p75/p95 = 0.046/0.232/0.629/1.036/2.662 nats (perplexity 1.05/1.26/1.88/2.82/14.3). Banded: 12.3% of frames near-deterministic (H<0.1, top-1 99.0%), 42.4% sharp (0.1–0.7, 90.0%), 30.4% few-way (0.7–1.4, 63.1%), 14.9% spread (>1.4, 36.2%). Entropy rises late-game: e^(mean H) 1.93 at 8-alive → 2.43 at 2-alive. Aggregate `val_policy` CE (0.832) minus mean H (0.811) ≈ 0.02.

### Heads-up eval (user-run)

80 games, n5 vs n20 τ+drop ep3 checkpoints (sub_5k), temperature 0.5 sampling, 40 random maps × slot-swapped pairs, max 1000 turns. Result: 38–42 (47.5% / 52.5%); binomial SE ±5.6%. Paired by map: ~12 n5 sweeps / ~13 splits / ~14 n20 sweeps — sign test null. (The map pairing was reconstructed from game indices; `results.jsonl` has no map id field, and the two plausible index conventions give 12/13/14 and 12/14/13 — same conclusion either way.) Winner→model mapping in `results.jsonl` is `slot_map[winner]`. Eval dir: `data/eval-runs/2026-06-10T08-25-18`.

```sh
./packages/eval-tools/scripts/run_adhoc.py \
  --policy "checkpoint:<n5_ckpt>:temperature=0.5,sample,value_head_variant=pyramid" \
  --policy "checkpoint:<n20_ckpt>:temperature=0.5,sample,value_head_variant=pyramid" \
  --max-turns 1000 --map-seed 0 --maps random:40 --games-per-map 1 --swap-slots
```

Two side-notes: `results.jsonl` `policy_diagnostics` records the value head's per-tick expected placement for every game (raw material for a future V(s)-monotonicity check); and at least one game showed a near-always-passing losing bot (132 of 145 ticks) — unexamined.

### fp16-obs comparability check

Both run eras train under fp16 autocast (`precision: fp16` in `args.json`); the 06-05 legs built obs fp32, everything from 6.07 on builds fp16. Per 6.07-1's bit-identity argument and parity test, the first conv sees identical bits either way under autocast, so cross-era comparisons (e.g. the λ=0 table above) carry no fp16-obs confound.
