## Slice 2 — the immediate next task: collapse the accumulator

**Goal.** `total` is currently assembled twice — once live in `bc_loss` (now the generic loop) and once *reconstructed* in `LossAccumulator.summary` from a second hardcoded list (`+ cfg.lambda_elim*elim_soft + cfg.lambda_elim*next_elim_soft`). Collapse that second list so the accumulator reconstructs `total` generically from the same registry. This finishes the "single source of truth for `total`" goal.

**Why it can't just read the `AuxLossResult`.** `LossAccumulator.update` receives the flat `losses` dict (the `out` of `bc_loss`), not the `AuxLossResult` — so the per-spec structure (which metrics group under which count, which is the trained term) isn't visible there. The fix is to expose that structure **statically** on the spec.

**Recommended approach (confirm with Daniel first):**
1. Add static metadata to each spec: `metric_keys` (e.g. `("elim", "elim_soft")`), `term_key` (`"elim_soft"`), `count_key` (`"n_elim"`), and a way to get its loss weight from cfg (e.g. a `weight_attr = "lambda_elim"` read via `getattr(cfg, ...)`, since both elim specs share `lambda_elim` today). These already exist per-call inside `AuxLossResult`; this lifts them to the class so the accumulator can use them without re-running `loss()`. `bc_loss`'s loop can then read the same static attrs (optionally simplifying `AuxLossResult`).
2. Rewrite `LossAccumulator` to hold generic per-spec running sums. `update`: for each `spec` in `REGISTRY` whose `count_key` is in `losses`, `count = int(losses[count_key]); per metric_key: sum[spec][k] += losses[k] * count; counts[spec] += count`. `summary`: per spec with `counts > 0`, `mean[k] = sum[k]/counts`, emit each `metric_key`/`count_key` into the summary dict, and `total += getattr(cfg, weight_attr) * mean[term_key]`. The core terms (policy/value/pass) stay as they are.

This reproduces today's numbers exactly (the variants are mutually exclusive, so only one spec ever has `counts > 0`, and both use `lambda_elim`) and generalizes to additive heads.

**Tests (focused — a high-value test or two, not exhaustive).** The accumulator's `next_death` path is currently un-exercised: `test_loss.py`'s `_fake_losses` helper has no `next_death` support, and only the time_bin path is covered (`test_accumulator_elim_weighted_by_alive_count`). For slice 2:
- Extend `_fake_losses` to emit the `next_death` keys (`next_elim`/`next_elim_soft`/`n_next_elim`).
- Add a `next_death` analogue of the weighted-count accumulator test (two batches, different `n_next_elim`; assert the summary mean is the count-weighted mean).
- Add one test that the accumulator's reconstructed `total` matches the expected count-weighted combination **including the soft term** for a `next_death` run — this is the core invariant slice 2 must preserve.

**Verification:** full suite green, plus the smoke runs below (the dump==accumulator CE line is the end-to-end signal that the generic reconstruction is correct).

## Carry-forward invariants & gotchas

- **`model_config` is deliberately torch-free.** Its docstring spells this out: `train_config`/`checkpoint`/`inference` compose `ModelConfig` without dragging torch into their import graph. **Do not import `aux_heads` (or anything torch-heavy) into `model_config`.** That's why `ELIM_HEAD_VARIANTS` stays a literal there, pinned to the registry by a test (`tests/test_aux_heads.py::test_registry_matches_model_config_variant_list`).
- **The dump CE is not the loss CE under weighted runs.** The dump's hard `elim_ce` is unweighted per-bin; it equals the accumulator's `elim` only when `elim_bin_weights is None` (today's default). Don't collapse `dump_records` into a reuse of the loss CE.
- **The dump==accumulator CE line is your end-to-end correctness check.** A clean smoke prints `mean next-elim CE X vs val X` (and `elim CE` for time_bin); they must match.
- **Residual reporting sites left intentionally.** `train.py`'s per-batch JSONL + console formatters still branch `if "elim" in … elif "next_elim" in …`; they key on metric-presence so they don't break. The `train.py` time_bin bin-edges dump-meta line is likewise a documented residual. These weren't worth a spec method; revisit only if a later slice makes it cheap.
- **Parallel session boundary.** A separate run-analysis session is editing `analysis/families/elim_head_debug.py` and the `6.21-2` diagnostics doc on this same branch. Those are **not** part of this refactor — don't touch them, and stage your commits explicitly (don't `git add -A`) so they stay out.
