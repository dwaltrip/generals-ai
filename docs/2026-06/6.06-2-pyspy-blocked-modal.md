# py-spy is blocked inside Modal containers (`6.06-2`)

**Date:** 2026-06-06

A feasibility probe found **py-spy cannot attach to any process inside a Modal container.** Every mode — `--pid <self> --subprocesses`, parent→child, and `--nonblocking` — fails with `Permission denied (os error 13)` reading the target's memory. It's the **Modal sandbox (gVisor)**, not YAMA `ptrace_scope`: scope was `1` (which still permits parent→child), yet parent→child failed too, and `--nonblocking` (`process_vm_readv`, no ptrace) failed identically — cross-process memory reads are denied at the syscall level, so the wrapper-launch fallback is out too.

**Implication:** profile the obs-pipeline blind spot (volume I/O / collate / IPC around the timed `build_obs` regions) **in-process** — cProfile inside the DataLoader worker — not with an external sampler. Probe archived at [`training/scripts/_archive/pyspy_probe.py`](../../training/scripts/_archive/pyspy_probe.py).
