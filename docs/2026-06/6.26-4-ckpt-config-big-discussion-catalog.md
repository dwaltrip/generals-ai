## Phase 1 — Migration mechanics + the frozen-in-time problem
- **(C)** Migration operation taxonomy from the 18 historical changes: add-field (additive, ~13), rename-key (`out_dir`→`run_dir`), nest/move-group (flat arch→`arch.*`, flat loss→`loss.*`), drop-key (`arch.in_ch`), rename+value-map (`elim_head_enabled`→`elim_head_variant`).
- **(C)** Frozen-in-time problem (the DB-migration trap; Alembic "don't import models," Rails `schema.rb`): a migration must not depend on live code that drifts.
- **(C)** Pure `dict→dict` migrations over literals are naturally frozen; danger = calling live code (live defaults, constructors) *inside* a migration. The design's "fill-if-absent with frozen values, never live defaults" rule *is* this discipline.
- **(C)** Construction (`TrainConfig(**)`, `build_model_cfg`, `__post_init__` coercions) runs **once at the end** of the chain on current-shape data — so migrations never invoke live constructors.
- **(C)** `_arch_for_load` today uses `asdict(LEGACY_ARCH)` = the *live* shape (collapse-to-current), not frozen-produces-v1. So relocating it is a *semantic conversion*, not a move.
- **(C)** `LEGACY_ARCH` is today's frozen-snapshot mechanism but shaped as a live-typed instance, hand-maintained in lockstep with the dataclass; per-version frozen fills replace it (strictly better). `vN.json` key-sets = the frozen-schema reference (the "don't import models" analog).
- **(T)** Stepwise-frozen (Alembic) vs collapse-to-current. The range-loop wants stepwise-frozen; the v0 code is collapse-to-current. Leaned stepwise-frozen.

## Phase 2 — The behavior-coupling realization (the "panic")
- **(C)** User's panic: the clean-seam premise only holds if you never delete/refactor old code that old configs depend on → implies growing backwards-compat code in live `main`.
- **(C, marquee seed)** Two senses of "config matches latest version": **Shape** (seam delivers cleanly) vs **Behavior** (seam structurally cannot). The unstated slide from shape→behavior was the bug.
- **(C)** Exposure grading: model-forward + obs-encoder = HIGH (every eval load); loss + training-loop = LOW (resume-only). "Large swathes" overstated — burden concentrated in forward + obs.
- **(C)** Pre-existing, not introduced by the design: `strict=True` + current forward already runs old checkpoints with today's code. The design is necessary-but-not-sufficient for behavioral compat (gives faithful arch+recipe = prerequisite).
- **(T)** Strategic options (orthogonal to config-versioning): additive-gated discipline / pin-SHA-per-checkpoint + checkout / curated-archive + re-train / explicit parallel versioning.
- **(O)** Q3 hinge: is "old + new co-resident in one process" (eval sweep) firm? Co-residency forbids the cheap pin-SHA-checkout escape.

## Phase 3 — Two-goals framing, barriers, A/B/Compat tiers
- **(C)** User's two opposing goals: Goal 1 = tame the sprawl of historical-behavior-preserving `if/else`; Goal 2 = isolate everything between checkpoint bytes and the Goal-1 interface.
- **(C)** Benign regime isn't accidental — user actively maintains it; `if/else` proliferating (elim-head = 5 variants, messy even in train-loop/metrics/logging).
- **(C)** Containment isn't 100% to model+obs — leaks into metrics/logging/analysis; cross-run analysis is important and non-trivial.
- **(C, key)** The **barrier model**: additive-gated change = no barrier; non-additive = barrier. Benign = barrier-free. The pain = the *price of zero barriers* (additive-gated accretion), not the barriers.
- **(C)** A/B reframed as **before/behind a barrier** (capability-defined, not taste-defined); curation operates *within* A.
- **(C)** The configurable builder is **B**, not the whole system; A stays hand-written/legible; build B lazily (empty until first barrier).
- **(C, caveat)** Quarantine ≠ deletion. Real fidelity-code reduction requires accepting degraded fidelity for the tail → the **B fidelity contract**: faithful / best-effort / unsupported.
- **(C)** Metrics leak: **universal** metrics (policy/value/pass — comparable across all) vs **variant-specific** (cohort-scoped); a 2nd schema-versioning problem parallel to config.
- **(C)** Interface: last-session's "loader → current TrainConfig" is correct *today* (barrier-free); A/B generalization is additive (LoadPlan gains a second arm) → shape it as a tagged union now. Migrate-to-nearest-supported-version, not always-to-current.
- **(C)** Diagnosis: present pain = additive-gated *sprawl* (fix = generic interfaces/specs, e.g. `AuxHeadSpec`); future pain = *blocked-from-deleting* (fix = A/B/barrier). Spec-ification is step one of both.
