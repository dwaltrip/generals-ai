## Findings

- **The legacy "pre-variant" band splits.** 6.09-3 treated `direct` as the presumed variant for all pre-05-28 runs, to verify. Verified: `2026-05-27T21-50-45Z` and `2026-05-28T08-21-33Z` were already pyramid; the other five legacy runs are direct.
- **The dense-history sweep ran on `cloud_24k_sub_5k`, not the full 24k** — full manifest, 3 epochs, launched 06-05 (pre-fp16-obs fix). The n=20 leg recorded only 2 of 3 epochs, presumably the starvation casualty. `runs-cloud/2026-06-07T08-41-55Z` (n=20, cloud_24k full, 4 ep) is a separate standalone run — the first ever on the full 24k manifest — not the sweep's n=20 leg. The early-reads table in 6.09-3 labels that run "sweep, n=20, 24k persp"; mislabel on both counts.
- **Near-controlled pairs for direct-vs-pyramid** at matched era/data scale: `2026-05-27T21-42-33Z` (direct, bs=512) and `2026-05-27T21-39-06Z` (direct, bs=256) vs `2026-05-27T21-50-45Z` (pyramid, bs=256), all cloud_24k mb=1500 5ep; and `2026-05-24T06-10-51Z` (direct) vs `2026-05-28T08-21-33Z` (pyramid), both sub_5k full 5ep bs=512. These are the cleanest reads available for "how much did `direct` overfit vs `pyramid`".
- Unverified curiosity: the 05-31 width-sweep runs record no `dense_history_n`, but the 192/192/240 leg's param count exactly matches the sweep's n=5 leg — consistent with the width sweep using what is now the n=5 input-channel count. Obs config for those runs not checked.
