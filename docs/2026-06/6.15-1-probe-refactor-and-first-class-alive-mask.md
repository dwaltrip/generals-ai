# probe tooling: structural refactor and a first-class alive_mask

**Date:** 2026-06-15

**Description:** Two arcs this session — a structural refactor of the frozen-probe tooling, and making the per-player alive field a first-class frame quantity (`alive_mask`) decoupled from the elimination head. Both landed and are green. The next-step task (the army-regression probe) is sketched but not yet wired up or run. The hardcoded-baseline known-issue from [`6.14-1`](6.14-1-who-dies-next-frozen-trunk-probes.md) is unrelated to this work and is still open.

## What landed

### Probe-lib refactor (probe-only, lower stakes)

`training/analysis/probes/` is now three layers, with a one-directional dependency that defines the split — `probe_runs/` imports the library; the library never imports `probe_runs/`:

- `core.py` / `cli.py` — the task-agnostic framework: feature sources, the feature cache, the train/eval loop, and the `ProbeTask` protocol (`core.py`); the shared CLI scaffolding (`cli.py`).
- `cross_player.py` — a kit shared by the "pick a player" probes (head zoo, masked CE/top-1, the army-channel lookup). Marked **provisional** in-module — it's a grab-bag and the grouping isn't settled (see Backlog).
- `probe_runs/` — one-off task scripts (`lowest_army`, `who_dies_next`, the in-progress `army_regression_task`).

Also folded in: dropped a premature task registry; collapsed the two who-dies-next imminent scripts into one parameterized by `--dt-max`; swapped a bespoke stdout tee for `utils.log.tee_stdio`; pruned dead protocol fields.

### alive_mask as a first-class frame field (touched training, higher stakes)

The per-player alive field (`[8]` bool — the cross-player softmax / regression domain) is one canonical `alive_mask` key emitted by the dataset.

- It previously had two names, `next_elim_alive_mask` and `elim_alive_mask`, one per elim-head variant, for the identical quantity. Unified to `alive_mask` at the dataset emit and across the training consumers (`loss.py`, `eval/dump.py`, `eval/run.py`, `train.py`) and the probe reads. This is the one change that touched load-bearing training code, not just the probe lib. Behavior-preserving: the suite (178 tests) stayed green, plus a live emit→probe-read smoke.
- A `FrameNeeds` contract replaced the probe's `elim_variant` field. A task now declares what each frame must carry — `elim_variant=...` for tasks that predict elimination, `alive_mask=True` for tasks that only need the alive field. The dataset gained `emit_alive_mask`, which builds the per-game elim precompute and emits only `alive_mask`, no elim head required. `lowest_army` declares `FrameNeeds(alive_mask=True)` — it only ever read the alive field. The design split: the capability lives in the dataset (`emit_alive_mask`), the policy lives in the framework (`FrameNeeds` → `dataset_args_for`).
- Offline dump readers go through `dump_compat.read_alive_mask`: prefers canonical `alive_mask`, falls back to the legacy keys for historical dumps, logs a WARNING per read so lingering old-dump use is observable. It lives in a torch-free module so the pure-numpy `elim_metrics` leaf stays torch-free.

## Next actions (the two that gate forward progress)

### 1. Finish and run the army-regression probe

`probe_runs/army_regression_task.py` is WIP, now unblocked by `FrameNeeds(alive_mask=True)`. Target extraction (read the broadcast leaderboard army channels via a board-cell read) and the head (a conv → masked mean pool → 8 scalars, the same shape as `ConvMeanPoolHead`) are sketched.

Remaining:
- Wire to the framework: `extract_target` returns a dict (`target` + `alive_mask` + `valid_mask`); the head takes `(feats, aux)`; declare `frame_needs = FrameNeeds(alive_mask=True)`; add `build_heads` and `main`.
- Implement the R² metric (below).
- Run it across the three sources: elim-ON trunk, elim-OFF trunk, raw-obs.

The goal: raw-obs R² ≈ 1.0 is the calibration anchor (the army totals are obs channels, so a trivial readout recovers them); the trunk-vs-raw-obs R² *ratio* answers whether the trunk preserved the army leaderboard or washed it out. This targets Open 1 from [`6.14-1`](6.14-1-who-dies-next-frozen-trunk-probes.md) — a continuous metric with no argmin saturation, unlike the lowest-army identity probe.

The R² metric: R² is a whole-split reduction — accumulate residual and total sums of squares over all val frames, then take the ratio; it is not a per-frame R² averaged. The framework's `metrics(pred, target, aux)` hook already receives the full val split (the eval loop concatenates every batch's predictions before calling it), so a whole-split R² fits the existing hook as-is — no eval-loop change is needed. Mask the loss/metric to alive players: a dead player's army is ~0 and trivially predictable, which would inflate R² — this is why the task needs `alive_mask`.

### 2. Probe-computed baseline (the 6.14-1 known-issue, still open)

This is unrelated to the alive_mask work above and remains untouched. Each probe task carries a hardcoded `baselines` dict (e.g. `rule_imminent: 0.478`) that `cli.py` prints as reference lines. Those constants were measured on a different frame population (the full val split, or a stale 5k constant) than the probe heads see (their val sub-split), so head-vs-rule gaps read ~1.3 pts too large.

Fix (designed, not built): compute the lowest-army rule's per-frame victim prediction inside `extract_target` — the obs army channels are already there, the same read `lowest_army` does — stash it in `aux`, and report its top-1 as a metric. It is then measured on the identical eval cache by construction, matched for both trunk and raw-obs sources, and the hardcoded dict goes away. Scoping caveat: the probe can self-compute the lowest-army rule and uniform per-frame, but not the army-delta / oracle baselines — those need the army trajectory across ticks, so they stay in `who_dies_next_baselines.py`, which walks the sim.

## Backlog (pull from as convenient)

- **`cross_player.py` is a grab-bag** (marked provisional in-module). It mixes obs introspection (`army_totals_ch_indices`) and the per-player pooled-readout heads — the same shape the army-regression head uses, so not softmax-specific — with the genuinely cross-player pieces (`masked_cross_player_ce`, the argmax-over-players `masked_top1`). Wants a rename or a split: a generic per-player-readout kit vs the softmax-specific loss/metric.
- **`valid_mask` → `in_bounds` / `board_cells` rename**, deferred as its own codebase-wide sweep, to do after the probe work rather than piecemeal. A partial inconsistency exists now: `army_regression_task.py` uses `board_mask` locally while the rest of the code uses `valid_mask`. Principle to preserve when the sweep happens: read padding through the mask (no top-left assumptions); flatten to a cell list only at leaf reads. Related: `board_cells_flat` currently lives in the WIP file with a "move somewhere reusable" TODO (and a `crop_to_board` 2D variant, if anything ever needs a real unpadded board).
- **Per-variant seed reset is a no-op.** `run_probe` builds all three heads in `build_heads` before the `torch.manual_seed(seed)` reseed loop, so the reseed doesn't control head init. Results are deterministic run-to-run, but the heads aren't initialized from a matched seed and the "reproducible head init per variant" comment overstates. Minor.
- **Smaller code-review findings** (low priority): no smoke test for the probe framework; `best_val_<metric>` and `best_val_loss` can come from different epochs, so the "best" row isn't a single checkpoint; `max_frames` keeps only the leading shuffled games (a sampling bias, not an even subsample); `army_totals_ch_indices`'s "brittle" TODO is now fail-loud-guarded but could be fully resolved by hoisting the army channel names into `constants.py`.
- **`dump_compat`'s legacy-key list** can be deleted once old dumps age out (a single isolated spot).
