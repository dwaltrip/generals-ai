## Notable implementation differences from 9.26-2

This section highlights the difference from the plan that matters most for part 1b.

### Reading the references tree

9.26-2 has the golden test load each entry's reference on its own: build the file path from the entry id (`<surface>/<point>/<fixture>.npz`) and open that file. The library doesn't provide that kind of lookup, because it isn't reliable on macOS. The file system ignores case when it opens a path, so the file it opens can have a name spelled differently from the id. During 1a, this let one file count as two different entries, and regen deleted the file.

Instead, we improved the implementation so that every read goes through `store.read_references`, which lists the tree and loads each file it finds. Each entry id then comes from a file's actual name on disk.

So for 1b, the golden test will read the tree once, in a session-scoped fixture, and call `get_reference` for each entry, with `None` meaning "unblessed, run regen".

## Minor variations from the implementation sketch (9.26-2)

These are mostly just FYI, so you aren't wondering why something looks different from 9.26-2.

- `render_change` leaves out the array name, and `render_content_diff` adds it. The report is expected to show the name as a heading. There is also a `render_layout` helper.
- `Point`, `Surface`, and `Registry` are keyword-only dataclasses.
- Input validation in the library raises `ValueError`, including in `check_content`, where 9.26-2 says an assertion error. `assert` is used only for internal invariants.
- `plan` raises `ValueError` for an empty fixture list, and for an id on disk that differs from a registered id only by case.
- `store.path_key(eid)` builds a case-insensitive key for an entry's path. Planning uses it to find the case-only collisions.
- `row_hashes` and `StreamingRowHasher` only accept non-negative axes.
- A `__meta__` member is written only when an entry has at least one `RowHashes`. It records dtypes as numpy dtype strings (such as `<f2`), which drop the field names of structured dtypes. No current producer hashes a structured array.
- There are a few tests the plan doesn't list: `test_registry.py`, `test_content.py` (each rejection in `check_content`), `test_compute_all_order`, and a test that an unchanged entry's file is not rewritten.
