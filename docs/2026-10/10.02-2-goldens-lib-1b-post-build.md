## Summary

Part 1b of the pass-1 plan (9.26-2) is built. The project side now runs on the goldens library: the registry, fixtures, producers, regen command, and golden tests all go through `training.goldens.lib`. The old modules and tests are deleted, and the references are re-blessed in the new layout.

The switchover was verified against the old references, which were read through `git show`. The obs hashes are unchanged. Each supervision point's file holds exactly the keys the old registry declared for that point, and each value equals the old file's. The check covered all 36 old files. ## Items from the post-build review

A review pass over the 1b code found no major problems. Three items came up:

1. **Differences from the design docs.** The code differs from 9.26-2 and 9.30-2 in several ways. 10.02-1 lists the differences from 1a. These are the ones from 1b:
    - The regen command is now `uv run python -m training.goldens.regen_cli [--dry-run]`. Its logic lives in the library (`regen_main` in `lib/cli.py`). The project's `regen_cli.py` only supplies the registry, the references root, and a fixture description.
    - The new `lib/testing.py` module gives library users a clean interface for adding goldens to their project. `load_test_context` builds a `GoldenTestContext` once per test session, holding the reference tree and a fixture loader that loads each fixture once. `assert_entry_matches` then checks one entry against its reference. The project's golden test is one call to it per entry.
    - Files that fail to load are recorded in `ReferenceTree.invalid_refs`, so loading the tree doesn't raise. `plan_regen` raises when any invalid references are present, and the golden test fails only the affected entry.
    - Renames: `plan` to `plan_regen`, `apply` to `apply_regen`, and `read_references` to `load_references`. The computed entries grouped by surface have a type alias, `ComputedEntriesBySurface`. Planning runs once per surface.
2. **No test checks the real references tree for files beyond the registered entries.** The golden tests only check registered entries. A leftover file under a registered surface (for example, from a dropped point) passes every test, as does an invalid file that isn't a registered entry. Either one only shows up when regen runs. This was also true before 1b. A test asserting that the real tree plans as a no-op would cover it, at the cost of running every producer a second time (about 1.5 s).
3. **9.30-2's import graph doesn't include the two new lib modules.** 9.30-2 says `run` is the only module that imports from both halves. `testing` and `cli` now do too: `testing` imports `compute` and `plan`, and `cli` imports `registry` and `report` (along with `run`). Both join the halves the way `run` does, so the layering holds, though the graph and that statement no longer match the code.

The CLI command name change is the one most likely to mislead a reader, since older docs that mentions regen have the old name.
