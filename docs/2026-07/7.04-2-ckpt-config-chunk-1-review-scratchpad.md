## Findings — gaps

### F1. v1 key-set freeze not done (design called it cheap-now + time-sensitive)

6.27-1 appendix C: "Freezing `v1.json` (the current key-set, the anchor the checks rest on) is the most time-sensitive piece — pin it at chunk-1 time, at the known-correct moment." Not in the diff, no snapshot anywhere in the tree. The working doc's deferred list folds all of appendix C into "chunk-2/3 — see 6.27-1 appendix", which loses the explicit "do the freeze itself at chunk-1" carve-out.

Meanwhile the unguarded failure mode is live: the writer now emits v1, config shape changes historically arrive ~18/month from *other* work, and a field added without a bump either silently defaults on old-v1 load (the exact drift this project targets) or TypeErrors. The pytest guardrail can stay deferred; the frozen snapshot is an hour of work and anchors everything later. Recoverable via git archaeology if skipped, but that's the awkward reconstruction the design wanted to avoid.

### F2. Working doc overclaims refactor-note coverage in state.py

6.27-3 §6: "In-code deferred smells (refactor-notes in place): the model_key re-read …; the from_checkpoint double-read; the now-dormant from_checkpoint arch-gate." Grep shows `state.py` has zero `ckpt-cfg-refactor-note` tags. Only the model_key re-read (inference.py:117) is tagged. The double-read is described in the docstring but untagged (a close-the-refactor sweep won't find it). The dormant arch-gate (state.py:121 `if "arch" in obj`) is worst: the comment says "Redundant second guard — the real gate is run_dir.check_drift" with no hint that it never fires for v1. A fresh reader would believe the assert covers v1 resumes.

Cheapest real fix is not a note: extend the gate to fire for v1 too — `model.cfg == config.arch` is exactly as meaningful for a v1 resume, and the model was already built. But design deferred that to resume rewiring; at minimum add the two missing tags so the sweep convention holds.

### F3. v1-format knowledge leaked into the module marked "goes away"

Old `bc/checkpoint.py` carries the header note "superseded by bc/storage/checkpoint.py … whatever is still needed here moves there … and this file goes away." Yet the chunk-1 `is_arch_bearing` fix put live v1 knowledge (`"config" in obj`) into it — duplicating `is_versioned_checkpoint`'s discriminator (same test, different signature: path vs obj). The duplication is forced by import direction (storage → old; the reverse would cycle). But `is_arch_bearing` isn't legacy reconstruction — it's a live, format-spanning discriminator with one consumer (inference.py). Moving it to `storage/checkpoint.py` (where it can call `is_versioned_checkpoint` on the loaded obj) puts all v1 format knowledge in the format module and shrinks the legacy module in the intended direction. Cheap now.

Related shape wrinkle, pre-existing: discriminators are split between path-taking (`is_arch_bearing`, `is_legacy_checkpoint` — each does its own full `torch.load`) and obj-taking (`is_combined_checkpoint`, `is_versioned_checkpoint`). The model_key re-read note already covers the load-twice cost; converging the discriminators on obj-taking with one path-level wrapper would fall out of the same fold-out.

## Findings — smaller

- **F4. `_PATH_FIELDS` matches `hint is Path` only.** A future `Path | None` field, or a Path inside `arch`/`loss`, silently misses the serde → checkpoint write succeeds, every load then fails under `weights_only=True`. Working doc §7 lists the adjacent test gap ("weights_only safety for a future non-Path field"). A cheap structural guard: a test (or an assert in `serialize_checkpoint`) that walks the assembled block and checks every leaf is a weights_only-safe primitive. That covers both the `Path | None` miss and any future exotic field type, without waiting for the guardrail chunk.
- **F5. `migrate` docstring says "leaving the input untouched" but only shallow-copies.** True while `MIGRATIONS` is empty; the first migration that mutates a nested dict (e.g. `data["arch"]["x"] = …` without copying) silently violates it and corrupts the caller's block. Either deep-copy at the boundary (blocks are small, cost is nil) or state the convention migrations must copy nested structures they touch. Deep-copy is the no-discipline-needed option.
- **F6. Path-field knowledge has two homes.** `bc/config._PATH_FIELDS` (introspected) vs `TrainConfig.from_file`'s hardcoded `("manifest", "intermediate")` loop (and `json_default` stringifies too). Import direction blocks sharing today (bc.config imports train_config). Resolves naturally when the config family consolidates into `bc/config` (already queued, NOTE in place) — worth listing as a named payoff of that move so it doesn't get missed.
- **F7. Stale prose in `probes/core.py` `load_frozen_model`:** "Architecture … comes from the checkpoint's `arch` key" — v1 records it at `config.arch`. The mechanical rename (`load_bc_model` → `load_checkpoint`) was applied but the sentence wasn't re-read. Say "the checkpoint's recorded arch".
- **F8. `validate_in_ch` error message under-names the inputs:** blames `dense_history_n` alone, but channel count also depends on `player_status_channels` (and future obs knobs). Copied from the legacy message. Trivial fix: print the whole `obs` config or just "resolved obs implies N channels".
- **F9. `ConfiguredModel.config` has a default `= None`.** Both real constructor sites pass it explicitly; the default's only effect is permitting accidental omission at future sites. Dropping the default makes the legacy-None deliberate at every constructor.
- **F10. test_checkpoint `_runtime()` re-states `TrainingState.to_dict` key-for-key.** The prod writer pairs `to_dict()` + `serialize_checkpoint`; the tests hand-build the same dict. Calling `state.to_dict()` tests the actual pairing and removes a copy of the runtime-keys fact. (Counter-argument: independence from to_dict bugs — but test_state already covers to_dict via save().)
- **F11. `serialize_checkpoint` trusts runtime/config coherence.** Nothing asserts `runtime["model"]` came from a model built with `config.arch`; `TrainingState` maintains the invariant, the free function's contract is implicit. Fine as-is (validate_in_ch catches formula drift on load, strict load catches shape drift); note only — maybe one docstring sentence naming the precondition.
- **F12. `git_sha` strictness now applies to manifest builds.** Previously best-effort ("unknown" fallback); now `build_manifest` crashes outside a git checkout. Deliberate per the commit, and right for code_sha (a silent "unknown" defeats provenance). Just noting the shared-helper coupling: the two consumers have different stakes, and if a non-checkout manifest-build environment ever appears, the fallback question reopens.
- **F13. test_agent.py TODOs are questions, not actions.** "Why are we testing checkpoint loading here in self-play?" — legitimate (the test is a training-domain smoke that happens to live in self-play because that's who depended on the checkpoint at the time; nothing self-play-specific remains). The answer is probably "move it to training tests or eval-tools", which is smaller than the TODO's lifetime will be. Also the file kept its `test_agent.py` name with the misnomer TODO. Fine short-term; flag for the next test-hygiene pass.
- **F14. `arch_for_load` name lost its planned `legacy_` prefix.** Context carries it while it lives in the legacy module; if F3's move happens (storage importing it), or when it relocates to the v0→v1 normalizer, the qualifier starts mattering. Rename at that move, not now.
- **F15. Two v1-layout key-set locks in two test files** (`test_v1_serialized_shape` exact set, `test_state` round-trip exact set). Both are legitimate (different entry points: serialize_checkpoint vs save()); when the TypedDict/key-constants follow-up (working doc §7) lands, both should read from it.

## Overall read

Chunk-1 landed close to spec, with the deviations documented rather than silent. Code quality of the new modules (config, storage, model_builder) is the best in the training package — short, single-purpose, docstrings that pass the keep-or-drop test. The strangler arrangement is honest (old module marked superseded, dependency edges pointing the right way except F3). The material findings are process-shaped, not bug-shaped: the one design item explicitly marked do-at-chunk-1-time (v1 key-set freeze) slipped, and the working doc's claim of refactor-note coverage is ahead of the code. No correctness bugs found in the diff.
