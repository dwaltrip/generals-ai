# Confound-boundaries survey — resolving the obs-fix hypothesis

*Date: 2026-07-08. A session note doubling as a point-in-time survey of the project's known behavior boundaries. Resolves the hypothesis in [7.06-1](7.06-1-obs-fix-barrier-hypothesis.md). Vocabulary and verdict logic: [the confounds framework](../confounds-framework.md), written this session. The behavior-changelog ([7.06-2](7.06-2-ckpt-config-motivations-and-direction.md) proto-plan) will take over as the running ledger, with this survey as its seed content.*

## Overview

- The remembered "unrecorded obs fix" was three separate changes, not one.
- Three old checkpoints (trained 2026-05-21 through 05-24, before the obs fixes) can't be fairly run or evaluated on current code — the obs channels changed underneath them. No other surviving non-smoke checkpoint is affected.
- All later checkpoints (2026-05-27 onward) can be fairly compared head-to-head with any other, on current code, in gameplay.
- Gameplay numbers recorded before 2026-06-07 don't compare with anything measured after. To compare against an old model, re-run the matchup — don't reuse its old numbers.
- Elim-head metrics recorded before 2026-06-18 don't compare with those recorded after (the labels changed). Gameplay evals are unaffected by this one.
- As far as the recorded eval docs show, no comparison ever accidentally crossed one of these lines.

## From one hypothesis to three boundaries

7.06-1 hypothesized a single recent, unrecorded obs fix acting as a barrier. The git sweep found no single commit matching the recollection — instead three distinct boundaries, each on a different surface. The recollection likely blended them, and identifying which one was "really" remembered stopped mattering once each was classified. All the relevant work is merged to main (nothing orphaned on the elim-head or ckpt-config branches), and no obs-building code changed after 2026-06-19.

## The three boundaries

Classified per the framework (E1 = recipe change, E2 = model contract, E3 = measurement contract).

### 1. Obs-content fixes (2026-05-21 / 05-27) — the true input barrier

"Close two obs-tensor fog-of-war leaks" (`2e6b2df`) and "Subtract expected production from army_delta channels" (`5a2beb0`), then "Replace game_progress channel with timestep (fix future-info leak)" (`e04cad6`). Ungated, in-place changes to existing obs channel values, in the shared path (training data + live).

- Effects: E1 + **E2 break** + E3 task (two of the fixes removed information leaks, so the earlier game was easier).
- This is the class 7.06-1's wording actually describes. It is also the only boundary with an open decision attached: the disposition of pre-fix checkpoints, which folds into the route-1 supported-checkpoints call.
- Affected population, per the [6.09-4 inventory](../2026-06/6.09-4-realistic-runs-inventory.md): `runs/20260521-005930` (predates all three fixes), `runs-cloud/2026-05-23T23-40-14Z` and `2026-05-24T06-10-51Z` (predate `e04cad6`). Everything from `2026-05-27T21-39-06Z` onward is post-fix — those runs started about two hours after the commit, assuming the cloud runs picked up committed code (unverified, cheap to check if it ever matters).

### 2. Stale-live-obs fix (2026-06-07) — a repair, not a break

"Fix one-tick-stale obs in live inference path" (`bc4bb19`, with same-day companion `49b335d` fixing the eval-bot's WorldModel). The live path double-seeded tick-0 history, so every live encode saw the previous tick's board. The training-data path never had the bug.

- Effects: **E2 repair** + E3 (all pre-fix gameplay-eval numbers were measured with every model seeing stale, one-tick-old inputs).
- Going forward this boundary is fully clean: old checkpoints run today see correct obs for the first time. Its cost is purely historical — the pre-06-07 recorded numbers.
- Before this session its only record was the [6.07-3 handoff note](../2026-06/6.07-3-one-tick-stale-obs-bug-handoff.md), never referenced by any later planning doc — the closest real match to "never recorded".

### 3. Elim-target tick-seam fix (2026-06-18) — targets, not obs

"Add bc/player_status; fix the obs/alive tick seam" (`4aace8b`): the alive/present masks moved from `death > t` to `death >= t`, ungated, on the targets side only. Obs channels are untouched — this is not the input barrier 7.06-1 described. The death-frame elim target became `dt = 0`.

- Effects: E1 (labels, and gameplay via trunk coupling) + E3 ruler (elim metrics and curves), plus an analysis-side residue: a pre-fix elim head scored today is graded against labels it wasn't trained on. The shift is small — one frame, ~1% of frames.
- The elim arc's comparability line: the 6.13–6.17 analyses (argmin toy, head-vs-rule) used pre-fix targets; the 6.19–6.21 diagnostics are post-fix.
- The record is contradictory rather than absent. [6.19-1](../2026-06/6.19-1-obs-player-status-channels-landed.md) records the fix well, including the `dt = 0` consequence, but three artifacts still describe the pre-fix state:
  - [6.18-6](../2026-06/6.18-6-obs-alive-tick-seam.md) says "not fixing now" — written hours before the fix and never updated.
  - The obs-side `TODO(obs-alive-tick-seam)` banner in `bc/obs/memory.py` survives and misdescribes `alive_mask` as `death>t`.
  - The commit message claims both TODO banners were retired, but only the elim-targets one was.

### Non-boundaries, for contrast

Several changes touched obs behavior without creating a boundary, because they were gated or verified byte-identical: the fp16 obs default flip (loaded checkpoints keep their recorded dtype), the player-status obs channels (`LEGACY_OBS_CFG` reconstructs the original 96-channel obs), configurable dense-history depth (legacy back-fill at the historical value), and the 06-05 obs perf refactors (output verified unchanged in-commit). The gating discipline works when applied — the three boundaries above are the cases where it wasn't.
