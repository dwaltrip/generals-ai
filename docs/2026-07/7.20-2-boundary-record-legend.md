# Boundary-record legend — draft

*Date: 2026-07-20. Status: draft. The reader-facing legend for boundary records, drafted during the goldens naming pass ([7.20-1](7.20-1-goldens-naming-pass.md)). At build time this text becomes the ledger's header (or a README beside the records, if each record gets its own file). Field list and wording are draft-grade until the build.*

---

Each entry records one boundary: a change to behavior-shaping code and the date it landed. Consult the ledger when comparing checkpoints or numbers from different dates. Full framework: [confounds-framework](../confounds-framework.md).

Fields:

- **surface**: the part of the system that was modified, producing the boundary this record describes. One of: `obs`, `obs-live`, `model-forward`, `training-targets`, `loss-func`, `eval-protocol`, `arch-shape`, `game-rules`.
- **impacts**: what the change does to pre-existing artifacts (checkpoints and recorded numbers). One or more of:
    - `recipe-change`: training-time code changed, so later checkpoints are genuinely different models. Not a confound: recorded for attribution.
    - `contract-break`: old checkpoints now run against code that differs from what they trained with.
    - `contract-repair`: a fix brought runtime back into line with training. The pre-fix era's numbers carry the old broken behavior.
    - `metrics-change`: how numbers are produced changed (metric or label definitions, eval protocol). Cross-date comparisons need a re-measure.
    - `mechanics-change`: the game the bot plays changed: rarely the game itself, more often our implementation of it (bug fixes in sim rules or in what information reaches the bot). Cross-date numbers describe different games, permanently.
- **channels**: the changed channels, copied from regen's printed extent.
- **comparisons invalidated**: which cross-date comparisons stop being valid.

Illustrative entry (the 2026-06-18 tick-seam fix, sketched in this format):

```
2026-06-18 — alive/present tick seam fixed (death > t → death >= t)
surface: training-targets
impacts: recipe-change, metrics-change
channels: none (targets-only change: alive mask, next_death)
comparisons invalidated: elim metrics and training curves across this date
```
